WebM Initialization Structure for Live Video

A valid WebM initialization sequence for live video streaming defines the structural metadata decoders require to parse subsequent media frames in real time. This article details the core components—the Extensible Binary Meta Language (EBML) header, Segment element, Segment Information, and Track entries—along with the specific structural parameters required to instantiate a continuous, unbounded live stream.

1. The EBML Header

Every valid WebM byte stream must start with an EBML header (Element ID: 0x1A45DFA3). For live video, this header establishes parser compatibility:

  • EBMLVersion (0x4286) & EBMLReadVersion (0x42F7): Typically set to 1.
  • EBMLMaxIDLength (0x42F2): Must be set to 4 (bytes).
  • EBMLMaxSizeLength (0x42F3): Must be set between 1 and 8 (bytes).
  • DocType (0x4282): Must be the ASCII string "webm".
  • DocTypeVersion (0x4287) & DocTypeReadVersion (0x4285): Set to 2 or higher (commonly 4 for modern codecs like VP9 and AV1).

2. The Segment Header

Immediately following the EBML header is the Root Segment element (Element ID: 0x18538067).

  • Unknown Data Size: In a live streaming context, the total length of the media is unknown at stream inception. The size field of the Segment element must be set to an undefined/unknown size (represented in EBML as all 1 bits in the size descriptor, e.g., 0x01FFFFFFFFFFFFFF for an 8-byte length descriptor).

3. Segment Information (Info)

The Info element (Element ID: 0x1549A966) provides global parameters for the stream timeline:

  • TimecodeScale (0x2AD7B1): Defines the timestamp scale factor in nanoseconds. The default is 1000000 (1 millisecond per tick), which maps Cluster and Block timecodes directly to milliseconds.
  • Duration (0x4489): For live streams, the Duration element must either be omitted entirely or set to an undefined state (NaN) so players treat the stream as an unbounded live broadcast.
  • MuxingApp (0x4D80) & WritingApp (0x5741): UTF-8 strings indicating the multiplexer software.

4. Track Parameters (Tracks)

The Tracks element (Element ID: 0x1654AE6B) contains one or more TrackEntry elements (Element ID: 0xAE). A valid live video track requires:

  • TrackNumber (0xD7): A non-zero unsigned integer uniquely identifying the track within subsequent media clusters.
  • TrackUID (0x73C5): A unique 64-bit integer identifier.
  • TrackType (0x83): Set to 1 for video (2 for audio if multiplexed).
  • CodecID (0x86): ASCII string identifying the video codec (e.g., "V_VP8", "V_VP9", or "V_AV1").
  • CodecPrivate (0x63A2): Required for certain codecs (such as AV1 or Opus) to provide initialization and decoder configuration data prior to decoding the first frame.
  • Video Settings (0xE0):
    • PixelWidth (0xB0): Width of the encoded video frames in pixels.
    • PixelHeight (0xBA): Height of the encoded video frames in pixels.
    • DisplayWidth (0x54B0) & DisplayHeight (0x54BA): Optional; defines aspect ratio overrides if non-square pixels are used.

5. Media Cluster Requirements for Live Streaming

The initialization segment ends once the Tracks element closes. Media is subsequently delivered via independent Cluster elements (Element ID: 0x1F43B675):

  • Cluster Timecode (0xE7): Must be strictly monotonically increasing across clusters based on the configured TimecodeScale.
  • First Block Alignment: The first media payload (SimpleBlock or BlockGroup) inside the initial cluster following initialization must contain a Keyframe (flagged accordingly) to allow the decoder to establish its reference buffer immediately.
