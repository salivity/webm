How WebM Demuxers Identify Keyframes and Delta Frames

A WebM demuxer determines whether a video frame is a keyframe (intra-frame) or a delta frame (inter-frame) by inspecting container-level structural flags within the Matroska/EBML format, and secondarily by examining the underlying video codec bitstream. Because WebM is a restricted subset of the Matroska container, it uses specific structural elements—primarily SimpleBlock flags and BlockGroup reference tags—to convey frame dependency information directly to the demuxer without requiring full video decoding.

1. The SimpleBlock Flags (Primary Method)

The vast majority of modern WebM files store video data inside SimpleBlock elements. A SimpleBlock contains a compact binary header preceding the raw video payload, which includes a 1-byte flags field.

The demuxer identifies frame types using the Keyframe bit located in this flags byte:

  • Keyframe (Intra-frame): Bit 7 (the most significant bit, or bit 0 depending on bit-numbering conventions, value 0x80) is set to 1. This explicitly signals that the block contains an independent frame that does not rely on previous or future frames for reconstruction.
  • Delta Frame (Inter-frame): The Keyframe bit is set to 0. This tells the demuxer that the frame depends on referenced reference frames to be decoded properly.

2. The BlockGroup and ReferenceBlock Structure (Legacy/Alternative Method)

When a WebM file uses BlockGroup elements instead of SimpleBlock elements, the demuxer detects keyframes by checking for dependency elements within the group:

  • Keyframe: A BlockGroup that contains a Block element but no ReferenceBlock element is treated as a keyframe. The absence of a reference indicates no temporal dependencies.
  • Delta Frame: If one or more ReferenceBlock elements are present inside the BlockGroup, the frame is a delta frame. The ReferenceBlock contains the relative timestamp of the frame(s) upon which this delta frame depends.

3. Codec Bitstream Inspection (Fallback Method)

If the container metadata is missing, corrupted, or generated by a non-compliant muxer, the demuxer can inspect the initial bytes of the video payload to identify the frame type based on the codec:

  • VP8: The demuxer reads the first byte of the payload. If the least significant bit (bit 0) is 0, it is a Keyframe; if it is 1, it is an Inter-frame.
  • VP9: The demuxer parses the uncompressed header. The frame_type bit determines the frame type (0 indicates a Keyframe, while 1 indicates an Inter-frame).
  • AV1: The demuxer reads the Open Bitstream Unit (OBU) header and parses the frame_header_obu to extract the frame_type syntax element (0 corresponds to KEY_FRAME).

Summary

WebM demuxers prioritize the Keyframe flag in the SimpleBlock header for fast and efficient parsing. This allows media players and processing pipelines to perform seeking, indexing, and adaptive streaming operations rapidly without parsing the compressed video payload itself.
