WebM Audio Bit Depth for Multi-Channel Vorbis

This article explains how the WebM container format handles audio bit depth when encapsulating multi-channel Vorbis streams. While WebM inherits elements from the Matroska specification capable of defining sample properties, the inherent architecture of the Vorbis audio codec dictates that traditional integer bit depth is omitted or ignored at both the container and bitstream levels, leaving sample resolution to the decoder.

The Matroska and WebM Container Structure

WebM is a restricted subset of the Matroska (EBML) container format. In Matroska-based specifications, audio track metadata is defined inside the Audio master element (EBML ID 0xE1). This element includes several standardized child elements for defining audio streams:

  • Channels (0x9F): Specifies the number of audio channels (e.g., 2 for stereo, 6 for 5.1 surround).
  • SamplingFrequency (0xB5): Specifies the sampling rate in Hertz.
  • BitDepth (0x6264): Defines the number of bits per sample for uncompressed or specific lossy PCM formats.

Vorbis Representation and Bit Depth Handling

Although WebM supports the BitDepth EBML element for specific audio formats like uncompressed PCM, Vorbis streams (identified by the A_VORBIS CodecID) handle audio data differently:

  1. Omission of the BitDepth Element: In WebM files containing Vorbis audio, the BitDepth container element is generally omitted. If a multiplexer includes the BitDepth tag, compliant decoders will ignore it, as it does not define the precision of the underlying audio data.
  2. Floating-Point Processing: Vorbis is a perceptual, transform-based (MDCT) audio compression format. Internally, Vorbis encodes audio as frequency domain representations using variable-precision floating-point numbers. It has no native concept of fixed integer bit depth (such as 16-bit or 24-bit).
  3. Decoder-Side Target Resolution: Because the bitstream does not have a fixed bit depth, the effective output bit depth is determined during the decoding stage. The decoder transforms the quantized MDCT coefficients back into time-domain pulse-code modulation (PCM) audio at whatever depth the playback system or output pipeline requests (typically 16-bit integer, 24-bit integer, or 32-bit floating-point PCM).

Encapsulation of Multi-Channel Streams

When encapsulating multi-channel Vorbis streams (such as 5.1 or 7.1 surround sound) in WebM:

  • Vorbis Headers in CodecPrivate: WebM stores the three required Vorbis initialization packets (Identification Header, Comment Header, and Setup Header) within the track's CodecPrivate element (0x63A2).
  • Channel Mapping: The Vorbis Identification Header defines the primary channel count (supporting up to 255 discrete channels), which must match the value specified in the WebM Channels element. The Setup Header defines the channel floor mappings, couplings, and residue vectors.
  • Independent Channel Processing: Multi-channel layouts maintain uniform precision across all channels via shared quantization models and channel-coupling configurations, without assigning explicit bit-depth indicators to individual channels.
