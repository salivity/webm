How WebM Stores BT.2020 Matrix Coefficients

This article explains how the WebM container format stores and signals matrix coefficients for the BT.2020 color space in 4K video. WebM relies on an Extensible Binary Meta Language (EBML) structure inherited from the Matroska specification to define color space metadata at the container level. By designating specific numerical values inside the video track configuration, WebM ensures that media players and decoders correctly interpret YUV-to-RGB color transformations for Ultra HD and High Dynamic Range (HDR) workflows.

The EBML Color Element Structure

WebM organizes stream data using a hierarchical EBML tree. Color metadata is stored at the container level inside the track settings rather than solely relying on the raw video stream. The path for this metadata within the file structure is:

Segment ➔ Tracks ➔ TrackEntry ➔ Video ➔ Colour

The Colour master element (EBML ID 0x55B0) contains various child elements defining the video’s colorimetry, including transfer characteristics, color primaries, and matrix coefficients.

The MatrixCoefficients Element

Matrix coefficients define the mathematical transformation used to derive luma and chroma signals from the red, green, and blue primary colors. Inside the Colour element, the matrix is designated by the MatrixCoefficients child element (EBML ID 0x55B1).

The values assigned to this element mirror the standardized numerical values established by ITU-T H.273 and ISO/IEC 23091-2:

  • Value 9 (BT2020_NCL): Specifies ITU-R BT.2020 non-constant luminance system. This is the standard setting for consumer 4K UHD video, HDR10, and modern streaming profiles.
  • Value 10 (BT2020_CL): Specifies ITU-R BT.2020 constant luminance system, typically reserved for specialized broadcast workflows.

When packaging 4K BT.2020 content into WebM, the multiplexer writes an unsigned integer of 9 into the MatrixCoefficients element to enforce non-constant luminance conversion.

Dual-Layer Signaling: Container and Bitstream

In a typical 4K WebM implementation, video is encoded using either the VP9 (specifically Profile 2 for 10-bit/12-bit color) or AV1 codecs. WebM uses dual-layer signaling, meaning the color configuration is stored at both the container layer and the elementary bitstream layer:

  1. Container Layer (WebM): The MatrixCoefficients element informs the demuxer and hardware decoders of the color properties before parsing frame-by-frame data. This allows media pipelines to configure rendering surfaces, color management systems, and display interfaces (like HDMI) without waiting for in-band stream headers.
  2. Codec Layer (VP9 or AV1): The raw bitstream also contains color metadata. In VP9, the sequence header contains a color_config() syntax element specifying the color space value matching BT.2020. In AV1, the sequence header includes a color_config() struct that explicitly writes the Matrix Coefficients syntax element matching ITU-T H.273 index 9.

Decoders prioritize consistency between these layers. If playback software encounters a stream where the WebM container and bitstream disagree, standard behavior dictates following the elementary stream's parameters, though properly authored 4K WebM files synchronize both to index 9 for BT.2020.
