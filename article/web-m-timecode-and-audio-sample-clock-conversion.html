WebM Timecode and Audio Sample Clock Conversion

This article explains the precise mathematical formulas that link WebM container timecodes to audio sample clocks. WebM structures its timing around a continuous nanosecond-based container timebase, whereas digital audio relies on a discrete integer clock governed by a fixed sampling rate. Converting accurately between these two timing domains is critical for preventing audio-video synchronization drift and sample truncation during playback and multiplexing.

Core Parameters and Definitions

To map WebM timestamps to discrete audio samples, five primary variables are required:

  • \(T_{\text{webm}}\): The raw integer timecode stored in the WebM Block or SimpleBlock header.
  • \(S_{\text{seg}}\): The TimestampScale (formerly TimecodeScale) defined in the WebM Segment Information, expressed in nanoseconds per container tick (default is \(1{,}000{,}000\text{ ns}\), or \(1\text{ ms}\)).
  • \(S_{\text{trk}}\): The TrackTimestampScale defined in the specific audio track entry (default is \(1.0\)).
  • \(F_s\): The audio sampling rate in Hertz (e.g., \(48{,}000\text{ Hz}\) or \(44{,}100\text{ Hz}\)).
  • \(N\): The absolute audio sample index (a zero-based integer count of audio frames).

Time in Seconds

Both WebM timecodes and audio sample counts represent an absolute time \(t\) in seconds from the start of the media presentation:

\[\text{WebM Time: } t = T_{\text{webm}} \times S_{\text{seg}} \times S_{\text{trk}} \times 10^{-9}\]

\[\text{Audio Sample Clock Time: } t = \frac{N}{F_s}\]

Mathematical Conversions

1. Converting WebM Timecode to Audio Sample Number

To determine the exact sample index \(N\) corresponding to a given WebM block timecode \(T_{\text{webm}}\):

\[N = \text{round}\left( \frac{T_{\text{webm}} \times S_{\text{seg}} \times S_{\text{trk}} \times F_s}{10^9} \right)\]

When \(S_{\text{seg}} = 1{,}000{,}000\) (the standard \(1\text{ ms}\) tick) and \(S_{\text{trk}} = 1.0\), the equation simplifies to:

\[N = \text{round}\left( \frac{T_{\text{webm}} \times F_s}{1{,}000} \right)\]

2. Converting Audio Sample Number to WebM Timecode

To calculate the WebM timecode \(T_{\text{webm}}\) for an audio packet starting at sample index \(N\):

\[T_{\text{webm}} = \text{round}\left( \frac{N \times 10^9}{F_s \times S_{\text{seg}} \times S_{\text{trk}}} \right)\]

Under standard default scaling (\(S_{\text{seg}} = 1{,}000{,}000\) and \(S_{\text{trk}} = 1.0\)), this simplifies to:

\[T_{\text{webm}} = \text{round}\left( \frac{N \times 1{,}000}{F_s} \right)\]

Practical Example

Consider a WebM file containing an Opus audio track at \(F_s = 48{,}000\text{ Hz}\) with \(S_{\text{seg}} = 1{,}000{,}000\) and \(S_{\text{trk}} = 1.0\):

  • Block Timecode to Sample: If a block has \(T_{\text{webm}} = 1500\) (representing \(1.5\text{ seconds}\)): \[N = \frac{1500 \times 48{,}000}{1{,}000} = 72{,}000\text{ samples}\]

  • Sample to Block Timecode: If an audio frame starts at sample \(N = 96{,}000\): \[T_{\text{webm}} = \frac{96{,}000 \times 1{,}000}{48{,}000} = 2000\text{ ms}\]

Non-Integer Timing Drift and Quantization

Because default WebM timecodes operate at millisecond precision (\(1{,}000\text{ Hz}\)), rates like \(44{,}100\text{ Hz}\) yield non-integer sample counts per tick (\(44.1\text{ samples/ms}\)). To avoid cumulative rounding errors:

  1. Maintain audio playback position using a 64-bit integer sample accumulator (\(N\)).
  2. Calculate container timecodes directly from the total sample count rather than accumulating rounded millisecond deltas.
  3. Use the CodecDelay element (in nanoseconds) to subtract encoder delay before computing the presentation time.
