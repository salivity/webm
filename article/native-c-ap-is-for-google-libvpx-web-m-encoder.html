Native C APIs for Google libvpx WebM Encoder

This guide provides an overview of the native C Application Programming Interfaces (APIs) used to interface directly with Google's libvpx reference encoder for VP8 and VP9 video formats. It details the essential header files, primary data structures, lifecycle management functions, frame submission workflows, and control macros necessary to configure and run the encoder efficiently within C or C++ applications.

Core Headers and Interface Selection

To directly access the encoding APIs, include the primary encoder header and the VP8/VP9 interface definitions:

#include <vpx/vpx_encoder.h>
#include <vpx/vp8cx.h>

Direct interaction relies on codec interface pointers defined in vp8cx.h:

  • vpx_codec_vp8_cx(): Returns the interface pointer for the VP8 encoder.
  • vpx_codec_vp9_cx(): Returns the interface pointer for the VP9 encoder.

Primary Data Structures

Direct interaction with libvpx revolves around four essential structures:

  • vpx_codec_ctx_t: The primary context object holding the state of the codec instance.
  • vpx_codec_enc_cfg_t: Holds high-level configuration parameters, including target bitrate, frame dimensions, timebase, multithreading settings, and rate control modes.
  • vpx_image_t: Represents raw, uncompressed image data (such as YUV420p) fed into the encoder.
  • vpx_codec_cx_pkt_t: Holds compressed packet data produced by the encoder, containing the bitstream payload, packet size, timestamps, and frame type flags (e.g., keyframe identification).

Configuration and Initialization

Before encoding starts, the encoder configuration must be populated and bound to a codec context:

  1. vpx_codec_enc_config_default: Populates a vpx_codec_enc_cfg_t structure with default settings suited for a chosen algorithm (VP8 or VP9) and target usage profile (e.g., realtime or standard streaming).
  2. vpx_codec_enc_init (or the version-checked macro vpx_codec_enc_init_ver): Initializes the vpx_codec_ctx_t context using the specified codec interface and configuration settings.

Dynamic Control and Codec Tuning

To tune parameters beyond the standard configuration struct, the API provides the generic control function and macro:

  • vpx_codec_control(): A variadic function that takes a context pointer and a control ID (defined in vp8cx.h), followed by parameter values.

Common control IDs include:

  • VP8E_SET_CPUUSED: Adjusts the speed/quality trade-off (negative values prioritize quality; positive values prioritize encoding speed).
  • VP8E_SET_STATIC_THRESHOLD: Sets the threshold for macroblock skipping in stationary scenes.
  • VP9E_SET_TILE_COLUMNS and VP9E_SET_TILE_ROWS: Configures multi-threading tile partitions in VP9.
  • VP9E_SET_LOSSLESS: Enables spatial lossless encoding for VP9.

Frame Processing and Ingestion

Uncompressed video frames are structured using the vpx_image_t API before being handed to the encoder:

  • vpx_img_alloc(): Allocates an image buffer managed directly by libvpx.
  • vpx_img_wrap(): Wraps an existing external memory buffer into a vpx_image_t structure without copying the raw data.

Once prepared, frames are passed to:

  • vpx_codec_encode(): Submits an uncompressed frame (vpx_image_t) to the encoder context. This call accepts presentation timestamps (PTS), duration, deadline flags (e.g., VPX_DL_REALTIME, VPX_DL_GOOD_QUALITY), and encoding flags such as VPX_EFLAG_FORCE_KF to force a keyframe. Passing a NULL pointer instead of an image signals the end of the stream and flushes remaining frames.

Packet Retrieval

After each call to vpx_codec_encode, compressed frames are retrieved sequentially using an iterator:

  • vpx_codec_get_cx_data(): Iterates over the context to return a pointer to a vpx_codec_cx_pkt_t structure. This function is called repeatedly in a loop until it returns NULL, ensuring all available output packets for the submitted frame are extracted and written to a WebM container or network stream.

Teardown and Cleanup

  • vpx_codec_destroy(): Releases all internal state memory, tables, and thread contexts allocated to the vpx_codec_ctx_t.
  • vpx_img_free(): Frees memory allocated specifically via vpx_img_alloc.
