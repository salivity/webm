MSE Timestamp Sync Across Split WebM Tracks

The Media Source Extensions (MSE) API manages timestamp synchronization across split WebM tracks by decoding embedded container timecodes and mapping them onto a unified presentation timeline. When audio and video are delivered in separate WebM streams, the browser assigns each track to its own SourceBuffer instance under a parent MediaSource object. Synchronization relies on the WebM container’s internal timecode structure, the active SourceBuffer append mode, and explicit timestamp adjustments applied via the MSE execution pipeline.

WebM Timecode Extraction and Absolute Timestamps

In a split-track configuration, the audio and video streams reside in independent WebM containers (often using VP9/AV1 for video and Opus for audio). Each WebM file defines a TimecodeScale in its Segment Info element and Timecode headers within each Cluster element. Individual media frames (SimpleBlock or BlockGroup) define relative offsets from their Cluster timecode.

When data is appended to a SourceBuffer via appendBuffer(), the browser’s demuxer calculates the absolute Presentation Timestamp (PTS) for each frame:

\[\text{PTS} = (\text{Cluster Timecode} + \text{Block Timecode}) \times \text{TimecodeScale}\]

Because both tracks are processed through separate demuxers, the integrity of these embedded timestamps serves as the primary baseline for track alignment.

Unified Presentation Timeline via segments Mode

By default, a SourceBuffer operates in segments mode (SourceBuffer.mode = 'segments'). In this mode, MSE places decoded frames directly onto the presentation timeline at the position dictated by their extracted PTS.

As long as the muxing process encoded both the audio and video tracks with synchronized timecode origins (where zero or a specific base time corresponds to the identical real-time event), MSE aligns the tracks naturally. The underlying media engine matches the audio and video presentation timestamps to the current playback time (currentTime) of the parent HTMLMediaElement.

Manual Alignment with timestampOffset

If split WebM tracks have mismatched base timecodes, or if media segments arrive out of sequence (such as in live streaming), MSE relies on the SourceBuffer.timestampOffset attribute.

Applying an offset shifts the presentation timeline for that specific buffer:

\[\text{Effective PTS} = \text{PTS} + \text{timestampOffset}\]

To synchronize mismatched streams:

  1. The demuxer reads the initial timestamp of the audio track and video track.
  2. If the audio stream starts at 0.00s but the video cluster starts at 0.08s, the application can adjust SourceBuffer.timestampOffset on the lagging buffer to normalize them to an identical start time.
  3. Once set, all subsequent appended clusters in that buffer adopt the new offset, bringing both tracks into continuous synchronization.

Audio as the Master Clock and Drift Management

During playback, the browser’s media rendering pipeline coordinates decoding and display across both SourceBuffer elements using the hardware audio clock as the master reference.

Because audio playback is sensitive to buffer underruns, the browser adjusts the video frame rendering rate to match the audio clock. If network latency or decoding complexity causes video to lag behind audio, the MSE implementation will drop video frames to catch up to the corresponding audio timestamp. If an audio gap occurs, MSE holds the current video frame until the next synchronized audio/video pair becomes available.
