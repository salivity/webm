WebM SourceBuffer Ready Events for Media Segments

When streaming WebM media using the Media Source Extensions (MSE) API, feeding video or audio segments requires precise coordination with the buffer's asynchronous lifecycle. The primary event indicating that a SourceBuffer has finished processing an append operation and is ready for the next media segment is the updateend event. Monitoring this event, along with verifying the boolean state of the updating property, ensures that subsequent calls to appendBuffer() execute without throwing state errors.

The Core Event: updateend

The appendBuffer() method on a SourceBuffer is asynchronous. When a WebM segment (such as an Initialization Segment or a Media Segment containing Clusters) is passed to appendBuffer(), the SourceBuffer sets its internal updating flag to true and begins parsing the byte stream.

Once the parsing and appending process completes, the SourceBuffer fires the updateend event. This event fires in all terminal cases:

  • After a successful append (immediately following the update event).
  • After an aborted operation (following the abort event).
  • After an error occurs during parsing or appending (following the error event).

Because updateend consistently signals the end of the update cycle regardless of success or failure, it is the primary event used to trigger the transmission or appending of the next WebM segment in a streaming queue.

The update Event

The update event fires specifically when appendBuffer() or remove() completes successfully. While update indicates a successful write to the buffer, standard implementations rely on updateend because it cleanly encapsulates the finalization of the asynchronous cycle. If you need to distinguish between a successful append and a failed append before proceeding, listen for update to confirm success and error to handle failures, or handle both prior to the final updateend trigger.

Verifying Readiness with the updating Property

Even when listening to events, the SourceBuffer.updating property serves as the definitive synchronous check:

  • updating === true: An append or remove operation is currently in progress. Calling appendBuffer() now will throw an InvalidStateError.
  • updating === false: The buffer is idle and ready to accept the next chunk of data.

Before pushing a new WebM segment, your application logic should verify that sourceBuffer.updating is false.

Parent MediaSource Prerequisites

For a SourceBuffer to accept data, the parent MediaSource instance must also be in an active state:

  • sourceopen Event: Media segments cannot be appended until the MediaSource object fires sourceopen and its readyState property is set to 'open'.
  • If the MediaSource transitions to 'ended' or 'closed', no further segments can be appended until it re-opens.

Standard Segment Queuing Pattern

Because media chunks often download faster than the SourceBuffer can parse them, a segment queue pattern is standard:

  1. Push downloaded WebM chunks into an in-memory array (queue).
  2. Define a function to process the queue: check if !sourceBuffer.updating and queue.length > 0.
  3. If ready, shift the next segment from the queue and call sourceBuffer.appendBuffer(segment).
  4. Attach an event listener to sourceBuffer for updateend that calls the queue processor again to send the next segment.
