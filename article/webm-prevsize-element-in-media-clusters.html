WebM PrevSize Element in Media Clusters

The PrevSize element in a WebM container specifies the total size, in bytes, of the immediately preceding Cluster. Positioned at the beginning of a Cluster, its primary functional role is to facilitate fast, efficient backward seeking and reverse playback without requiring the media player to scan the file linearly or rely entirely on a global index.

Backward Seeking and Navigation

In the Matroska and WebM specifications, media data (such as VP8/VP9 video and Opus/Vorbis audio frames) is grouped into discrete chunks called Clusters. When a media player needs to navigate backward—such as rewinding, jumping back several seconds, or stepping backward frame-by-frame—it must locate the start of previous Clusters to decode keyframes.

Without PrevSize, a demuxer located at the current Cluster has no direct way of knowing where the previous Cluster begins, because Clusters are variable in size. By reading the PrevSize value at the header of the current Cluster, the demuxer can simply subtract that byte count (along with the size of the EBML ID and length descriptor) from the current Cluster's file offset. This allows the parser to jump directly to the first byte of the preceding Cluster in a single seek operation.

Streaming and Files Without Cues

While WebM files often contain a Cues element (an index table mapping timestamps to byte offsets), this table is not always available or usable:

  • Live Streams: In live or progressive WebM streams, a global index cannot exist because the media is being generated in real time.
  • Truncated or Incomplete Files: If a file transfer is interrupted, or if the Cues element is placed at the end of the file (as is common in one-pass encoding), the index cannot be read until downloading completes.

In these scenarios, PrevSize acts as a backward-pointing linked list. It allows demuxers to traverse backward through the media stream dynamically, enabling reverse navigation even in the total absence of index metadata.

Technical Characteristics

  • EBML ID: 0xAB
  • Type: Unsigned integer (uinteger)
  • Level: 2 (Direct child of the Cluster element, alongside Timecode)
  • Mandatory: No. In WebM, the element is optional. When absent, demuxers must rely on external indexes or forward-scanning algorithms to navigate backward.
  • Value Representation: The value represents the entire size of the previous Cluster element in octets, including its EBML ID and data size fields.
