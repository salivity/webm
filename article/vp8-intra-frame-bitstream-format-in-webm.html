VP8 Intra-Frame Bitstream Format in WebM

This article explains the specific bitstream format used for embedding VP8 intra-frame (keyframe) data within the WebM container. It covers how WebM wraps raw VP8 video packets using Matroska-based EBML structures, the breakdown of the uncompressed VP8 intra-frame header tag, the required 3-byte synchronization code, and the organization of the subsequent compressed payload partitions.

Container-Level Encapsulation in WebM

WebM is a restricted subset of the Matroska (MKV) multimedia container format, which utilizes Extensible Binary Meta Language (EBML). Within a WebM file, VP8 video data is placed directly into SimpleBlock or Block elements inside the Cluster elements.

WebM does not add complex bitstream packetization wrappers around VP8 frames. Instead, it embeds the raw, elementary VP8 frame bitstream directly as the payload of a SimpleBlock. The SimpleBlock header contains flags indicating whether the contained frame is a keyframe (intra-frame) or an inter-frame, matching the internal payload type.

Raw VP8 Intra-Frame Bitstream Structure

The underlying bitstream format for VP8 video frames is specified in RFC 6386. An intra-frame in VP8 consists of an uncompressed header followed by compressed macroblock and coefficient partitions.

The format of an intra-frame payload is structured as follows:

1. The 3-Byte Frame Tag (Uncompressed Header)

Every VP8 frame begins with a 24-bit (3-byte) uncompressed frame tag containing essential decoding flags:

  • Bit 0 (Frame Type): Set to 0 to denote an intra-frame (keyframe). A value of 1 denotes an inter-frame.
  • Bits 1–3 (Version): Indicates the VP8 bitstream profile/version (typically 0).
  • Bit 4 (Show Frame): Set to 1 if the decoded frame is intended for display, or 0 if it is only meant to update reference buffers.
  • Bits 5–23 (First Partition Size): A 19-bit unsigned integer representing the byte length of the first compressed data partition.

2. The 3-Byte Synchronization Code

Immediately following the 3-byte frame tag, all VP8 intra-frames must include a fixed 3-byte synchronization start code:

  • Byte 0: 0x9D
  • Byte 1: 0x01
  • Byte 2: 0x2A

This 24-bit sequence validates the frame as a valid VP8 keyframe and ensures proper byte alignment.

3. Image Dimensions and Scaling (4 Bytes)

Directly after the start code, 4 bytes define the frame dimensions and scaling factors:

  • Width (16 bits): 14 bits for horizontal pixel dimensions and 2 bits for horizontal scale factor.
  • Height (16 bits): 14 bits for vertical pixel dimensions and 2 bits for vertical scale factor.

4. Compressed Data Partitions

Following the uncompressed header, the remainder of the intra-frame payload is compressed using a boolean arithmetic entropy coder:

  • First Partition: Contains frame-level metadata, color space information, clamping type, loop filter parameters, token partition configuration, and intra-prediction modes for all macroblocks.
  • DCT/WHT Token Partitions: Contains the quantized Discrete Cosine Transform (DCT) and Walsh-Hadamard Transform (WHT) residual coefficients for the Y, U, and V color planes, organized in 1, 2, 4, or 8 distinct sub-partitions to allow multi-threaded decoding.
