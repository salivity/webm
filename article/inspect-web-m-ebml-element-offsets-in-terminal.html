Inspect WebM EBML Element Offsets in Terminal

WebM files are built upon Extensible Binary Meta Language (EBML), a binary equivalent of XML used to structure multimedia containers. When debugging stream corruption, calculating byte ranges for media streaming, or verifying keyframe placement, developers often need to inspect the precise byte offsets of internal EBML elements. This guide demonstrates how to inspect and extract internal element offsets from WebM files directly in the terminal using standard utilities such as mkvinfo, mediainfo, and ffprobe.

Inspecting Offsets with MKVToolNix (mkvinfo)

The mkvinfo utility from the MKVToolNix package is the most accurate and purpose-built tool for analyzing Matroska and WebM container hierarchies. By default, mkvinfo outputs a simplified element tree, but enabling verbosity reveals byte-level offsets and header sizes.

Run the following command to display element positions and payload offsets:

mkvinfo -v -v input.webm

In the output, mkvinfo details the byte position where each element begins, along with its size and ID:

+ EBML head at 0 size 40
|+ EBML version: 1
|+ EBML read version: 1
|+ EBML maximum ID length: 4
|+ EBML maximum size length: 8
|+ Doc type: webm
+ Segment, size 1048576 at 40
|+ Segment information at 52 size 75
|+ Tracks at 127 size 112
|+ Cluster at 239 size 15200

To limit output strictly to a concise tree containing byte positions and sizes without deep element payloads, combine verbosity with summary flags:

mkvinfo -s -v input.webm

Using MediaInfo for Detailed Hex and Offset Dumps

The CLI version of mediainfo includes an advanced --Details flag designed to trace parsing directly at the byte level. This option prints the hexadecimal offset, element ID, and byte size for every EBML node encountered.

To inspect the structural offsets:

mediainfo --Details=1 input.webm

For large files where you only want top-level container offsets (such as EBML, Segment, Info, Tracks, and Cluster elements) without printing every video packet, restrict the depth using standard shell filters:

mediainfo --Details=1 input.webm | grep -E "(Cluster|Tracks|Info|SeekHead)"

The left-hand column in the output denotes the exact hexadecimal or decimal offset where the container parser found the corresponding EBML ID.

Tracing EBML Elements with FFprobe

While ffprobe is primarily used for codec and packet analysis, FFmpeg's trace logging level (-v trace) forces the internal Matroska/EBML demuxer to print every element ID, size, and file offset during parsing.

Run the following command to inspect EBML parsing events:

ffprobe -v trace -i input.webm 2>&1 | grep -i ebml

To view the byte positions of specific structural containers such as Clusters or Cues:

ffprobe -v trace -i input.webm 2>&1 | grep -E "id 0x1f43b675|id 0x1c53bb6b"

In Matroska and WebM specifications, 0x1f43b675 corresponds to a Cluster element and 0x1c53bb6b corresponds to a Cues element. The trace log outputs the file position where the demuxer encounters these identifiers, allowing you to map raw byte coordinates directly to transport streams.
