Client-Side WebM Remuxing Libraries for PWAs

Client-side WebM remuxing allows Progressive Web Applications (PWAs) to re-encapsulate audio and video streams into a WebM container directly within the browser, eliminating server-side processing costs and enabling offline multimedia workflows. This article explores the primary software libraries available for in-browser WebM remuxing, examining lightweight JavaScript multiplexers, WebAssembly ports of industry-standard multimedia frameworks, and specialized EBML manipulators.

webm-muxer

webm-muxer is a lightweight, dependency-free JavaScript library built specifically to work alongside the modern WebCodecs API. It takes raw encoded video and audio chunks (such as VP8, VP9, AV1, or Opus) and packages them into a valid Matroska/WebM container format.

Because webm-muxer focuses exclusively on multiplexing without including heavy decoders or encoders, its bundle size is minimal—making it ideal for performance-sensitive PWAs. It supports streaming outputs via the FileSystemWritableFileStream or in-memory targets like ArrayBufferTarget, enabling real-time file writing with negligible memory overhead.

FFmpeg.wasm

ffmpeg.wasm is a pure WebAssembly port of the FFmpeg multimedia suite. It provides full remuxing capabilities directly inside the browser using standard FFmpeg commands (such as -c copy).

For PWAs, ffmpeg.wasm can ingest virtually any container format (such as MP4, MKV, or AVI) and remux the elementary streams into a WebM container without re-encoding, preserving video quality and executing significantly faster than a full transcode. However, it carries a larger bundle size (often several megabytes) and typically requires SharedArrayBuffer support, which demands cross-origin isolation headers (COOP and COEP) enabled on the web server.

Libav.js

libav.js is an Emscripten port of Libav and FFmpeg tailored specifically for browser integration. Unlike monolithic builds, libav.js offers modular variants, allowing developers to import only the demuxers and muxers needed for WebM creation.

This modularity makes libav.js an efficient middle ground between a massive full-featured FFmpeg build and a barebones multiplexer. It operates effectively inside Web Workers, preventing the browser's main UI thread from freezing during large file operations.

ts-ebml and EBML.js

Because WebM is a subset of the Extensible Binary Meta Language (EBML), low-level libraries like ts-ebml and EBML.js are frequently used for structural remuxing and metadata patching.

A common limitation of the native browser MediaRecorder API is that it outputs WebM files lacking duration metadata, causing playback scrubbing issues. Libraries like ts-ebml read the raw WebM ArrayBuffer, parse the EBML element tree, inject a accurate Duration tag and SeekHead index, and output a fully scrubbable, spec-compliant WebM file directly on the client.

Architectural Considerations for PWAs

When implementing these libraries inside a PWA, intensive file operations should always be delegated to a dedicated Web Worker. This preserves UI responsiveness and ensures that background tasks, like caching processed media to the Cache API or IndexedDB, do not disrupt the user experience.
