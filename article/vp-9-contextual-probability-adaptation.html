VP9 Contextual Probability Adaptation

This article provides an overview of how the VP9 video codec's entropy coder dynamically selects and updates symbol probabilities using contextual data from neighboring blocks. In VP9, arithmetic coding efficiency relies on context modeling, where the spatial states of adjacent blocks (specifically the left and top neighbors) determine the probability distributions applied to syntax elements. Below, we examine the mechanics of context derivation, decision trees, and the frame-level adaptation process that allows VP9 to maximize compression efficiency.

The Role of Spatial Neighbors in Context Derivation

VP9 utilizes a non-adaptive binary arithmetic coder during the decoding of a single frame, meaning that the probability values assigned to individual contexts remain static throughout that specific frame. However, the selection of which probability to use is highly dynamic and context-dependent.

To determine the context index for a specific syntax element—such as partition sizes, intra-prediction modes, reference frames, or skip flags—the coder inspects the syntax elements of causal spatial neighbors:

  • Above Neighbor (A): The block immediately above the current block.
  • Left Neighbor (L): The block immediately to the left of the current block.

The states of these two neighbors are combined to form a context index. For example, if both the left and above blocks use intra-prediction, the probability model selected for the current block's prediction mode will heavily bias toward intra-prediction. If one or neither neighbor uses intra-prediction, a different probability entry is chosen from the lookup table. If a neighbor is outside the current frame or tile boundary, a predefined default fallback context is used.

Tree-Based Binarization and Context Lookup

Non-binary syntax elements in VP9 are converted into binary decision trees. Each node in the tree represents a binary decision (a "bin"), and each bin has an associated probability table.

  1. Context Index Calculation: The coder evaluates the neighboring blocks \((A \text{ and } L)\) to produce an index offset.
  2. Node-Specific Probabilities: As the arithmetic coder traverses the decision tree for a symbol, it retrieves a specific probability \(P\) for each node using the calculated context index.
  3. Entropy Coding: The boolean arithmetic coder reads or writes the bit based on this context-derived probability, minimizing bitrate for predictable neighbor patterns.

Symbol Counting and Backward Probability Adaptation

While probabilities do not change mid-frame, VP9 tracks symbol occurrences to adjust probabilities for subsequent frames. This process is called backward adaptation:

  1. Count Accumulation: Throughout the frame, the codec maintains internal counts of how often each symbol occurs within each specific neighbor-derived context.
  2. Maximum Likelihood Estimation: At the end of the frame, the encoder and decoder use these accumulated counts to calculate new empirical probabilities for each context.
  3. Weighting with Previous Probabilities: The newly calculated probability is blended with the previous frame’s probability using an adaptation factor. This smoothing prevents radical probability shifts caused by temporary anomalies.
  4. Frame Context Selection: VP9 maintains four separate frame-level context models. The frame header specifies which of the four context buffers to use and whether the updated probabilities should be written back to update that context buffer for future frames.

Forward Updates via the Frame Header

In cases where backward adaptation is too slow to respond to a major scene change, VP9 supports forward probability updates. The encoder directly transmits new probability values in the frame header for specific contexts. To minimize overhead, VP9 uses a 1-bit flag per probability to signal whether an explicit update is being transmitted, ensuring that only contexts with significant deviation from the baseline consume header bandwidth.
