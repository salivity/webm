Single-Pass vs Two-Pass VP9 WebM Encoding

When encoding WebM video using the libvpx-vp9 codec, choosing between single-pass (1-pass) and two-pass (2-pass) encoding determines the balance between encoding speed, file size predictability, and visual quality. Single-pass encoding processes the video in one go, prioritizing speed for real-time applications, while two-pass encoding analyzes the entire video first to optimize bitrate allocation in the second pass, resulting in significantly higher visual quality and compression efficiency.

How Single-Pass VP9 Encoding Works

In single-pass encoding, libvpx-vp9 analyzes and compresses each frame simultaneously in a single pass. The encoder makes bit-allocation decisions based only on the current frame and immediately preceding frames, without knowledge of future frames or scene changes.

  • Speed: Encodes in roughly half the time compared to two-pass encoding.
  • Bitrate Allocation: Less efficient. Fast-motion or complex scenes may suffer from compression artifacts because the encoder cannot borrow bits from simpler upcoming scenes.
  • Primary Use Case: Real-time applications, live streaming (such as WebRTC), and rapid preview generation where encoding latency is the primary concern.

FFmpeg Single-Pass Example

ffmpeg -i input.mp4 -c:v libvpx-vp9 -b:v 2M -crf 30 -pass 1 -an output.webm

(Note: Using single-pass with VP9 generally requires setting a target bitrate or using the Constant Quality/CRF mode directly without pass logging).

ffmpeg -i input.mp4 -c:v libvpx-vp9 -crf 30 -b:v 0 output.webm

How Two-Pass VP9 Encoding Works

Two-pass encoding divides the compression workflow into two distinct stages:

  1. First Pass (-pass 1): The encoder reads the entire video without generating the final output. It creates a statistical log file containing data on scene cuts, motion vectors, spatial detail, and frame complexity.
  2. Second Pass (-pass 2): The encoder uses the generated log file to distribute bits across the entire duration of the video. It allocates higher bitrates to high-motion and complex scenes while reducing bitrates during static or low-detail scenes.
  • Speed: Requires significantly more time because the video is parsed twice.
  • Bitrate Allocation: Highly optimized, maximizing visual quality at any given target size.
  • Predictability: Allows strict adherence to a specific file size or average bitrate (VBR/CBR).
  • Primary Use Case: Video on Demand (VoD), archival, web hosting, and any offline distribution where final quality takes precedence over encoding duration.

FFmpeg Two-Pass Example

Pass 1:

ffmpeg -i input.mp4 -c:v libvpx-vp9 -b:v 2M -crf 30 -pass 1 -an -f null /dev/null

Pass 2:

ffmpeg -i input.mp4 -c:v libvpx-vp9 -b:v 2M -crf 30 -pass 2 -c:a libopus -b:a 128k output.webm

Key Differences Summary

Feature Single-Pass (libvpx-vp9) Two-Pass (libvpx-vp9)
Encoding Speed Fast Approximately 2x slower
Bitrate Efficiency Lower quality per megabyte Maximum quality per megabyte
Complex Scenes Risk of blocking or bitrate spikes Handled cleanly using global lookahead

Best For Live streams, rapid drafts Production VoD, web distribution

Which One Should You Choose?

For virtually all offline WebM/VP9 video production, two-pass encoding is the recommended standard. VP9's advanced compression mechanisms rely heavily on lookahead statistics to achieve its high compression ratios compared to older codecs like H.264. Use single-pass encoding only when time or compute resources are strictly limited.
