Opus Loudness Normalization in WebM Containers

This article examines the loudness normalization metadata mechanisms available for Opus audio streams encapsulated within WebM containers. It details the intrinsic header gain values defined by the Opus format, the supplementary ReplayGain and ITU-R BS.1770 / EBU R 128 container tags supported by WebM, and how media players apply this metadata during decoding and playback.

Opus Head Output Gain

The primary loudness adjustment mechanism for Opus in WebM is the Output Gain field embedded in the OpusHead structure. When Opus is encapsulated in WebM (which is a subset of the Matroska container format), the OpusHead is placed inside the CodecPrivate element of the audio track.

  • Field Definition: A 16-bit signed integer representing a gain offset in \(1/256\,\text{dB}\) units (Q7.8 format).
  • Application: Decoders are required by the Opus specification to apply this gain directly during the decoding pipeline unless explicitly instructed otherwise by a player interface.
  • Intended Use: Normalizing the stream to a reference level (typically -23 LUFS / -24 LUFS for broadcast or custom targets for streaming) without modifying or re-encoding the compressed audio frames.

Matroska / WebM Tag-Based Loudness Metadata

In addition to the bitstream header gain, WebM inherits Matroska's tagging system (<Tags> element), which allows non-destructive, non-mandatory loudness metadata to be carried at the container level. These tags are useful when a player wants to apply loudness adjustments selectively (e.g., applying album gain instead of track gain, or leaving dynamic range untouched).

ReplayGain Standard Tags

WebM supports standard ReplayGain tags stored within SimpleTag elements:

  • REPLAYGAIN_TRACK_GAIN: Stored as a floating-point string specifying the decibel gain relative to the target level (e.g., -3.20 dB).
  • REPLAYGAIN_TRACK_PEAK: A floating-point number representing the maximum sample or true-peak value normalized to 1.0 (e.g., 0.985432).
  • REPLAYGAIN_ALBUM_GAIN: The decibel gain required to normalize an entire collection of tracks together.
  • REPLAYGAIN_ALBUM_PEAK: The highest peak value across the entire album.

ITU-R BS.1770 and EBU R 128 Tags

Modern distribution workflows often include explicit loudness metrics defined by ITU-R BS.1770 and EBU R 128:

  • LOUDNESS_INTEGRATED / EBU_R128_INTEGRATED: The measured integrated loudness of the track in LUFS (e.g., -14.0 LUFS).
  • LOUDNESS_RANGE / EBU_R128_LRA: The statistical loudness range of the track in LU.
  • TRUE_PEAK: The maximum inter-sample peak level in dBTP.

Processing and Precedence

Players and playback frameworks (such as FFmpeg, Chromium, and libavformat) handle these loudness values according to their implementation:

  1. Decoder Level: The Opus decoder automatically reads the CodecPrivate gain from the OpusHead and scales the output PCM samples.
  2. Player/Renderer Level: If container tags (such as ReplayGain or R128 metadata) exist, a player can calculate additional scaling at the audio mixing stage to match a custom target (such as -14 LUFS for web streaming) or to prevent clipping identified by peak tags.
