Sub-Pixel Interpolation Filters in WebM Video

Sub-pixel motion estimation in WebM codecs, primarily VP8 and VP9, allows video encoders to achieve high compression efficiency by tracking motion at fractional pixel offsets rather than whole-integer grid points. Because real-world motion rarely aligns cleanly with the camera's discrete pixel grid, the encoder must reconstruct nonexistent pixel values at fractional locations—such as half-pixel, quarter-pixel, or eighth-pixel coordinates. This reconstruction is executed using finite impulse response (FIR) interpolation filters applied across neighboring full-pixel samples to generate smooth, artifact-free reference blocks for inter-frame prediction.

The Role of Fractional Shifts

In standard integer-pixel motion estimation, motion vectors point directly to actual sample points captured in reference frames. Fractional pixel shifts refine these vectors by addressing displacements between full pixels. When a motion vector contains a fractional component, the codec cannot simply copy a block from the reference frame. Instead, it must dynamically generate the reference block through interpolation, significantly reducing prediction error (residuals) and saving bits during entropy coding.

Separable 1D Filtering Process

WebM codecs compute 2D sub-pixel surfaces using separable 1D filtering to maintain computational efficiency. Instead of evaluating complex two-dimensional matrices simultaneously:

  1. Horizontal Pass: A 1D horizontal interpolation filter is applied across the integer pixels of the reference frame to produce intermediate values at the required horizontal fractional phase.
  2. Vertical Pass: A 1D vertical interpolation filter is then applied to the intermediate values generated by the horizontal pass to establish the final vertical fractional phase.

Intermediate calculations maintain elevated bit depths (typically 14 to 16 bits of precision) to prevent rounding errors and drift before the values are scaled, rounded, and clamped back to the native video bit depth.

VP8 Sub-Pixel Implementation

In the legacy VP8 standard used within early WebM containers, motion vectors achieve quarter-pixel (1/4-pel) precision. The interpolation process operates in two distinct stages:

  • Half-Pixel (1/2-pel) Positions: VP8 applies a symmetric 6-tap filter with coefficients [2, -11, 108, 108, -11, 2] / 128 (or similar normalized variants depending on the exact fractional offset). This long filter uses six adjacent integer samples to capture high-frequency details while attenuating high-frequency noise.
  • Quarter-Pixel (1/4-pel) Positions: Once half-pixel values are derived, quarter-pixel values are calculated using simple bilinear interpolation (a 2-tap average) between the nearest full-pixel and half-pixel neighbors.

VP9 Advanced Switchable Filtering

VP9 expands sub-pixel precision down to eighth-pixel (1/8-pel) shifts and replaces the fixed VP8 approach with switchable 8-tap interpolation filters. Because different image regions possess different spatial frequency characteristics, VP9 allows the encoder to select among three distinct filter types at the frame or block level:

  • Regular (8-tap): A balanced filter based on a windowed sinc function. It serves as the general-purpose default, preserving sharpness while avoiding aliasing artifacts.
  • Smooth (8-tap): Applies heavier smoothing by attenuating higher frequencies. This filter is optimal for flat textures, low-contrast gradients, and noisy scenes where sharp interpolation could produce false high-frequency ringing.
  • Sharp (8-tap): Emphasizes high-frequency retention with a sharper cut-off. It is best applied to distinct structural edges, fine textures, and high-contrast boundaries to prevent motion blur during translation.

Each of these three filters includes precomputed coefficient sets for each of the possible fractional phases between integer samples (1/8, 2/8, 3/8, 4/8, 5/8, 6/8, and 7/8).

Boundary Clamping and Precision Control

When sub-pixel interpolation occurs near frame borders, the multi-tap filter inevitably references coordinates lying outside the reconstructed frame. WebM decoders resolve this by extending edge pixels outward via clamping (edge replication). The mathematical sums generated by the FIR filters are subsequently normalized by division (implemented via right-bit shifts) with an added rounding factor to ensure bit-exact cross-platform decoding between software and hardware implementations.
