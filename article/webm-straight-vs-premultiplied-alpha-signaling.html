WebM Straight vs Premultiplied Alpha Signaling

The WebM container format indicates the presence of transparency through specific video track metadata and container-level frame packaging, standardizing natively on straight alpha rather than providing a toggle for premultiplied alpha. Understanding how WebM signals transparency involves examining the AlphaMode container element, auxiliary alpha data storage via BlockAdditional, and how decoders handle the interpretation of color and opacity data during playback and compositing.

The AlphaMode Element

WebM inherits its container structure from Matroska (EBML). Transparency signaling is primarily handled in the container header under the TrackEntry -> Video element using the AlphaMode flag (EBML ID 0x53C0):

  • 0 (Default): The video stream contains no alpha channel.
  • 1: The video stream contains an alpha channel.

When AlphaMode is set to 1, demuxers and decoders are instructed to look for auxiliary alpha data alongside the primary video frames.

Alpha Storage via BlockAdditional

WebM does not interleave alpha components into a single standard 32-bit pixel format (like RGBA) inside VP8 or VP9 compressed bitstreams. Instead, it stores alpha data in a dedicated sub-stream within the container:

  1. The primary compressed VP8/VP9 frame contains the color (YUV) information.
  2. The alpha channel is compressed as a separate monochrome VP8/VP9 frame.
  3. This secondary alpha frame is packaged in the container alongside the base video frame using the BlockAdditional structure with a BlockAddID of 1.

Straight Alpha Standardization

The WebM specification natively defines alpha data as straight alpha (also known as unassociated alpha).

  • No Dedicated Container Flag: There is no separate container-level metadata tag inside WebM to toggle between straight and premultiplied color channels.
  • Color Independence: The primary video stream stores color values without prior multiplication by the corresponding alpha values.
  • Opacity Mask: The auxiliary alpha stream stores the raw, unmultiplied 8-bit transparency mask values ranging from 0 (fully transparent) to 255 (fully opaque).

Playback and Compositing Interpretation

Because the container signals the presence of an alpha channel via AlphaMode = 1 and assumes straight alpha conventions, the responsibility for handling premultiplication rests entirely on the rendering pipeline:

  • Demuxing/Decoding: The WebM demuxer parses the BlockAdditional data and passes the primary YUV color frame and the alpha frame to the decoders.
  • Color Space Conversion: Decoders convert the YUV data to RGB and align it with the decoded alpha plane.
  • Compositor Multiplication: If the rendering engine (such as a web browser graphics engine or a video editing timeline) requires premultiplied alpha for blending operations, it performs the premultiplication step in memory after decoding, multiplying the RGB values by the alpha factor prior to drawing the frame to the screen.
