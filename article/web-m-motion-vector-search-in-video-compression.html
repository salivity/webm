WebM Motion Vector Search in Video Compression

Motion vector search in WebM inter-frame compression is the process of locating matching pixel blocks between video frames to eliminate temporal redundancy. By utilizing codecs such as VP8 and VP9, WebM analyzes frame-to-frame movement, calculates displacement coordinates known as motion vectors, and encodes only the differences between frames. This mechanism drastically reduces file sizes while maintaining high visual fidelity.

Block Partitioning

The compression engine divides each target frame into smaller processing units. In VP8, frames are split into 16x16 macroblocks that can be further subdivided down to 4x4 sub-blocks. VP9 expands this with flexible superblock structures ranging from 64x64 down to 4x4 blocks. The motion estimation algorithm evaluates these blocks individually or hierarchically to determine the optimal block size for representing local motion.

Motion Vector Prediction

Before initiating an active search across the reference frame, the encoder calculates a motion vector predictor (MVP). This predictor is derived from the motion vectors of spatially adjacent blocks (left, top, top-right) and temporal co-located blocks from previous reference frames. Establishing a reliable starting predictor narrows the search radius, accelerates computation, and reduces the bitrate required to encode the final motion vector differences.

Search Area and Pattern Algorithms

Instead of performing an exhaustive Full Search across the entire reference frame, WebM encoders deploy fast-search heuristic algorithms to find the best block match within a defined search window. Common search patterns include:

  • Diamond Search (DS) and Hexagon Search (HEX): Iterative spatial step patterns that quickly move toward the direction of highest correlation.
  • Successive Elimination: Algorithms that use mathematical inequalities to skip candidate blocks that mathematically cannot beat the current best match.

The search tests candidate blocks within one or more reference frames (such as the "Last Frame," "Golden Frame," or "AltRef Frame" in VP8/VP9).

Cost Function and Matching Metrics

Candidate blocks are evaluated using error metrics to measure distortion. The encoder primarily uses:

  1. Sum of Absolute Differences (SAD): A computationally lightweight metric used in the early stages of integer-pel searches to assess raw pixel differences.
  2. Sum of Squared Differences (SSD) / Sum of Absolute Transformed Differences (SATD): A metric that factors frequency-domain fidelity via Hadamard transforms for greater accuracy.
  3. Rate-Distortion Optimization (RDO): The final evaluation balances image distortion (\(D\)) against the estimated bit cost (\(R\)) needed to signal the motion vector, governed by the Lagrangian multiplier equation: \[\text{Cost} = D + \lambda \cdot R\]

Sub-Pixel Refinement

Once the best integer-pixel (full-pel) location is identified, the algorithm refines the search to fractional-pixel accuracy (half-pel, quarter-pel, and in some profiles, eighth-pel precision). Because actual physical motion rarely aligns perfectly with the pixel grid, the encoder uses interpolation filters (such as 6-tap or 8-tap sub-pixel filters) to generate virtual intermediate pixel values. The vector is adjusted to the sub-pixel coordinate that yields the lowest RDO cost.

Residual Generation and Encoding

After the optimal motion vector is determined, the encoder subtracts the predicted reference block from the current block to produce a "residual error" matrix. If the motion vector search is successful, this residual is near zero across most pixels. The encoder then applies Discrete Cosine Transform (DCT) or Asymmetric Discrete Sine Transform (ADST), quantizes the transformed coefficients, and packages the motion vector differences alongside the residual data using boolean entropy encoding.
