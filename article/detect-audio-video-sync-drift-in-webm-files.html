Detect Audio Video Sync Drift in WebM Files

Audio-video (AV) synchronization drift occurs when the audio and visual tracks of a media container gradually fall out of alignment over time. This article covers automated methods and scripts used to detect and measure AV sync discrepancies in generated WebM files, focusing on FFmpeg/FFprobe scripts, Python automation using packet presentation timestamps (PTS), and specialized media analysis tools.

Understanding AV Drift in WebM Containers

WebM is a subset of the Matroska (MKV) container format that typically encapsulates VP8/VP9/AV1 video and Vorbis/Opus audio. Sync issues in generated WebM files generally stem from:

  • Variable Frame Rate (VFR) inconsistencies: Video frames dropping without corresponding timestamp adjustments.
  • Timestamp offsets: A difference between the initial audio PTS and video PTS (start_time offset).
  • Clock drift / Duration mismatch: Sampling rate discrepancies causing the audio stream's total duration to diverge from the video stream.

1. Quick Duration and Start Time Check (Bash + FFprobe)

A fast method to detect gross desynchronization is comparing the start times and total durations of the primary audio and video streams using ffprobe.

#!/usr/bin/env bash

FILE="$1"

if [ -z "$FILE" ]; then
    echo "Usage: $0 <input.webm>"
    exit 1
fi

# Extract video and audio start times and durations
V_START=$(ffprobe -v error -select_streams v:0 -show_entries stream=start_time -of default=noprint_wrappers=1:nokey=1 "$FILE")
A_START=$(ffprobe -v error -select_streams a:0 -show_entries stream=start_time -of default=noprint_wrappers=1:nokey=1 "$FILE")
V_DUR=$(ffprobe -v error -select_streams v:0 -show_entries stream=duration -of default=noprint_wrappers=1:nokey=1 "$FILE")
A_DUR=$(ffprobe -v error -select_streams a:0 -show_entries stream=duration -of default=noprint_wrappers=1:nokey=1 "$FILE")

# Fallback to container-level duration if stream duration is empty
if [ -z "$V_DUR" ] || [ -z "$A_DUR" ]; then
    V_DUR=$(ffprobe -v error -show_entries format=duration -of default=noprint_wrappers=1:nokey=1 "$FILE")
    A_DUR=$V_DUR
fi

# Calculate drift and offset using python for floating-point arithmetic
python3 -c "
v_start = float('${V_START:-0}')
a_start = float('${A_START:-0}')
v_dur = float('${V_DUR:-0}')
a_dur = float('${A_DUR:-0}')

start_offset = abs(v_start - a_start)
duration_drift = abs(v_dur - a_dur)

print(f'Start Time Offset : {start_offset:.4f} s')
print(f'Duration Drift    : {duration_drift:.4f} s')

THRESHOLD = 0.040 # 40ms standard broadcast tolerance
if start_offset > THRESHOLD or duration_drift > THRESHOLD:
    print('[FAIL] Desynchronization detected exceeding threshold.')
    exit(1)
else:
    print('[PASS] Audio and video streams are synchronized.')
"

2. Packet-Level Timestamp Analysis (Python)

For generated files where streams are padded or frame drops cause gradual internal drift, packet-level analysis via ffprobe JSON output is required.

#!/usr/bin/env python3
import json
import subprocess
import sys

def analyze_webm_sync(file_path, threshold_ms=45):
    """
    Analyzes packet presentation timestamps (PTS) to check for AV drift.
    """
    cmd = [
        "ffprobe",
        "-v", "error",
        "-show_packets",
        "-select_streams", "v:0,a:0",
        "-show_entries", "packet=codec_type,pts_time,duration_time",
        "-of", "json",
        file_path
    ]
    
    result = subprocess.run(cmd, stdout=subprocess.PIPE, stderr=subprocess.PIPE, text=True)
    if result.returncode != 0:
        print(f"Error reading file: {result.stderr}")
        sys.exit(1)
        
    data = json.loads(result.stdout)
    packets = data.get("packets", [])
    
    video_pts = [float(p["pts_time"]) for p in packets if p.get("codec_type") == "video" and "pts_time" in p]
    audio_pts = [float(p["pts_time"]) for p in packets if p.get("codec_type") == "audio" and "pts_time" in p]

    if not video_pts or not audio_pts:
        print("Error: Missing video or audio packets.")
        sys.exit(1)

    initial_offset = abs(video_pts[0] - audio_pts[0]) * 1000
    final_drift = abs(video_pts[-1] - audio_pts[-1]) * 1000

    print(f"File: {file_path}")
    print(f"Initial Offset : {initial_offset:.2f} ms")
    print(f"Final End Delta: {final_drift:.2f} ms")

    if initial_offset > threshold_ms or final_drift > threshold_ms:
        print(f"Result: FAIL (Exceeds {threshold_ms} ms threshold)")
        return False
    
    print("Result: PASS")
    return True

if __name__ == "__main__":
    if len(sys.argv) < 2:
        print("Usage: python3 sync_check.py <file.webm>")
        sys.exit(1)
    
    success = analyze_webm_sync(sys.argv[1])
    sys.exit(0 if success else 1)

3. Signal-Based and Test-Pattern Verification

When automated verification requires testing actual content synchronization (rather than only container metadata):

  • Flash-and-Beep Pattern Scripts: When generating synthetic WebM test media, inject a visual flash alongside an audio beep at set intervals (e.g., every 10 seconds). You can then run an automated script using FFmpeg filters (blackdetect / freezedetect combined with ebur128 or silencedetect) to correlate the exact timestamps where the visual and audio events trigger.
  • QCTools CLI: The open-source qcli tool can process WebM files to output frame-by-frame quality metrics, including audio/video continuity flags that reveal dropped frames directly correlated to drift.
  • Cross-Correlation Automation: For transcode testing (e.g., source MP4 to generated WebM), scripts can extract the raw audio using FFmpeg, generate an acoustic fingerprint or cross-correlation matrix against the source audio track, and measure the exact sample shift.
