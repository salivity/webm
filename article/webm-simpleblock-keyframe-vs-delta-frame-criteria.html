WebM SimpleBlock Keyframe vs Delta Frame Criteria

Determining whether a WebM SimpleBlock contains a keyframe or a delta frame relies primarily on a specific 1-byte header flag defined at the container level. While the container-level flag provides decoders and demuxers with immediate frame classification without parsing the underlying video stream, bitstream-level data within formats such as VP8, VP9, or AV1 also contains explicit markers defining frame types.

The Container-Level Flag (Matroska/EBML)

In the WebM specification, which is a subset of the Matroska (MKV) format, frame data is packaged within a SimpleBlock element. The binary structure of a SimpleBlock header consists of three main metadata fields preceding the actual media payload:

  1. Track Number: Encoded as an EBML variable-length integer (VINT).
  2. Timecode (Relative Timestamp): Stored as a signed 16-bit integer (2 bytes).
  3. Flags Byte: A single 8-bit field (1 byte) containing packet-level indicators.

The determination of a keyframe versus a delta frame occurs at the container level by inspecting Bit 7 (the most significant bit, or mask 0x80) of this flags byte:

  • Keyframe: If Bit 7 is set to 1 (flags & 0x80 != 0), the block represents an intra-frame (keyframe). This frame can be decoded independently without references to previous or future frames.
  • Delta Frame: If Bit 7 is set to 0 (flags & 0x80 == 0), the block contains an inter-frame (delta frame) that depends on data from other reference frames.

Codec-Level Bitstream Confirmation

While demuxers rely on the SimpleBlock flags byte for fast seeking and indexing, the payload itself also dictates whether the frame is a keyframe according to the video codec's specification:

  • VP8: The frame header begins with a 3-byte uncompressed tag. Bit 0 of the first byte specifies the frame type: 0 denotes a keyframe, and 1 denotes an inter-frame.
  • VP9: The uncompressed header contains a frame_type bit immediately following the frame marker and profile bits. A value of 0 denotes a KEY_FRAME, whereas other values signify non-keyframes such as INTER_FRAME.
  • AV1: The frame header within the Open Bitstream Unit (OBU) contains a frame_type syntax element. When set to KEY_FRAME (value 0) or INTRA_ONLY_FRAME (value 2), the frame provides intra-coded refresh functionality.

Standards-compliant WebM encoders synchronize the SimpleBlock Bit 7 flag with the codec-level frame type. A disparity where the container marks a frame as a keyframe while the bitstream represents an inter-frame is considered malformed.

Handling Audio Blocks

For audio tracks contained in a SimpleBlock, Bit 7 is almost universally set to 1. Because compressed audio packets (such as Opus or Vorbis) are typically independently decodable without temporal reference frames, they are treated as keyframes at the container level.
