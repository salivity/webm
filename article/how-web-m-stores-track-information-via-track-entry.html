How WebM Stores Track Information via TrackEntry

The WebM container format, derived from Matroska (MKV), utilizes an Extensible Binary Meta Language (EBML) structure to organize multimedia streams. At the core of stream configuration is the TrackEntry element, which resides inside the parent Tracks master element. This article explains how WebM uses TrackEntry to define individual audio, video, and subtitle streams, covering essential metadata fields, codec identification, and media-specific configuration settings required for playback.

Structural Placement in EBML

In a WebM file, data is arranged hierarchically. The root EBML header is followed by a Segment element, which contains major sections including Info, Tracks, and Cluster (media payloads).

The Tracks element acts as a container for one or more TrackEntry elements:

\Segment
  \Tracks
    \TrackEntry (Video Track)
    \TrackEntry (Audio Track)

Each TrackEntry represents a distinct elementary stream and contains all parameters needed by a demuxer and decoder to process that stream.

Key Identifiers and Flags

Each TrackEntry includes basic properties that define how the demuxer routes packets to the correct decoder pipeline:

  • TrackNumber: A compact integer used inside individual data blocks (SimpleBlock or BlockGroup) within Clusters to associate media frames with this track.
  • TrackUID: A unique 64-bit integer assigned to the track, ensuring persistent identification across edits or stream merges.
  • TrackType: An integer specifying the media type. Common WebM values are 1 for Video, 2 for Audio, and 17 for Subtitles.
  • FlagEnabled: Indicates whether the track is active and usable (default is 1).
  • FlagDefault: Indicates whether the track should be played automatically if no user preference is specified.
  • FlagLacing: Specifies whether the track allows EBML frame lacing to pack multiple frames into a single block.

Codec Configuration

TrackEntry links the container metadata to the appropriate decoding library via specific codec parameters:

  • CodecID: A standardized string defining the compression format. WebM supports specific codecs such as V_VP8, V_VP9, and V_AV1 for video, and A_OPUS or A_VORBIS for audio.
  • CodecPrivate: A binary data field containing stream-level headers or initialization data required by specific decoders (such as Vorbis setup headers or AV1 sequence headers).
  • CodecName: An optional human-readable name for the codec.
  • SeekPreRoll / CodecDelay: Used frequently with codecs like Opus to manage audio priming and correct decoding timestamps.

Media-Specific Sub-Elements

Depending on the TrackType, a TrackEntry contains specialized master elements describing spatial or temporal parameters:

Video Settings (Video Element)

  • PixelWidth / PixelHeight: Coded dimensions of the video stream in pixels.
  • DisplayWidth / DisplayHeight: Intended rendering dimensions, accounting for non-square pixel aspect ratios.
  • FrameRate: Optional nominal frame rate value.
  • Colour: Contains advanced colorimetry information, including matrix coefficients, transfer characteristics, and color primaries for HDR metadata.

Audio Settings (Audio Element)

  • SamplingFrequency: Audio sampling rate in Hertz (e.g., 48000.0).
  • Channels: The number of audio channels (e.g., 1 for mono, 2 for stereo, 6 for 5.1 surround).
  • BitDepth: Optional bit resolution per sample.

Demuxer Processing

When a media player opens a WebM file, it parses the Tracks header and creates an internal representation of each TrackEntry. The player instantiates the matching decoders using CodecID and CodecPrivate data, maps the TrackNumber to the decoding queue, and configures output buffers using the resolution and audio channel properties stored in the TrackEntry.
