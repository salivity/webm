VP9 Visible vs Altref Frame Binary Flags Explained

In WebM VP9 bitstreams, the decoder determines whether a decoded frame is presented to the viewer or stored invisibly as an alternate reference (altref) frame by parsing specific binary flags in the uncompressed frame header. Altref frames act as invisible temporal predictors that enhance compression efficiency without being rendered directly to the display. The primary syntax element controlling this behavior is the show_frame flag, which works in conjunction with show_existing_frame to manage the decoding and display pipeline.

The show_frame Flag

The decisive binary flag distinguishing visible frames from non-displayed frames is show_frame. Located in the uncompressed header immediately after the frame type declaration (when decoding a new frame), show_frame is a single-bit syntax element:

  • show_frame = 1: The frame is decoded and immediately output to the display buffer as a visible frame.
  • show_frame = 0: The frame is decoded but suppressed from display. It is written exclusively into one or more reference frame buffers for future inter-frame prediction. Every standard altref frame is coded with show_frame = 0.

The show_existing_frame Flag

Before checking show_frame, the decoder evaluates the show_existing_frame flag, which appears near the very beginning of the uncompressed header (after the 2-bit frame marker and profile bits):

  • show_existing_frame = 1: Instructs the decoder not to decode a new picture payload. Instead, it reads a subsequent 3-bit index (frame_to_show_map_idx) pointing to an existing reference buffer (such as the buffer storing a previously decoded altref frame) and outputs it directly to the display.
  • show_existing_frame = 0: Signals that a full, standard frame header follows, containing new compressed transform blocks and motion vectors, followed by the frame_type and show_frame flags.

Buffer Management: refresh_frame_flags

When a frame is designated as invisible (show_frame = 0), the bitstream must designate where that frame will be held in memory. In non-key frames, the header exposes the 8-bit refresh_frame_flags field.

Each bit corresponds to one of the eight internal reference frame buffers maintained by the VP9 decoder. For an altref frame, the encoder sets the specific bit corresponding to the designated altref buffer slot (traditionally buffer index 2 or 3, depending on encoder configuration). This guarantees that the decoded data is retained for future motion compensation.

Summary of Bitstream States

Frame Intent show_existing_frame show_frame Description
Visible Frame 0 1 Decodes a new frame and outputs it immediately.
Altref Frame 0 0 Decodes a new invisible frame and stores it in the reference buffer.
Display Altref 1 N/A Does not decode new image data; displays a stored reference frame indicated by frame_to_show_map_idx.
