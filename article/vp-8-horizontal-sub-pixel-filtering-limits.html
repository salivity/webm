VP8 Horizontal Sub-Pixel Filtering Limits

This article provides an overview of the computational limits associated with VP8 horizontal sub-pixel filtering in WebM decoders. In VP8 motion compensation, fractional-pixel interpolation accounts for a substantial share of decoding workloads. The performance ceilings of horizontal sub-pixel filtering are primarily governed by filter tap depth, memory bandwidth, SIMD vectorization constraints, and intermediate precision management during separable filtering operations.

Filter Tap Depth and Arithmetic Complexity

VP8 utilizes a 6-tap polyphase filter for fractional-pel interpolation at half-pixel locations, as well as a bilinear or 6-tap based configuration for quarter-pixel offsets. Computing a single horizontal sub-pixel requires reading six continuous horizontal source pixels, multiplying each by a filter coefficient, and summing the results.

The mathematical operation requires six multiplications and five additions per reconstructed sample. When scaled to large macroblock partitions (such as 16x16 luma blocks) across high frame rates, this creates a sustained computational floor. While the coefficients are static and symmetric, reducing dynamic coefficient calculation overhead, the fixed multiply-accumulate (MAC) density remains a constant processing drain on hardware decoders and CPUs lacking dedicated video acceleration.

SIMD Alignment and Register Pressure

On modern processors, horizontal filtering is accelerated via SIMD extensions such as x86 SSE/AVX or ARM NEON. However, horizontal filtering faces architectural vectorization limits:

  1. Precision Expansion: Source pixels are 8-bit unsigned values, but coefficient multiplication requires signed 16-bit intermediate storage to avoid overflow during summation. Converting 8-bit data to 16-bit registers halves the effective vector capacity of SIMD units.
  2. Unaligned Memory Loads: Horizontal interpolation frequently accesses memory addresses not aligned to 16-byte or 32-byte boundaries. Unaligned loads reduce throughput and increase pipeline stall frequencies compared to aligned block copies.
  3. Data Shuffling: Computing horizontal neighbor samples across vector lanes requires frequent intra-register shifts, byte-unpacking, or permute instructions (such as pslldq, psrldq, or palignr), which consume valuable execution cycles before arithmetic logic units can execute multiplication.

Intermediate Buffering and Cache Contention

Sub-pixel motion compensation in VP8 is typically implemented as a separable 2D filter: a horizontal pass followed by a vertical pass. The horizontal filter executes first, outputting intermediate results that must be consumed by the vertical filter.

Because the intermediate values require 16-bit signed precision to maintain accuracy prior to rounding, the intermediate data stream doubles in memory size relative to the final reconstructed image. Decoders must either write these intermediate values to L1 cache arrays or maintain them entirely within wide processor registers. When high-resolution streams exceed processor cache limits or register allocation capacity, the horizontal filter introduces memory bandwidth bottlenecks that restrict overall decoder frame rates.
