How CSP Restricts Unauthorized WebM Media Loading

Content Security Policy (CSP) secures web applications by dictating which external sources and origins are authorized to deliver executable content and media assets. In the context of WebM media files, CSP relies on the media-src directive to validate all requests originating from HTML <audio> and <video> elements. By configuring these directives, web administrators ensure browsers reject any WebM asset fetched from unauthorized domains, preventing malicious media injection, bandwidth theft, and data exfiltration.

The Role of the media-src Directive

The media-src directive specifically governs the origins from which multimedia assets—including WebM video and audio files—can be requested and rendered. When a browser parses a document containing a <video> tag referencing a WebM resource, it checks the source URL against the rules defined in the site's Content-Security-Policy HTTP response header.

If media-src is explicitly defined, the browser only permits WebM requests that match the specified domains, schemes, or keywords. If the media-src directive is not defined, the browser falls back to the rules configured under the broader default-src directive.

Browser Enforcement Mechanism

  1. Request Interception: When the browser encounters an element such as <video src="https://untrusted-cdn.com/video.webm">, the network engine consults the active CSP header before completing the network fetch.
  2. Policy Evaluation: The destination URL is evaluated against the whitelist specified in the policy.
  3. Action:
    • Allowed Origin: If the domain matches an entry (such as 'self' or a designated CDN), the browser continues downloading and playing the WebM stream.
    • Unauthorized Origin: If the domain is absent from the policy, the browser immediately terminates the network request, blocks the WebM media from loading, and logs a CSP violation in the browser's developer console.

Policy Configuration Examples

To restrict WebM playback exclusively to the website's own origin and a trusted CDN, deploy the following HTTP header:

Content-Security-Policy: default-src 'self'; media-src 'self' https://media.trustedcdn.com;

In this setup, attempting to load a WebM video from https://unauthorized-source.com/media.webm fails immediately.

To completely prevent the website from loading any media files, including WebM:

Content-Security-Policy: media-src 'none';

Restricting Media Schemes and Buffers

Attackers can sometimes bypass simple domain checks by generating media on the client side using JavaScript and custom streams. CSP mitigates this by controlling protocol schemes:

  • Blob URLs: If a WebM file is constructed dynamically in memory using Media Source Extensions (MSE) or URL.createObjectURL(), it uses the blob: scheme. You must explicitly include blob: in media-src to allow it, or omit it to block programmatic media generation.
  • Data URIs: Embedded Base64 WebM streams use the data: scheme. Omitting data: from media-src prevents inline media payload execution.

Violation Monitoring

CSP allows developers to monitor unauthorized WebM loading attempts without necessarily breaking user experience via the Content-Security-Policy-Report-Only header combined with the report-to directive. This enables real-time logging of unauthorized media assets attempting to load across the application.
