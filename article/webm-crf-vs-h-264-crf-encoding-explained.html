WebM CRF vs H.264 CRF Encoding Explained

The Constant Rate Factor (CRF) is a rate control mode that dynamically adjusts bitrate to maintain consistent visual quality across video frames. While both H.264 (typically encoded via libx264) and WebM codecs (VP8 and VP9 via libvpx and libvpx-vp9) utilize the -crf parameter, they operate on different numerical scales, handle bitrate limits differently in encoding tools like FFmpeg, and yield distinct visual quality at equivalent numerical values.

The Numerical Scale Differences

The most immediate difference between H.264 and WebM CRF is the scale range:

  • H.264 (libx264): The scale runs from 0 to 51. A value of 0 is truly lossless, 23 is the default, and 18 is generally considered visually lossless. Every increase of +6 roughly halves the bitrate.
  • WebM (libvpx / libvpx-vp9): The scale runs from 0 to 63. A value of 0 represents the highest quality (lossless in VP9 when combined with specific profiles), while 63 represents the lowest quality.

Because the scales have different maximum bounds and underlying mathematical models, identical numerical values do not produce equivalent visual quality.

Quality and Bitrate Equivalencies

A common misconception is that setting -crf 23 in VP9 will yield the same output as -crf 23 in x264. In practice:

  • x264 Quality Baseline: Values between 18 and 28 are standard. An x264 CRF of 23 produces high-definition content with a balanced file size.
  • VP9 Equivalent Targets: Recommended VP9 CRF values generally fall between 15 and 35. To match the visual quality of an H.264 encode at CRF 23, VP9 typically requires a CRF value between 30 and 33, resulting in a significantly smaller file size due to VP9's superior compression efficiency.
  • VP8 Target Range: For the older VP8 codec, usable CRF values generally sit between 4 and 16 for high quality, as VP8 is less efficient than both x264 and VP9.

FFmpeg Rate Control Implementation

In FFmpeg, the -crf parameter behaves differently depending on whether it is used with libx264 or libvpx-vp9:

1. Pure CRF Mode in H.264

For H.264, invoking -crf automatically enables Constant Rate Factor mode without needing additional bitrate parameters:

ffmpeg -i input.mp4 -c:v libx264 -crf 23 output.mp4

2. Constrained vs. Pure CRF in WebM (VP9)

For WebM codecs, specifying only -crf triggers Constrained Quality (CQ) mode, which targets the specified CRF but caps the bitrate to the codec's default target bitrate. To achieve Pure CRF mode (unconstrained variable bitrate based strictly on visual quality), the video bitrate must explicitly be set to zero (-b:v 0):

ffmpeg -i input.mp4 -c:v libvpx-vp9 -crf 31 -b:v 0 output.webm

Omitting -b:v 0 in VP9 encoding will cause the encoder to prioritize the default bitrate limit over the desired visual quality target.
