WebM Opus: Stereo vs Multi-Stream Audio Parsing

WebM parsers differentiate between simple stereo and multi-stream Opus audio packets by evaluating initialization metadata located in the container's track header rather than inspecting the raw audio payload alone. Specifically, the parser inspects the CodecPrivate element within the Matroska/WebM EBML structure, which encapsulates the Opus identification header (OpusHead). This header defines the channel mapping family, stream counts, and channel layout, instructing the demuxer and decoder whether incoming packets consist of standard single-stream audio or multiplexed multi-stream audio frames.

The Role of the WebM Track Header

WebM containers designate Opus audio tracks using the A_OPUS Codec ID. When opening an audio track, a compliant WebM parser must first read the CodecPrivate EBML data element associated with that track.

The CodecPrivate payload matches the layout of the standard Ogg Opus identification header (OpusHead). The critical fields parsed include:

  • Channel Count (8 bits): The total number of output channels.
  • Channel Mapping Family (8 bits): The operational mode defining how streams are mapped to output channels.
  • Stream Count (8 bits): The number of individual Opus streams present in each packet (present only if the mapping family is greater than 0).
  • Coupled Stream Count (8 bits): The number of stereo-coupled streams (present only if the mapping family is greater than 0).
  • Channel Mapping Table: An array of channel indices mapping decoded streams to speaker positions.

Differentiating by Channel Mapping Family

The primary branching point for a WebM parser is the Channel Mapping Family:

1. Simple Stereo (Mapping Family 0)

When the mapping family byte is set to 0:

  • The channel count must be either 1 (mono) or 2 (stereo).
  • No stream count, coupled stream count, or mapping table fields are stored in CodecPrivate.
  • The parser interprets the stream count implicitly as 1.
  • Each WebM SimpleBlock or Block payload represents an individual, standard Opus packet.
  • The internal Opus Table of Contents (TOC) byte within the packet itself signals whether that single stream contains mono or stereo data, stereo coupling modes, and the encoding bandwidth.

2. Multi-Stream Opus (Mapping Family 1 and Others)

When the mapping family is set to 1 (surround sound layouts up to 255 channels) or higher (such as family 2 or 3 for Ambisonics):

  • The parser reads the explicit Stream Count (\(M\)) and Coupled Stream Count (\(N\)) fields directly from CodecPrivate.
  • Total output channels can exceed 2 (e.g., 5.1 or 7.1 surround).
  • The parser configures the multi-stream Opus decoder (opus_multistream_decoder) with the exact channel mapping matrix.

Packet Structure Differences

Once configured by the header, the WebM parser processes the packet data contained in individual media blocks:

  • Family 0 Packets: The entire block payload corresponds to a single Opus packet. The parser passes the buffer directly to the standard Opus decoder without splitting.
  • Multi-Stream Packets: The WebM block contains \(M\) separate Opus stream payloads packed consecutively. To decode these correctly, the multi-stream framing convention requires that the first \(M - 1\) sub-packets use the self-delimiting framing format (which includes a length prefix indicating byte size), while the final (\(M\)-th) sub-packet occupies the remainder of the block.

By combining the structural rules of CodecPrivate with the self-delimiting boundaries inside multi-stream packets, the WebM parser reliably unpacks and routes the audio data to the appropriate decoding pipeline.
