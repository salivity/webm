WebM Chapter Edition Flags for Alternate Cuts

WebM files can store multiple versions of a video—such as theatrical releases, director's cuts, or censored versions—within a single file by utilizing Matroska-based Chapter Edition structures. By defining multiple timeline playlists through chapter entries and setting specific flags like EditionFlagOrdered and EditionFlagDefault, a media player can construct different viewable cuts using shared audio and video data without duplicating footage.

The Mechanism: Editions and Ordered Chapters

Because the WebM format is a restricted subset of the Matroska (EBML) specification, it inherits the container's robust chaptering architecture. In standard playback, chapters simply mark jump points across a continuous timeline. However, the specification allows chapters to be organized into distinct EditionEntry groupings, where each edition represents a completely different timeline or cut.

Within an EditionEntry, the EditionFlagOrdered element is the primary mechanism that enables alternate cuts. When EditionFlagOrdered is set to true (1):

  • The media player treats the chapters in that edition as a sequential playlist rather than mere bookmarks.
  • The player plays the exact timestamp segments defined by each chapter's start and end times, jumping across gaps in the source video.
  • Shared scenes only need to be encoded once. Alternate scenes, extended takes, or bonus footage are appended elsewhere in the video track and referenced only by the editions that require them.

Key Chapter Edition Flags

To manage how players interact with these alternate cuts, the container relies on several flags defined at the EditionEntry level:

  • EditionFlagDefault: Dictates whether an edition should be selected automatically if the user has not chosen a preference. Only one edition per file should have this flag set to true (1). For example, a studio can set the standard theatrical cut as the default while keeping the director's cut accessible in the menu.
  • EditionFlagOrdered: Informs the parser that the chapters define a non-linear, ordered timeline. The player must assemble the playback path sequentially according to the chapter start and end timestamps rather than playing the physical stream from start to finish.
  • EditionFlagHidden: Marks an edition as hidden from the user interface. This is typically used for background structural logic, testing, or nested segment transitions that should not appear as user-selectable options in playback menus.

How Alternate Cuts Function in Practice

Consider a film with a common introduction, an alternate middle scene, and a common ending:

  1. The underlying video track contains: Segment A (Intro), Segment B (Theatrical Middle), Segment C (Director's Cut Middle), and Segment D (Ending).
  2. Edition 1 (Theatrical Cut): EditionFlagDefault is set to 1, and EditionFlagOrdered is set to 1. The chapter list explicitly references timestamps for Segment A, jumps directly to Segment B (skipping Segment C), and ends with Segment D.
  3. Edition 2 (Director's Cut): EditionFlagDefault is set to 0, and EditionFlagOrdered is set to 1. The chapter list references timestamps for Segment A, jumps over Segment B directly to Segment C, and concludes with Segment D.

When a compatible player opens the file, it reads the edition headers, presents the user with the choices, and seamlessly seeks between the designated time codes, delivering distinct viewing experiences from a single, storage-efficient file.
