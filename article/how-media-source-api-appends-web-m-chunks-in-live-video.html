How MediaSource API Appends WebM Chunks in Live Video

The MediaSource Extensions (MSE) API enables browsers to stream live video seamlessly by allowing JavaScript to pass media data directly to an HTML5 <video> element. During live WebM playback, the browser receives raw video/audio chunks from a server via WebSockets or HTTP, parses the container data, and appends it to a SourceBuffer instance. This article explains the technical lifecycle of initializing the MediaSource, structuring WebM initialization and media segments, managing the append queue, and handling buffer eviction for continuous live playback.

Initializing the MediaSource and SourceBuffer

The playback pipeline begins by creating a MediaSource object and assigning its object URL to the src attribute of a standard <video> element.

const video = document.querySelector('video');
const mediaSource = new MediaSource();
video.src = URL.createObjectURL(mediaSource);

Once attached, the mediaSource fires the sourceopen event. At this stage, you register a SourceBuffer by specifying the WebM MIME type and codec string:

mediaSource.addEventListener('sourceopen', () => {
  const mimeCodec = 'video/webm; codecs="vp9, opus"';
  const sourceBuffer = mediaSource.addSourceBuffer(mimeCodec);
});

WebM Stream Structure: Init Segment vs. Media Segments

WebM is a subset of the Matroska (MKV) container format based on Extensible Binary Meta Language (EBML). To correctly decode live chunks, the stream must be split into two types of segments:

  1. Initialization Segment: Contains the EBML Header, Segment Header, and Tracks element (which defines codec private data, resolution, and audio channels). This must be appended first so the decoder understands how to process incoming frames.
  2. Media Segments (Clusters): Contain one or more EBML Cluster elements holding the actual time-stamped video and audio frames (SimpleBlock or BlockGroup).

Appending Data via appendBuffer()

Live chunks are fetched continuously across the network as ArrayBuffer or Uint8Array objects. When a chunk arrives, it is fed to the SourceBuffer using appendBuffer():

  1. Check State: The application must verify that sourceBuffer.updating is false before appending.
  2. Append Data: Calling sourceBuffer.appendBuffer(chunk) transitions updating to true.
  3. Parse and Decode: The browser parses the EBML data, extracts the Presentation Time Stamps (PTS), and places the frames into the SourceBuffer's internal timeline track.
  4. Completion Event: Once the chunk is integrated into the buffer, the SourceBuffer dispatches the updateend event, setting updating back to false and signaling that the next chunk can be appended.

To prevent runtime errors, incoming network chunks should be stored in an in-memory queue and pushed to appendBuffer() sequentially upon every updateend event.

Managing Live Timelines and Buffer Eviction

During live streaming, video runs indefinitely, introducing two specific requirements:

  • Append Mode and Timestamp Offset: If the live stream segments contain disjointed or resetting internal timestamps, set sourceBuffer.mode = 'sequence'. This causes the browser to ignore container-level timestamps and append each new cluster immediately after the previous one. Alternatively, in 'segments' mode, the browser places clusters according to their internal timestamps, requiring continuous timestamps or manual adjustments using sourceBuffer.timestampOffset.
  • Memory Management (Buffer Eviction): Because browser memory is limited, retaining hours of live video in memory will crash the tab. The application must periodically remove older, already-viewed data from the buffer using sourceBuffer.remove(start, end):
const currentTime = video.currentTime;
if (currentTime > 60 && !sourceBuffer.updating) {
  // Retain the last 30 seconds, remove everything older
  sourceBuffer.remove(0, currentTime - 30);
}

Through this continuous cycle—fetching WebM clusters, queueing them, appending them to the SourceBuffer, and pruning old ranges—the MediaSource API delivers uninterrupted, low-latency live video playback.
