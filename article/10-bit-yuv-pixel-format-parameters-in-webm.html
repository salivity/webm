10-Bit YUV Pixel Format Parameters in WebM

This article provides an overview of the container-level parameters that define 10-bit YUV pixel formats within the WebM container. Because WebM is a subset of the Matroska (MKV) specification based on EBML (Extensible Binary Meta Language), video pixel format metadata is established inside the Video track settings using specific Colour sub-elements. Understanding these parameters is essential for accurately signaling bit depth, chroma subsampling, and colorimetry for codecs like VP9 and AV1.

The Colour Master Element

In WebM, track-level video attributes reside inside the TrackEntry -> Video element. Pixel format parameters—including bit depth, subsampling, and color space—are encapsulated within the optional Colour master element (EBML ID 0x55B0). When demuxers read a 10-bit YUV stream, they inspect the child elements of Colour to configure the decoding and rendering pipeline before the codec bitstream is even processed.

Key Container Elements Defining 10-Bit YUV

1. BitsPerChannel (0x55B2)

This element explicitly sets the bit depth of the luma and chroma components. For a 10-bit YUV stream, BitsPerChannel is an unsigned integer set to 10. If omitted, decoders typically default to 8 bits per channel unless signaled otherwise within the video bitstream.

2. Chroma Subsampling Elements

WebM specifies the layout of chroma channels (U and V) relative to luma (Y) using two separate horizontal and vertical subsampling parameters:

  • ChromaSubsamplingHorz (0x55B3): The number of pixels to remove horizontally. Set to 1 for 4:2:0 and 4:2:2, or 0 for 4:4:4.
  • ChromaSubsamplingVert (0x55B4): The number of pixels to remove vertically. Set to 1 for 4:2:0, or 0 for 4:2:2 and 4:4:4.

Together, these determine standard YUV formats:

  • YUV 4:2:0 (10-bit): ChromaSubsamplingHorz = 1, ChromaSubsamplingVert = 1
  • YUV 4:2:2 (10-bit): ChromaSubsamplingHorz = 1, ChromaSubsamplingVert = 0
  • YUV 4:4:4 (10-bit): ChromaSubsamplingHorz = 0, ChromaSubsamplingVert = 0

3. ChromaSiting Elements

Chroma sample locations relative to the luma sample grid are defined by:

  • ChromaSitingHorz (0x55B7): Defines horizontal position (0 = Unspecified, 1 = Left collocated, 2 = Half).
  • ChromaSitingVert (0x55B8): Defines vertical position (0 = Unspecified, 1 = Top collocated, 2 = Half).

For standard progressive 10-bit content, 1 (collocated) or 2 (half-grid alignment) is typically used to prevent color fringing during YUV-to-RGB conversion.

4. Range (0x55B9)

The quantization range defines whether the 10-bit integer values span the standard broadcast limits or the full digital spectrum:

  • 0: Unspecified
  • 1: Studio/Limited range (Y typically maps to 64–940, UV to 64–960 in 10-bit)
  • 2: Full range (values span 0–1023)
  • 3: Defined by MatrixCoefficients / TransferCharacteristics

5. MatrixCoefficients (0x55B1)

This parameter defines how the Y, U, and V channels are derived from RGB components. For 10-bit SDR content, BT.709 (1) is common. For 10-bit HDR or Wide Color Gamut (WCG) streams, BT.2020 Non-constant Luminance (9) is standard.

6. ColourPrimaries (0x55BB) and TransferCharacteristics (0x55BA)

While not strictly determining the layout of the YUV pixel array, these parameters complete the pixel format definition by establishing the color gamut and opto-electrical transfer function (EOTF):

  • Primaries: Typically set to 9 for ITU-R BT.2020 in 10-bit HDR/WCG pipelines.
  • Transfer: Set to 16 for SMPTE ST 2084 (PQ) or 18 for ARIB STD-B67 (HLG).

Interaction with Codec Bitstreams

WebM container-level pixel format values should mirror the internal bitstream configuration (such as VP9 Profile 2 or AV1 Main/High Profile sequence headers). If a discrepancy occurs, modern decoders typically prioritize the underlying bitstream parameters, but conforming container metadata ensures correct thumbnail generation, hardware pipeline allocation, and rapid playback initialization across media frameworks.
