Prevent WebM Hotlinking and Save Bandwidth

Hotlinking WebM video files directly from your server can quickly drain your bandwidth, increase hosting costs, and degrade overall website performance. This guide covers actionable server-level configurations to secure your WebM media, including referer-based blocking in Nginx and Apache, CDN-level firewall rules, Cross-Origin Resource Sharing (CORS) restrictions, and token-based signed URLs.

1. Nginx Configuration Using the valid_referers Directive

Nginx handles hotlink prevention natively using the ngx_http_referer_module. This module inspects the Referer header sent by the client's browser and blocks requests originating from unauthorized domains.

Add the following block inside your server configuration in nginx.conf:

location ~* \.(webm)$ {
    valid_referers none blocked server_names *.yourdomain.com yourdomain.com;
    if ($invalid_referer) {
        return 403;
    }
}
  • none: Allows direct visits (e.g., users entering the URL directly or using bookmarks without a referer header).
  • blocked: Permits requests where the referer header was stripped by firewalls or proxies.
  • server_names: Allows your own domain and subdomains.
  • return 403: Denies unauthorized third-party domains immediately without serving the video data.

2. Apache Configuration Using .htaccess and mod_rewrite

Apache uses mod_rewrite to match incoming referer headers against authorized domain patterns.

Add these directives to your root .htaccess file or main virtual host configuration:

RewriteEngine On
RewriteCond %{HTTP_REFERER} !^$
RewriteCond %{HTTP_REFERER} !^https?://(www\.)?yourdomain\.com [NC]
RewriteCond %{HTTP_REFERER} !^https?://(www\.)?trustedpartner\.com [NC]
RewriteRule \.(webm)$ - [F,NC,L]
  • !^$: Allows blank referrers (direct hits).
  • [NC]: Makes the domain matching case-insensitive.
  • [F]: Sends a standard 403 Forbidden response to unauthorized referers.
  • [L]: Stops processing further rewrite rules if this condition matches.

3. Restrict Video Playback via CORS Headers

Browsers fetching WebM assets via JavaScript (fetch or XMLHttpRequest) or cross-origin <video> tags with specific credential requirements honor Cross-Origin Resource Sharing (CORS) rules.

For Nginx:

location ~* \.webm$ {
    add_header Access-Control-Allow-Origin "https://yourdomain.com";
    add_header Access-Control-Allow-Methods "GET, OPTIONS";
}

For Apache:

<FilesMatch "\.webm$">
    Header set Access-Control-Allow-Origin "https://yourdomain.com"
</FilesMatch>

4. Advanced Protection: Signed URLs and Time-Limited Tokens

Referer headers can be spoofed or stripped. For premium or proprietary WebM content, token authentication ensures that each video URL is unique, signed with a cryptographic secret, and set to expire after a defined period.

  • Nginx secure_link Module: Generates an MD5 hash incorporating the client's IP, the file path, and an expiration timestamp. If the hash does not match or the time expires, Nginx refuses to serve the WebM file.
  • CDN-Level Signed URLs: Platforms like Cloudflare, AWS CloudFront, or Fastly support signed cookies or query parameters. Media links generated by your backend application only function for valid sessions, rendering static hotlinks useless on third-party sites.

5. Edge-Level Hotlink Protection (Cloudflare / CDNs)

Blocking requests before they hit your origin server saves the most bandwidth.

  • Cloudflare ScrapeShield: Enable the built-in "Hotlink Protection" toggle under the ScrapeShield settings dashboard to automatically block unauthorized image and media embedding.
  • WAF Custom Rules: Create a Cloudflare WAF rule to block requests where http.request.uri.path contains ".webm" and not http.referer contains "yourdomain.com" and http.referer ne "". This filters traffic entirely at the edge layer.
