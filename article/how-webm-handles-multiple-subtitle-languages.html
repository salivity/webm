How WebM Handles Multiple Subtitle Languages

The WebM container format encapsulates multiple subtitle languages by utilizing the structural framework of Matroska and Extensible Binary Meta Language (EBML) to define independent subtitle tracks and multiplex their data into a single file. By declaring separate track headers with specific language metadata and interleaving timestamped WebVTT payloads alongside audio and video packets, WebM allows media players to identify, select, and render different language streams synchronously.

EBML Track Architecture

WebM inherits its container hierarchy from Matroska, which organizes media streams using EBML master elements. Within the WebM header, the Tracks master element contains individual TrackEntry definitions for every stream in the file.

To include multiple languages, the file author defines a separate TrackEntry for each language. Each subtitle entry contains essential descriptor tags:

  • TrackType: Set to 17 (or 0x11 in hexadecimal), identifying the stream specifically as subtitle data.
  • TrackNumber: A unique integer assigned to the track, used to identify its data packets throughout the file.
  • Language / LanguageIETF: Specifies the language code using ISO 639-2 (e.g., eng, spa, fra) or standard BCP 47 language tags.
  • Name: An optional human-readable label (such as "English SDH" or "Director's Commentary Subtitles") displayed in media player menus.
  • CodecID: Defines the format of the subtitle payload, typically D_WEBVTT/SUBTITLES or D_WEBVTT/CAPTIONS for WebM.

WebVTT Payload Encapsulation

WebM officially supports subtitles formatted as WebVTT (Web Video Text Tracks). In a multi-language WebM file, the text cues, formatting settings, and timing data are segmented into discrete WebVTT cue payloads. These text fragments are stored without the standard WEBVTT file header, as the container headers already define the stream parameters.

Interleaving in Clusters

WebM stores media data chronologically within Cluster elements. Inside each cluster, media payloads are wrapped in Block or SimpleBlock elements.

Every subtitle block includes:

  1. Track Reference: The TrackNumber linking the block back to its specific TrackEntry language definition.
  2. Timestamp: The exact time code relative to the cluster's timecode, ensuring synchronization with the video and audio streams.
  3. Payload: The raw WebVTT cue text for that specific time window.

Because these blocks are interleaved chronologically based on their presentation timecodes, all language tracks coexist alongside audio and video packets within the same stream timeline.

Demuxing and Playback Selection

When a media player or web browser loads a WebM file, the demuxer reads the Tracks header and registers all available subtitle tracks. It presents the language options to the user based on the Language and Name metadata.

Once the user selects a language, the demuxer filters the incoming cluster blocks during playback, decoding only the Block elements matching the chosen TrackNumber while ignoring the data blocks corresponding to unselected languages.
