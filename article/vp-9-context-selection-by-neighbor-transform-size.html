VP9 Context Selection by Neighbor Transform Size

In the VP9 video coding standard, context modeling improves entropy coding efficiency by exploiting spatial correlation between adjacent blocks. Specifically, VP9 determines the probability contexts for critical syntax elements—most notably the transform block size (tx_size) and transform skip flags—by evaluating the transform dimensions of the directly adjacent above and left neighboring blocks. This article breaks down how VP9 queries neighboring transform boundaries, computes context indices, and manages spatial alignment across variable-sized coding blocks.

The Purpose of Transform Size Context Modeling

VP9 supports four discrete transform sizes: 4x4, 8x8, 16x16, and 32x32. Larger transforms are typically chosen in smooth, uniform areas, while smaller transforms are reserved for edges, fine textures, and complex motion. Because neighboring regions in natural video usually share structural characteristics, the transform size chosen for a current block is highly correlated with the transform sizes used in adjacent blocks.

Rather than encoding transform selections with static probability distributions, VP9 employs context-adaptive binary arithmetic coding. By dynamically conditioning probability models on neighbor states, the encoder reduces the bit cost required to signal transform sizes and related residual flags.

Determining the Context Index for Transform Size

When coding the transform size for a given block, the VP9 entropy coder derives a specific context index. The primary neighbors considered are:

  • Above Neighbor (\(A\)): The transform block immediately adjacent to the top edge of the current block.
  • Left Neighbor (\(L\)): The transform block immediately adjacent to the left edge of the current block.

The context index is computed based on whether each neighbor’s transform size meets or exceeds the maximum allowable transform size of the current coding unit.

The standard context derivation logic functions as follows:

  1. Check Neighbor Availability: The decoder checks whether the above and left neighbors exist within the current frame or tile boundary. If a neighbor is unavailable (such as at frame edges or tile borders), its transform size defaults to zero or is treated as not meeting the threshold.
  2. Threshold Evaluation: For an available neighbor, its selected transform size is compared against the maximum transform size supported by the current block’s partition size (\(tx\_max\)):
    • \(\text{above\_condition} = (\text{above\_tx\_size} \ge \text{tx\_max})\)
    • \(\text{left\_condition} = (\text{left\_tx\_size} \ge \text{tx\_max})\)
  3. Context Selection: The active context index is computed as the sum of these conditions: \[\text{Context Index} = \text{above\_condition} + \text{left\_condition}\]

This calculation yields three potential context states (0, 1, or 2):

  • Context 0: Neither neighbor used a transform size greater than or equal to the current block's target size. This indicates a high likelihood of localized detail, skewing probabilities toward smaller transform splits.
  • Context 1: Exactly one neighbor met or exceeded the threshold.
  • Context 2: Both neighbors used transform sizes at or above the threshold, signaling a broad, flat region where a large transform size is statistically preferred.

Spatial Tracking via the 4x4 Processing Grid

Because VP9 allows flexible recursive partitioning (from 64x64 down to 4x4 units), neighboring blocks rarely share a 1:1 size correspondence with the current block.

To maintain consistency, VP9 tracks transform parameters at a standardized sub-block granularity (typically 4x4 or 8x8 units). The engine stores the transform size selected across every internal grid unit within a partitioned block. When a subsequent block queries its left or above boundary:

  • It references the specific 4x4 grid cell directly adjacent to the top-left corner of the current transform unit.
  • If a neighboring block was partitioned into smaller sub-transforms, the query reads the sub-transform directly touching the boundary, preserving local spatial accuracy.

Impact on Residual Skip Flags

Transform size decisions also influence surrounding syntax elements, such as the skip flag (which signals whether a block contains any non-zero transform coefficients). The context for predicting whether a block can be skipped relies on whether neighboring blocks contain transform residuals. The transform size of neighbors dictates the boundary mapping used to fetch these non-zero coefficient flags, ensuring that probabilities match the geometric scale of adjacent residual activity.
