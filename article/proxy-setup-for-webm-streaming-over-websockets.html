Proxy Setup for WebM Streaming Over WebSockets

Streaming WebM video payloads over WebSockets requires continuous, bi-directional, and low-latency transport without intermediate packet buffering or premature connection drops. This article outlines the exact reverse proxy configurations—specifically covering Nginx, HAProxy, and Envoy—required to maintain WebSocket connections, disable I/O buffering, optimize TCP transmission, and adjust timeout parameters to achieve seamless real-time WebM streaming.

Critical Challenges in WebM WebSocket Delivery

WebM streams consist of structured clusters containing VP8/VP9 video frames and Opus audio packets. When delivered over WebSockets, the proxy must treat the payload as an indefinite binary stream. Misconfigurations introduce three primary failure modes:

  1. Proxy Buffering: Standard HTTP proxies accumulate chunks before transmission, which corrupts the initial initialization segment or creates severe playback latency.
  2. Idle Timeouts: Streaming video often encounters periods of variable bitrates; standard proxy read timeouts will sever the socket if packets are temporarily delayed.
  3. TCP Backpressure: Without low-level TCP optimizations, packet queues induce jitter, leading to visual artifacts and decoder starvation on the client.

Nginx Configuration

To proxy WebM data via WebSockets in Nginx, you must explicitly upgrade the connection, disable all proxy buffering, and lengthen socket timeouts.

map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}

server {
    listen 443 ssl http2;
    server_name stream.example.com;

    ssl_certificate /etc/ssl/certs/stream.crt;
    ssl_certificate_key /etc/ssl/private/stream.key;

    location /webm-stream {
        proxy_pass http://backend_stream_servers;
        
        # Enable HTTP/1.1 and protocol upgrade
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        proxy_set_header Host $host;

        # Disable buffering for real-time delivery
        proxy_buffering off;
        proxy_request_buffering off;

        # Extend timeouts for long-running media streams
        proxy_read_timeout 86400s;
        proxy_send_timeout 86400s;
        proxy_connect_timeout 60s;

        # Kernel TCP adjustments for streaming
        tcp_nodelay on;
    }
}

Key Directives Explained:

  • proxy_buffering off;: Immediately delivers incoming WebM chunks to the client without waiting for memory buffers to fill.
  • tcp_nodelay on;: Disables Nagle's algorithm on proxied connections, ensuring WebM keyframes and clusters are transmitted immediately without artificial grouping delays.
  • proxy_read_timeout 86400s;: Prevents Nginx from dropping active streams that have low data transmission during blank scenes or pauses.

HAProxy Configuration

HAProxy natively handles WebSockets in HTTP mode when configured to transition into a direct bidirectional tunnel.

frontend https_in
    bind *:443 ssl crt /etc/ssl/certs/stream.pem
    mode http
    
    acl is_websocket hdr(Upgrade) -i WebSocket
    use_backend webm_ws_backend if is_websocket

backend webm_ws_backend
    mode http
    option forwardfor
    
    # WebSocket Tunnel Timeouts
    timeout tunnel 3600s
    timeout server 3600s
    timeout client 3600s
    timeout connect 5s
    
    # Disable response buffering
    no option http-buffer-request
    
    server stream_node_1 127.0.0.1:8080 check

Key Directives Explained:

  • timeout tunnel 3600s;: Overrides timeout client and timeout server once the bidirectional WebSocket tunnel is negotiated, keeping the WebM feed open.
  • no option http-buffer-request;: Ensures low latency by preventing HAProxy from waiting for complete request bodies.

Envoy Configuration

Envoy handles WebSocket traffic using explicit route-level upgrade configurations and stream buffer limit modifications.

static_resources:
  listeners:
  - name: stream_listener
    address:
      socket_address: { address: 0.0.0.0, port_value: 443 }
    filter_chains:
    - filters:
      - name: envoy.filters.network.http_connection_manager
        typed_config:
          "@type": type.googleapis.com/envoy.extensions.filters.network.http_connection_manager.v3.HttpConnectionManager
          stat_prefix: ingress_ws
          route_config:
            name: local_route
            virtual_hosts:
            - name: stream_service
              domains: ["*"]
              routes:
              - match: { prefix: "/webm-stream" }
                route:
                  cluster: stream_backend
                  timeout: 0s
                  idle_timeout: 0s
                  upgrade_configs:
                  - upgrade_type: "websocket"
          http_filters:
          - name: envoy.filters.http.router
            typed_config:
              "@type": type.googleapis.com/envoy.extensions.filters.http.router.v3.Router
  clusters:
  - name: stream_backend
    connect_timeout: 0.25s
    type: STATIC
    lb_policy: ROUND_ROBIN
    load_assignment:
      cluster_name: stream_backend
      endpoints:
      - lb_endpoints:
        - endpoint:
            address:
              socket_address: { address: 127.0.0.1, port_value: 8080 }

Key Directives Explained:

  • timeout: 0s and idle_timeout: 0s: Disables route timeouts entirely, treating the connection as an infinite live media transmission.
  • upgrade_configs: Explicitly permits the WebSocket protocol exchange while preserving raw binary throughput without payload inspection.
