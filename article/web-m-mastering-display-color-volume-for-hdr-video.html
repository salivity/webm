WebM Mastering Display Color Volume for HDR Video

This article explains how the WebM container format stores and signals mastering display color volume metadata for High Dynamic Range (HDR) video. Inheriting specifications from the Matroska (MKV) container, WebM incorporates dedicated Extensible Binary Meta Language (EBML) elements that describe the color gamut, white point, and luminance capabilities of the display used to master the content. This metadata enables downstream renderers and consumer displays to perform accurate tone mapping.

Structural Placement in the WebM Container

WebM organizes metadata hierarchically using EBML. Mastering display parameters are embedded at the track level within the video settings. The hierarchical structure is defined as follows:

  • Segment
    • Tracks
      • TrackEntry
        • Video
          • Colour
            • MasteringMetadata

The Colour element defines the baseline color properties of the video track, while the nested MasteringMetadata element specifically encapsulates the physical characteristics of the mastering display according to the SMPTE ST 2086 standard.

Mastering Display Metadata Elements

The MasteringMetadata container includes distinct float elements representing the mastering display’s chromaticity coordinates (CIE 1931 color space) and luminance boundaries:

1. Color Primaries and White Point

These values define the exact color boundaries and reference white of the mastering monitor:

  • PrimaryRChromaticityX and PrimaryRChromaticityY: Red primary chromaticity coordinates (values from 0.0 to 1.0).
  • PrimaryGChromaticityX and PrimaryGChromaticityY: Green primary chromaticity coordinates (values from 0.0 to 1.0).
  • PrimaryBChromaticityX and PrimaryBChromaticityY: Blue primary chromaticity coordinates (values from 0.0 to 1.0).
  • WhitePointChromaticityX and WhitePointChromaticityY: Reference white point coordinates (typically D65 for standard HDR workflows).

2. Display Luminance Boundaries

These values specify the dynamic range capability of the mastering monitor:

  • LuminanceMax: The maximum luminance of the mastering display, expressed in candelas per square meter (\(\text{cd/m}^2\) or nits), stored as a floating-point number (e.g., 1000.0 or 4000.0).
  • LuminanceMin: The minimum luminance (black level) of the mastering display, expressed in \(\text{cd/m}^2\) (e.g., 0.005 or 0.0001).

Complementary HDR Elements in WebM

For full HDR signal interpretation, WebM pairs the MasteringMetadata block with content light level metadata (CTA-861.3) and foundational color characteristics stored directly under the parent Colour element:

  • MaxCLL (Maximum Content Light Level): An unsigned integer indicating the maximum pixel brightness in the entire video stream (\(\text{cd/m}^2\)).
  • MaxFALL (Maximum Frame-Average Light Level): An unsigned integer indicating the highest average picture level among all individual frames (\(\text{cd/m}^2\)).
  • TransferCharacteristics: Identifies the Electro-Optical Transfer Function (EOTF), such as value 16 for SMPTE ST 2084 (PQ / Perceptual Quantizer) or value 18 for Hybrid Log-Gamma (HLG).
  • Primaries: Identifies the color gamut container (e.g., value 9 for ITU-R BT.2020).
  • MatrixCoefficients: Defines the color space matrix used to derive luma and chroma from RGB (e.g., ITU-R BT.2020 non-constant luminance).

Playback and Tone Mapping Workflow

When a WebM HDR video (commonly encoded using VP9 Profile 2 or AV1) is played, the media demuxer reads the MasteringMetadata and light level elements prior to decoding video frames. The rendering pipeline passes this static metadata to the operating system or display controller via APIs such as DirectX, Vulkan, or HDMI dynamic communication channels. The target display compares the mastering monitor's limits against its own hardware capabilities, calculating appropriate tone-mapping curves to preserve highlight details and shadow gradients without clipping.
