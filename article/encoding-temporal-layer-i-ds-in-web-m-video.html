Encoding Temporal Layer IDs in WebM Video

The WebM container format does not feature a dedicated container-level element to encode temporal layer IDs (TIDs) directly in video packets. Instead, WebM delegates temporal scalability signaling to the underlying video bitstream payloads—such as VP8, VP9, and AV1—while providing container-level cues through the Discardable flag in standard SimpleBlock structures.

Container-Level Signaling via SimpleBlock

WebM stores compressed video frames inside Matroska Cluster elements using SimpleBlock structures. A standard SimpleBlock consists of:

  • A variable-length integer indicating the Track Number.
  • A 2-byte signed relative timestamp.
  • An 8-bit flags byte.
  • The raw codec frame payload.

The 8-bit flags byte includes a Discardable flag located at Bit 0. While this flag does not convey an explicit temporal layer number (such as Layer 0, 1, or 2), muxers set this bit to 1 for frames that are not referenced by any other frames in the dependency chain. In standard temporal scalability models, frames residing in the highest temporal layer are non-reference frames. Demuxers and playback engines use this flag to drop highest-layer packets without decoding the payload when system resources or bandwidth are constrained.

Codec-Specific Bitstream Encoding

Because WebM itself omits a discrete temporal ID header, temporal layer indexing is resolved directly within the video codec bitstream encapsulated inside the SimpleBlock:

1. AV1 (AOMedia Video 1)

AV1 provides native, explicit temporal layer signaling within its bitstream syntax. An AV1 payload consists of Open Bitstream Units (OBUs). When temporal scalability is enabled:

  • The obu_extension_flag in the general OBU header is set to 1.
  • This exposes the 1-byte obu_extension_header.
  • The first 3 bits of the obu_extension_header represent the temporal_id.

The temporal_id explicitly assigns the packet to a temporal layer ranging from 0 to 7.

2. VP9

In VP9, temporal scalability is managed within the uncompressed frame header:

  • Unlike the WebRTC RTP payload format (which uses an explicit 3-bit TID in the VP9 descriptor), WebM strips the transport-level RTP headers upon file muxing.
  • WebM decoders deduce temporal layers by parsing the frame header to evaluate reference buffer indices and refresh masks (last_frame, golden_frame, and altref_frame).
  • When scalability structure (SS) data is included in keyframes, the bitstream outlines the entire temporal layering pattern, allowing the demuxer to track the layer ID of subsequent frames based on frame count and reference patterns.

3. VP8

VP8 does not feature an explicit temporal layer syntax inside its raw bitstream. Temporal scalability in VP8 is implemented through strict reference frame update patterns (targeting the Golden Frame and Alternate Reference Frame buffers). Applications reading WebM must parse the uncompressed VP8 frame tag to evaluate which reference buffers are updated, thereby determining the frame's temporal layer status mathematically.

Streaming vs. File Encapsulation

In real-time network transport, protocols like WebRTC explicitly define temporal layer IDs in the RTP payload specification. When these streams are muxed into a standard WebM file or byte stream, the RTP payload headers are discarded. To identify temporal layers inside a WebM file, a demuxer must parse the codec-level frame headers directly, relying only on the WebM Discardable flag for container-level layer pruning.
