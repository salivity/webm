WebM Initialization Segment Structure for MSE

Serving WebM video over Media Source Extensions (MSE) requires a distinct initialization segment that provides the media player with critical decoding parameters and track configurations before media data is processed. This article outlines the exact EBML elements and structural layout necessary to construct a valid WebM initialization segment compliant with the W3C WebM Byte Stream Format.

Core Architecture of the Initialization Segment

An initialization segment for WebM must contain EBML and Matroska metadata describing the stream, but it must not contain any encoded media frames (Cluster elements). When fed into an MSE SourceBuffer, this payload configures the demuxer and decoders.

The segment must contain three main structural components in the following order:

  1. EBML Header (EBML)
  2. Segment Header (Segment)
  3. Segment Information (Info) and Track Definitions (Tracks)

1. EBML Header

The file must begin with a standard EBML Header element that identifies the document type and version:

  • EBMLVersion: Typically set to 1.
  • EBMLReadVersion: Typically set to 1.
  • EBMLMaxIDLength: Must be 4.
  • EBMLMaxSizeLength: Usually 8.
  • DocType: Must be set to the string "webm".
  • DocTypeVersion: Set to 2 or higher (commonly 4 for modern codecs like VP9 or AV1).
  • DocTypeReadVersion: Set to 2.

2. Segment Container

Following the EBML Header is the root Segment element.

  • In an MSE environment, the total size of the segment cannot be predetermined because media chunks are appended dynamically.
  • The Segment element size is typically set to an unknown size (all bits set to 1 in the EBML size field, e.g., 0x01FFFFFFFFFFFFFF for an 8-byte size).
  • The initialization segment contains the beginning of this Segment element and encapsulates the Info and Tracks elements.

3. Info Element (Segment Information)

The Info element provides global stream information necessary for timestamp calculations:

  • TimestampScale (formerly TimecodeScale): Defines the timestamp multiplier in nanoseconds (default is 1,000,000, which makes timestamps millisecond-based).
  • MuxingApp & WritingApp: Text strings identifying the multiplexer and software used.
  • Duration: Optional in the initialization segment when streaming live content, but can be included if the stream length is known.

4. Tracks Element

The Tracks element defines all elementary streams (video and audio) present in the container. It contains one or more TrackEntry elements.

Each TrackEntry must contain:

  • TrackNumber: A unique positive integer identifying the track, which must match the track references in subsequent media segment Cluster blocks.
  • TrackUID: A unique ID for the track.
  • TrackType: Set to 1 for Video or 2 for Audio.
  • CodecID: Identifies the stream codec (e.g., V_VP8, V_VP9, V_AV1, A_OPUS, A_VORBIS).
  • CodecPrivate: Required for certain codecs (like Vorbis or specific AV1 configurations) containing codec setup headers.

Video Track Specifications

If TrackType is 1 (Video), the Video sub-element must include:

  • PixelWidth: The display/encoded width in pixels.
  • PixelHeight: The display/encoded height in pixels.
  • DisplayWidth & DisplayHeight: Optional, for non-square pixel aspect ratios.
  • Colour: Optional, defining color space, transfer characteristics, and matrix coefficients (critical for HDR/VP9/AV1).

Audio Track Specifications

If TrackType is 2 (Audio), the Audio sub-element must include:

  • SamplingFrequency: Sample rate in Hz (e.g., 48000.0).
  • Channels: The number of audio channels (e.g., 2 for stereo).
  • BitDepth: Optional bit depth configuration.

Separation from Media Segments

To function correctly in MSE:

  • The initialization segment ends immediately after the closing tag of the Tracks element.
  • No Cluster, SimpleBlock, or BlockGroup elements may appear in the initialization segment.
  • All subsequent data appended to the SourceBuffer must consist strictly of standalone Cluster elements (Media Segments), referencing the track IDs established in this initialization structure.
