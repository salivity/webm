Convert to WebM with Constant Frame Rate in FFmpeg

Converting video to the WebM format often results in a variable frame rate (VFR) by default, which can introduce audio-video desynchronization and compatibility issues with video editors or streaming pipelines. Enforcing a strict constant frame rate (CFR) requires configuring FFmpeg to normalize input timestamps and fix output pacing. This guide details the essential FFmpeg flags and filter parameters needed to guarantee a reliable CFR output when encoding to WebM.

Essential FFmpeg Parameters for CFR

To force a constant frame rate in WebM (using VP8 or VP9 codecs), combine frame rate definition, video filtering, and synchronization flags.

1. -fps_mode cfr (or -vsync cfr)

This parameter controls how FFmpeg handles video synchronization. Setting it to cfr instructs the encoder to duplicate frames if the source drops below the target frame rate or drop frames if the source exceeds it.

Note: In FFmpeg 5.1 and newer, -fps_mode cfr replaces the legacy -vsync cfr (or -vsync 1) syntax.

2. -vf "fps=VALUE"

Applying the fps video filter is the most robust method for generating CFR content. Unlike simple container-level flags, this filter resamples timestamps at the decoding stage, ensuring frames arrive at precise, uniform intervals before reaching the encoder.

3. -r VALUE

Setting -r defines the output container's nominal frame rate. When used alongside -vf fps=VALUE, it guarantees that both the stream timestamps and the container headers match the desired rate.

Complete Command Examples

Using VP9 and Opus (Recommended)

This command converts an input video to a CFR WebM file at 30 frames per second using the VP9 video codec and Opus audio codec:

ffmpeg -i input.mp4 -c:v libvpx-vp9 -b:v 2M -vf "fps=30" -r 30 -fps_mode cfr -c:a libopus output.webm

Legacy FFmpeg Syntax (Versions prior to 5.1)

If using an older version of FFmpeg, use -vsync 1 or -vsync cfr:

ffmpeg -i input.mp4 -c:v libvpx-vp9 -b:v 2M -vf "fps=30" -r 30 -vsync cfr -c:a libopus output.webm

Verification

To verify that the resulting WebM file has a constant frame rate, inspect the packet presentation timestamps (PTS) using ffprobe:

ffprobe -v error -select_streams v:0 -show_entries frame=pkt_pts_time,pkt_duration_time -of csv=p=0 output.webm

A consistent duration value across all frames confirms that the output adheres strictly to CFR.
