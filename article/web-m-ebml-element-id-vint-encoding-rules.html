WebM EBML Element ID VINT Encoding Rules

This article provides an overview of the variable-length integer (VINT) encoding rules that govern Element IDs within WebM. As a subset of the Extensible Binary Meta Language (EBML), WebM utilizes specialized VINT structures to identify container elements, metadata headers, and media clusters. The following sections detail the exact bit-level constraints, length limits, and uniqueness requirements applied specifically to Element IDs in WebM implementations.

Preservation of the Length Descriptor

In standard EBML VINT encoding (such as for element data sizes), the length descriptor—consisting of zero or more leading zero bits followed by a terminating 1 bit—is stripped out to read the integer value.

For Element IDs, this rule does not apply. The length descriptor bit pattern is preserved as an integral part of the Element ID itself. When parsers identify an element, the leading 0 bits and the marker 1 bit are included in the hexadecimal or numerical representation of the ID (e.g., the EBML Header ID is represented as 0x1A45DFA3, retaining the 0001 prefix).

Octet Length Limits (1 to 4 Octets)

While EBML allows variable-length integers up to 8 octets in length, WebM strictly limits Element IDs to a range of 1 to 4 octets:

  • Class A (1 Octet): Starts with bit pattern 1xxxxxxx
  • Class B (2 Octets): Starts with bit pattern 01xxxxxx
  • Class C (3 Octets): Starts with bit pattern 001xxxxx
  • Class D (4 Octets): Starts with bit pattern 0001xxxx

Any Element ID encoded using 5 or more octets is invalid in WebM and must be rejected by compliant demuxers.

Bit Patterns and Usable Ranges

The position of the first set bit (1) dictates the total byte length of the ID. The remaining bits serve as the payload:

  • 1-Byte IDs: Bitmask 0x80, usable payload of 7 bits. Raw range: 0x81 to 0xFE.
  • 2-Byte IDs: Bitmask 0x4000, usable payload of 14 bits. Raw range: 0x407F to 0x7FFE.
  • 3-Byte IDs: Bitmask 0x200000, usable payload of 21 bits. Raw range: 0x203FFF to 0x3FFFFE.
  • 4-Byte IDs: Bitmask 0x10000000, usable payload of 28 bits. Raw range: 0x101FFFFF to 0x1FFFFFFE.

Forbidden and Reserved Values

EBML VINT encoding forbids specific values from serving as valid Element IDs:

  1. All Data Bits Set to One: An Element ID whose data bits (excluding the length descriptor) are all set to 1 is reserved. Consequently, 0xFF, 0x7FFF, 0x3FFFFF, and 0x1FFFFFFF are invalid Element IDs.
  2. All Zero Marker: An octet sequence beginning with eight 0 bits (0x00) cannot define a valid length descriptor and is strictly prohibited.
  3. Empty Data Payload: Values containing only the VINT marker bit with all trailing data bits set to zero are reserved in certain classes to prevent collisions with legacy systems or empty masks.

Fixed-Length Representation (No Redundant Encoding)

Element IDs in WebM do not permit canonical normalization through zero-padding. An Element ID assigned a shorter length cannot be padded with leading zeros into a longer VINT format. For example, a 1-octet Element ID such as 0x81 cannot be encoded as a 2-octet sequence 0x4081. Each defined WebM element has a fixed, immutable octet size defined directly by its specification.
