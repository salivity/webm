EBML Timestamp Data Sizes in WebM Explained

WebM relies on Extensible Binary Meta Language (EBML) to organize video and audio streams, utilizing a hierarchical timestamping system to achieve millisecond-level precision. This article details the specific data structures and byte sizes EBML uses to encode these timestamps across the segment, cluster, and block levels.

The Foundation: TimestampScale

WebM defines time precision using the TimestampScale element (EBML ID 0x2AD7B1) located in the Segment Information header.

  • Data Type: EBML Unsigned Integer (uint).
  • Data Size: Variable length, typically 3 to 4 bytes (24 to 32 bits).
  • Default Value: 1,000,000 nanoseconds (exactly 1 millisecond).

Because the default scale sets each timestamp unit to one millisecond, all subsequent timestamp values in the container represent integer counts of milliseconds. Storing the standard 1,000,000 value requires a 3-byte payload (0x0F4240), prefixed by an EBML variable-size integer (VINT) length descriptor.

Cluster Timestamps

A WebM file is divided into individual Cluster elements, each containing a base timestamp element (Timestamp, EBML ID 0xE7).

  • Data Type: EBML Unsigned Integer (uint).
  • Data Size: Variable length, typically 1 to 4 bytes (8 to 32 bits).
  • Function: Serves as the absolute base time for all media blocks inside that specific cluster.

EBML allows variable-length encoding for integers. For example:

  • A cluster occurring at second 5 (5,000 ms) uses 2 bytes (0x1388).
  • A cluster occurring at 1 hour (3,600,000 ms) uses 3 bytes (0x36EE80).
  • Longer media files up to ~49 days use 4 bytes.

Block-Level Relative Timestamps

Inside a Cluster, video and audio frames are packed into SimpleBlock or Block structures. Rather than storing full absolute timestamps, each block stores an offset relative to the cluster's base timestamp.

  • Data Type: Signed 16-bit Integer (int16).
  • Data Size: Exactly 2 bytes (16 bits), fixed width.
  • Range: -32,768 to +32,767 units (milliseconds).

Unlike standard EBML elements, this 2-byte field is part of the raw block header and does not use variable-length encoding. It directly follows the Track Number (encoded as an EBML VINT). Because this field is a 16-bit signed integer, a WebM cluster cannot span more than 32,767 milliseconds (approximately 32.7 seconds) of forward media time relative to the cluster timestamp.

Summary of Byte Sizes

  • TimestampScale: 3 to 4 bytes (variable unsigned integer)
  • Cluster Timestamp: 1 to 4 bytes (variable unsigned integer, depending on file duration)
  • Block Relative Timestamp: 2 bytes (fixed signed 16-bit integer)
