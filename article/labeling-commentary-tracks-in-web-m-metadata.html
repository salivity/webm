Labeling Commentary Tracks in WebM Metadata

WebM relies on a subset of the Matroska (MKV) container specification to manage audio and video streams, identifying secondary language commentary tracks through specific metadata elements inside the track header. By defining elements such as the track type, descriptive naming strings, language codes, and specific track flags within an Extensible Binary Meta Language (EBML) structure, media players can correctly distinguish, label, and offer commentary audio alongside the primary mix.

The TrackEntry Element

In a WebM container, every stream is defined within a TrackEntry master element located inside the Tracks header block. Commentary tracks are designated as audio by setting the TrackType element value to 2 (the standard Matroska identifier for audio).

Descriptive Naming

To make the track recognizable in user interfaces (such as audio selection menus in web browsers and media players), the Name element is utilized:

  • Element ID: 0x536E (Name)
  • Value: A UTF-8 string explicitly describing the track's context (e.g., "Director's Commentary", "Cast Commentary (Spanish)").

This label provides the immediate human-readable title shown to viewers selecting an alternative stream.

Language Tagging

WebM defines the language of an audio track using standard language descriptors to allow automated selection based on player locale settings:

  • Language (0x22B59C): The legacy Matroska tag containing an ISO 639-2 three-letter language code (such as eng for English, spa for Spanish, or fra for French).
  • LanguageBCP47 (0x22B59D): The modern, preferred element adhering to BCP 47 syntax (such as en, es-419, or fr-CA), allowing more granular regional identification for secondary language tracks.

Track Flags and Roles

To prevent secondary commentary from clashing with the primary feature audio upon playback initiation, specific binary flags must be configured within the TrackEntry:

  • FlagDefault (0x88): Must be set to 0 (False). This ensures players do not automatically select the commentary track over the main audio stream when loading the media file.
  • FlagForced (0x55AA): Set to 0 (False), designating that the track is not required for fundamental comprehension.
  • FlagCommentary (0x55EE): Introduced in newer Matroska specifications and supported by modern WebM parsers, this boolean flag formally designates the audio stream as supplemental commentary.

Muxing with FFmpeg

When authoring WebM files, command-line tools like FFmpeg translate these metadata parameters into the corresponding Matroska EBML elements via track metadata and disposition tags:

-metadata:s:a:1 title="Director's Commentary" -metadata:s:a:1 language=spa -disposition:s:a:1 commentary -disposition:s:a:1 default=0

This configuration maps the secondary audio stream (a:1) to a Spanish language tag, applies the user-facing title, unsets default playback, and writes the proper commentary disposition directly to the WebM metadata block.
