WebM Alpha Channel Video Container Elements

This article provides an overview of how the WebM container encapsulates transparency data alongside primary video streams. It details the specific Matroska-derived elements responsible for defining alpha support at the track level and linking alpha channel frames directly to the primary video frames within the container structure.

In the WebM format (which is a subset of the Matroska container specification), the element that links the primary video track to its alpha channel data at the frame level is <BlockAdditions>.

Frame-Level Linkage: <BlockAdditions>

Within a WebM file containing transparency (often utilizing VP8 or VP9 with alpha), the alpha stream is not stored as an entirely independent track with its own distinct track UID. Instead, the alpha data is linked directly to the main video frames on a per-frame basis inside a <BlockGroup> container.

The structure operates through the following hierarchy:

  • <BlockGroup>: Wraps the primary video frame along with any synchronized supplementary data.
  • <Block>: Contains the primary color data (YUV bitstream) for the frame.
  • <BlockAdditions>: A container element within the <BlockGroup> designed to store additional data attached to the primary block.
    • <BlockMore>: An entry inside <BlockAdditions>.
    • <BlockAddID>: An integer set to 1 to explicitly designate that the accompanying payload is alpha channel transparency data.
    • <BlockAdditional>: The actual binary payload of the alpha channel frame (an auxiliary VP8/VP9 frame containing the monochrome opacity data).

Track-Level Declaration: <AlphaMode>

To alert media decoders that a video track contains linked alpha data via <BlockAdditions>, WebM relies on the <AlphaMode> element at the track configuration level.

  • Path: Segment -> Tracks -> TrackEntry -> Video -> AlphaMode
  • Function: Setting <AlphaMode> to 1 indicates that the video stream includes transparency data linked to the primary frames. When set to 0 (or omitted), the track is treated as purely opaque, and decoders ignore any auxiliary block additions.
