Using canPlayType for WebM Codec Verification

The HTML5 HTMLMediaElement.canPlayType() method is an essential JavaScript API used to determine whether a browser can play a specific media format before initiating a download or playback. When working with the WebM container format, passing precise codec parameters allows the browser to evaluate its decoding capabilities for modern video formats like VP8, VP9, and AV1, alongside audio formats like Opus and Vorbis. This article explains how the canPlayType() method operates, how to construct accurate WebM MIME type strings, and how to interpret the browser's responses.

How the canPlayType() Method Works

The canPlayType() method belongs to the HTMLMediaElement interface and can be invoked on standard <video> or <audio> DOM elements. It accepts a single string argument representing the MIME type and optional codec definitions, and synchronously returns one of three string values reflecting the browser's level of support:

  • "" (Empty string): The browser cannot play the specified media type.
  • "maybe": The browser cannot determine if it can play the format without downloading and attempting to decode the media data (often returned when a container type is provided without specific codec parameters).
  • "probably": The browser recognizes the container and explicitly supports the declared codec configuration.

Structuring WebM Codec Strings

A media query consists of a container MIME type followed by a codecs parameter specifying the specific video and audio compression formats. Because the WebM container can encapsulate different video codecs (VP8, VP9, AV1) and audio codecs (Vorbis, Opus), omitting the codecs parameter generally yields an ambiguous "maybe".

To get a definitive "probably" response, pass the detailed codec string inside the query parameter:

  • VP8 Video with Vorbis Audio: video/webm; codecs="vp8, vorbis"
  • VP9 Video (Profile 0) with Opus Audio: video/webm; codecs="vp9, opus"
  • VP9 with Specific Encoding Profiles: video/webm; codecs="vp09.00.10.08" (indicates VP9, Profile 0, Level 1.0, 8-bit depth)
  • AV1 Video with Opus Audio: video/webm; codecs="av01.0.05M.08, opus"

Implementation Example

To test for compatibility programmatically, create an in-memory video element and evaluate the return value:

function checkWebMSupport(codecString) {
  const video = document.createElement('video');
  const mimeType = `video/webm; codecs="${codecString}"`;
  const support = video.canPlayType(mimeType);

  return support === 'probably' || support === 'maybe';
}

// Verification checks
const supportsVP9 = checkWebMSupport('vp9, opus');
const supportsAV1 = checkWebMSupport('av01.0.05M.08, opus');

if (supportsAV1) {
  // Serve high-efficiency AV1 WebM stream
} else if (supportsVP9) {
  // Fall back to VP9 WebM stream
} else {
  // Fall back to alternative formats like MP4/H.264
}

Why Exact Codec Strings Matter

Under the hood, canPlayType() checks the browser's internal demuxer and the underlying hardware or software decoders. A browser might support the WebM container demuxer natively while lacking the specific decoding pipeline for newer codecs like AV1 or specific high-bit-depth profiles of VP9 (such as 10-bit or 12-bit HDR profiles). Supplying the full FourCC or standardized codec string guarantees that the browser verifies hardware and software decoder pipelines accurately, preventing broken playback states for end users.
