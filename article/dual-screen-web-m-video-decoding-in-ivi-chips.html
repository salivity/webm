Dual-Screen WebM Video Decoding in IVI Chips

Modern in-vehicle infotainment (IVI) processors handle dual-screen hardware decoding of WebM video by leveraging multi-stream Video Processing Units (VPUs), high-bandwidth memory architectures, and dedicated Display Processing Units (DPUs). Through hardware-level resource partitioning and zero-copy rendering pipelines, the processor decodes two distinct WebM streams—typically encoded in VP9 or AV1—and routes them to separate driver and passenger displays simultaneously without placing significant computational load on the CPU.

Multi-Stream Hardware Decoders (VPU)

Automotive System-on-Chips (SoCs) include dedicated hardware accelerators engineered specifically for video decoding. WebM containers store video encoded in VP8, VP9, or AV1 formats. To decode two streams at once, the IVI processor's VPU uses time-division multiplexing across a single high-throughput decoding engine or assigns tasks to distinct, independent hardware decoding cores. The hardware executes entropy decoding, inverse discrete cosine transform (IDCT), and motion compensation directly in silicon, allowing concurrent 1080p or 4K playback at 60 frames per second with minimal CPU intervention.

Memory Management and Zero-Copy Pipelines

Streaming two high-resolution videos simultaneously creates intense memory demands. IVI architectures address this using high-speed unified memory (such as LPDDR4X or LPDDR5) managed by Direct Memory Access (DMA) controllers. Once the VPU decodes a frame, it writes the raw YUV data directly into a shared hardware buffer via frameworks like Linux DMA-BUF or Android Hardware Buffer. The display engine accesses these frames directly from memory, eliminating intermediate CPU memory copies, reducing memory latency, and preventing frame drops on both screens.

Independent Display Processing Units (DPUs)

After decoding, the raw pixel data must be formatted and output to two distinct screens, such as the digital instrument cluster and a front-passenger entertainment display. The SoC’s DPU features multiple independent hardware display pipelines. Each pipeline is responsible for color-space conversion (YUV to RGB), scaling, rotation, and hardware composition. Pipeline A routes one decoded stream to the primary display interface (such as eDP or MIPI-DSI), while Pipeline B simultaneously processes and sends the second stream to an independent display controller (such as an external FPD-Link or GMSL serializer).

Virtualization and OS-Level Resource Partitioning

Modern vehicle cockpits often isolate different screens into secure domains using Type-1 automotive hypervisors. For instance, the driver's display may run a safety-certified real-time operating system (RTOS), while the passenger display runs Android Automotive. To handle dual WebM decoding across virtual machines, the IVI chip utilizes hardware virtualization extensions (SR-IOV) or paravirtualized GPU/VPU drivers. The hypervisor orchestrates hardware decode contexts so that each operating system interacts with the underlying silicon as if it possesses a dedicated decoder, ensuring that video processing in the infotainment domain cannot disrupt safety-critical display functions.
