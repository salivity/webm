VP9 Temporal Motion Vector Prediction Equations

In WebM VP9 video streams, temporal motion vector (TMV) prediction allows inter-coded blocks to leverage motion information from previously decoded frames. Unlike codecs that scale motion vectors based on explicit timestamp intervals or Picture Order Counts (POC), VP9 evaluates collocated blocks on a fixed coordinate grid and applies reference-matching logic and boundary clamping to derive candidate vectors. This article details the mathematical formulations and algorithms used to calculate temporal motion vector candidates in VP9.

1. Collocated Block Coordinate Mapping

Temporal motion vector candidates in VP9 are derived from the motion vectors of the previously decoded frame stored in the reference buffer when the frame header flag use_prev_frame_mvs is enabled. VP9 tracks motion vectors at an 8×8 pixel granularity.

Given a current block located at pixel coordinates \((x, y)\), the collocated block index \((bx, by)\) inside the temporal buffer is determined by:

\[bx = \lfloor x / 8 \rfloor = x \gg 3\] \[by = \lfloor y / 8 \rfloor = y \gg 3\]

Where \(\gg\) represents an arithmetic bitwise right-shift operation.

2. Candidate Selection and Reference Frame Matching

Because VP9 streams do not include Picture Order Count (POC) syntax in the uncompressed bitstream header, motion vectors cannot be linearly scaled by temporal distance (\(dt\)). Instead, VP9 checks if the reference frame used by the collocated block matches the target reference frame of the current block.

Let \(Ref_{target} \in \{\text{LAST\_FRAME}, \text{GOLDEN\_FRAME}, \text{ALTREF\_FRAME}\}\) be the designated reference frame for the current block, and let \(Ref_{prev}(bx, by)\) be the reference frame assigned to the collocated block in the prior frame.

The temporal candidate motion vector \(\mathbf{MV}_{temporal}\) is assigned according to the following condition:

\[\mathbf{MV}_{temporal} = \begin{cases} \mathbf{MV}_{prev}(bx, by), & \text{if } Ref_{prev}(bx, by) = Ref_{target} \\ \mathbf{0}, & \text{otherwise} \end{cases}\]

If the collocated reference does not match \(Ref_{target}\), the candidate is discarded or treated as unavailable, rather than projected across time.

3. Sub-Pixel Precision and Scaling

Motion vectors in VP9 are represented in 1/8-pel (eighth-pixel) units. When a valid temporal motion vector candidate is imported from the buffer, it already exists in 1/8-pel resolution:

\[\mathbf{MV} = (MV_x, MV_y)\]

If spatial resolution changes occur across reference frames (VP9 Dynamic Resolution Switching), the temporal motion vector components are scaled based on the horizontal and vertical scaling factors between the reference frame and the current frame:

\[MV_{x, scaled} = \text{round}\left( \frac{MV_x \cdot W_{current}}{W_{reference}} \right)\] \[MV_{y, scaled} = \text{round}\left( \frac{MV_y \cdot H_{current}}{H_{reference}} \right)\]

Where:

  • \(W_{current}\) and \(H_{current}\) represent the width and height of the current frame.
  • \(W_{reference}\) and \(H_{reference}\) represent the dimensions of the referenced frame.

4. Boundary Clamping Equations

Before the temporal vector can be finalized into the candidate list (ref_mv_stack), it must be constrained to prevent memory access violations outside the decoded frame borders.

The clamped motion vector \(\mathbf{MV}_{clamped} = (MV'_x, MV'_y)\) is computed using the \(\text{clip3}\) operator:

\[MV'_x = \text{clip3}(MV_{x, min}, MV_{x, max}, MV_x)\] \[MV'_y = \text{clip3}(MV_{y, min}, MV_{y, max}, MV_y)\]

Where:

\[\text{clip3}(low, high, v) = \max(low, \min(v, high))\]

The dynamic range boundaries for an \(N \times M\) block at pixel offset \((x, y)\) are defined by:

\[MV_{x, min} = -(x + \text{BORDER\_OFFSET}) \times 8\] \[MV_{x, max} = (W_{frame} - x - N + \text{BORDER\_OFFSET}) \times 8\] \[MV_{y, min} = -(y + \text{BORDER\_OFFSET}) \times 8\] \[MV_{y, max} = (H_{frame} - y - M + \text{BORDER\_OFFSET}) \times 8\]

Where \(\text{BORDER\_OFFSET}\) corresponds to the sub-pixel interpolation filter tap margins (typically 16 to 32 pixels in VP9 implementations), ensuring sub-pel interpolation filters have valid surrounding data during motion compensation.
