Opus CodecDelay Constraints in WebM

This article outlines the technical and structural requirements governing the placement of the CodecDelay element for Opus audio streams in the WebM container. In WebM, proper positioning, cardinality, and data formatting of CodecDelay within the Matroska/EBML hierarchy are critical for ensuring accurate audio decoding, correct priming sample discarding, and seamless audio-video synchronization.

EBML Hierarchy and Placement

The CodecDelay element (EBML ID 0x56AA) is strictly constrained to the track header definition within the WebM container schema. It must reside inside the TrackEntry master element (0xAE), which in turn is located within the top-level Tracks element (0x1654AE6B) under the root Segment (0x18538067).

Placing CodecDelay anywhere outside of an individual TrackEntry—such as directly within Cluster, Segment, or Audio settings sub-elements—violates the WebM specification and causes parser failure.

Track and Codec Association

The presence of CodecDelay is tied to specific track attributes:

  • TrackType Requirement: It must only be defined on tracks where TrackType (0x83) is set to 2 (Audio).
  • CodecID Requirement: In WebM implementations of Opus, the CodecID (0x86) must be set to A_OPUS. While CodecDelay is optional or unused for some other codecs in standard Matroska, the WebM Opus adoption specification makes CodecDelay mandatory for every Opus track.

Cardinality and Multiplicity

  • Occurrence: CodecDelay must occur exactly once per Opus TrackEntry.
  • Zero or Duplicate Instances: A missing CodecDelay in an Opus TrackEntry renders the track non-compliant, as players cannot determine the pre-skip duration. Conversely, duplicate CodecDelay elements within the same TrackEntry are invalid under EBML parsing rules.

Data Type and Formatting Rules

  • Element Type: CodecDelay is stored as an unsigned integer (EBML uinteger).
  • Units: The value must be expressed in absolute nanoseconds, regardless of the TimestampScale specified in the SegmentInformation or the audio sample rate.
  • Value Alignment: For Opus, this value corresponds directly to the encoder's pre-skip delay (typically 3,840 samples at 48 kHz, translating to 80000000 nanoseconds, or 80 milliseconds). It dictates how many nanoseconds of decoded audio the demuxer/decoder must discard from the start of the stream to eliminate encoder priming artifacts.

Structural Interdependence with SeekPreRoll

When CodecDelay is present in an Opus TrackEntry, it is structurally paired with the SeekPreRoll element (0x56BB). While CodecDelay governs the container-level discard duration from the initial playback start, SeekPreRoll defines the sample preroll required when seeking to an arbitrary point in the stream. Both elements exist as direct siblings inside the TrackEntry and share the same nanosecond-based integer representation.
