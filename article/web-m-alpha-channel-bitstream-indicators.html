WebM Alpha Channel Bitstream Indicators

This article explains how a WebM demuxer or parser identifies the presence of an alpha transparency channel within a video stream. Because WebM is based on the Matroska (EBML) container format, detection relies on specific container-level elements and frame-level block structures rather than an interleaved pixel component inside the primary video bitstream. By inspecting the AlphaMode track header, the frame-level BlockAdditions structures, and the secondary compressed bitstream, parsers reliably determine transparency data for each video frame.

Track-Level Indicator: The AlphaMode Element

Before processing individual video frames, a WebM parser checks the track headers within the EBML hierarchy:

  • Element Name: AlphaMode
  • Element ID: 0x53C0
  • Location: Segment -> Tracks -> TrackEntry -> Video -> AlphaMode

The AlphaMode element is an unsigned integer. When set to 1, it signals to the parser that the video track contains alpha channel data alongside the primary color data. If this element is absent or set to 0, the parser treats the video as strictly opaque, ignoring any transparency metadata in subsequent blocks.

Frame-Level Indicators: BlockGroup and BlockAdditions

Standard WebM video streams without alpha typically store compressed frames inside SimpleBlock elements. When transparency is present, frames must instead be wrapped within a BlockGroup element to accommodate the secondary alpha stream.

A parser identifies alpha on a per-frame basis using the following nested structure:

  1. BlockGroup (0xA0): Replaces SimpleBlock to allow multi-part frame metadata.
  2. Block (0xA1): Contains the primary encoded video frame (YUV color data).
  3. BlockAdditions (0x75A1): A container for auxiliary frame data.
  4. BlockMore (0xA6): An individual entry inside BlockAdditions.
  5. BlockAddID (0xEE): An unsigned integer identifying the type of additional data. For WebM alpha transparency, this value must be set to 1.
  6. BlockAdditional (0xA5): The binary payload containing the encoded alpha frame that corresponds directly to the primary color frame in the sibling Block.

Secondary Codec Bitstream Structure

The data inside BlockAdditional is not raw uncompressed pixel values. Instead, it is a complete, independently encoded bitstream (typically VP8 or VP9) representing the alpha channel as a monochrome (luma-only) plane:

  • Keyframe Synchronization: The parser checks the keyframe flag of the primary Block bitstream and expects the bitstream in BlockAdditional to match the keyframe status of the primary frame.
  • Resolution Matching: When decoded, the frame generated from the BlockAdditional bitstream must match the horizontal and vertical pixel dimensions of the primary decoded YUV frame.
  • Plane Mapping: The parser extracts the luma (Y) plane from the decoded secondary frame and applies it as the 8-bit alpha (transparency) mask for the color image. Any chroma components (U/V) present in the secondary bitstream are discarded.
