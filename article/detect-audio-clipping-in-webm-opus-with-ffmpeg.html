Detect Audio Clipping in WebM Opus with FFmpeg

This article details how developers can automate the detection of audio clipping inside WebM containers containing Opus audio streams using FFmpeg. It covers the mechanisms behind digital and intersample clipping in lossy codecs, provides the exact FFmpeg filter commands needed to measure sample peaks and flat-topping, and demonstrates how to parse the results programmatically inside an automated pipeline.

Understanding Clipping in Opus Audio

Opus is a floating-point, lossy audio codec. When decoding Opus inside a WebM container, sample values can exceed 0 dBFS due to lossy reconstruction and intersample peaks. Clipping can manifest in two distinct ways:

  1. Digital Hard Clipping (Flat-Topping): Multiple consecutive audio samples reach the maximum possible ceiling (0 dBFS), creating flat-topped waveforms that produce audible distortion.
  2. True Peak Intersample Clipping: Peak levels that exceed 0 dBFS when reconstructed through a digital-to-analog converter (DAC), common after decoding compressed Opus audio.

FFmpeg provides two primary audio filters to detect these anomalies programmatically: astats and ebur128.

Method 1: Detecting Sample Clipping with the astats Filter

The astats filter analyzes audio properties across channels. For clipping detection, two metrics are critical:

  • Peak count: The total number of samples that touch the maximum digital level.
  • Flat factor: A metric indicating consecutive identical peak samples (the primary indicator of hard clipping).

Run the following command to output global audio statistics to stderr:

ffmpeg -hide_banner -nostats -i input.webm -vn -af "astats=metadata=0:reset=0" -f null -

In the output, locate the channel and overall statistics:

[Parsed_astats_0 @ 0x...] Flat factor: 0.000000
[Parsed_astats_0 @ 0x...] Peak count: 128
[Parsed_astats_0 @ 0x...] Peak level dB: 0.000000
  • A Peak level dB of 0.000000 alongside a non-zero Peak count signals that samples are reaching digital saturation.
  • A Flat factor significantly greater than 0.0 confirms hard clipping (waveform flattening).

Method 2: Detecting True Peak Overshoots with ebur128

Because Opus uses float representation, decoded signals often exceed 0 dBFS without immediate sample-level truncation. To detect intersample clipping in compliance with ITU-R BS.1770, use the ebur128 filter with true peak metering enabled:

ffmpeg -hide_banner -nostats -i input.webm -vn -af "ebur128=peak=true" -f null -

The terminal output provides a summary at the end of the process:

  True peak:
    Peak:                1.4 dBFS

Any True Peak measurement greater than 0.0 dBFS indicates intersample clipping that will cause distortion when rendered on standard audio hardware.

Programmatic Integration with Python

To integrate detection into a CI/CD pipeline, automated ingest worker, or quality-control script, execute FFmpeg as a subprocess and parse the output using regular expressions.

import subprocess
import re
import json

def analyze_webm_clipping(file_path: str) -> dict:
    cmd = [
        "ffmpeg",
        "-hide_banner",
        "-nostats",
        "-i", file_path,
        "-vn",
        "-af", "astats=metadata=0:reset=0,ebur128=peak=true",
        "-f", "null",
        "-"
    ]
    
    process = subprocess.run(cmd, stderr=subprocess.PIPE, stdout=subprocess.DEVNULL, text=True)
    output = process.stderr

    # Extract astats metrics
    flat_factor_match = re.search(r"Flat factor:\s+([0-9.]+)", output)
    peak_count_match = re.search(r"Peak count:\s+([0-9]+)", output)
    peak_db_match = re.search(r"Peak level dB:\s+(-?[0-9.]+)", output)

    # Extract ebur128 True Peak metric
    true_peak_match = re.search(r"True peak:\s+Peak:\s+(-?[0-9.]+)\s+dBFS", output)

    flat_factor = float(flat_factor_match.group(1)) if flat_factor_match else 0.0
    peak_count = int(peak_count_match.group(1)) if peak_count_match else 0
    peak_db = float(peak_db_match.group(1)) if peak_db_match else -99.0
    true_peak = float(true_peak_match.group(1)) if true_peak_match else -99.0

    has_sample_clipping = peak_db >= 0.0 and peak_count > 0 and flat_factor > 0.0
    has_true_peak_clipping = true_peak > 0.0

    return {
        "file": file_path,
        "is_clipping": has_sample_clipping or has_true_peak_clipping,
        "metrics": {
            "peak_level_db": peak_db,
            "peak_count": peak_count,
            "flat_factor": flat_factor,
            "true_peak_dbfs": true_peak
        }
    }

# Example execution
result = analyze_webm_clipping("audio_track.webm")
print(json.dumps(result, indent=2))

Threshold Recommendations

  • Hard Clipping: Reject or flag tracks where flat_factor > 0.001 and peak_count > 10.
  • True Peak Intersample Clipping: Flag tracks where true_peak > 0.0 dBFS. For standard broadcast and streaming normalization (such as YouTube or Spotify), target a True Peak ceiling between -1.0 dBFS and -2.0 dBFS prior to Opus compression to prevent encoder-induced clipping.
