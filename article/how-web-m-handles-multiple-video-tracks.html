How WebM Handles Multiple Video Tracks

This article explains how the WebM container format manages, multiplexes, and synchronizes multiple video tracks within a single media stream. Based on the Extensible Binary Meta Language (EBML) derived from the Matroska specification, WebM provides a structured header and packet-level addressing system to distinguish between different video streams, assign metadata, and enable track selection during playback.

Structural Architecture: The Tracks Element

At the file header level, the WebM container defines all media streams inside a top-level Segment that contains a Tracks master element. Each video stream within the container is defined as an individual TrackEntry.

When multiple video tracks are present, each TrackEntry contains specific identifying parameters:

  • TrackNumber: A unique integer within the file used by the demuxer to map incoming data blocks to the correct stream.
  • TrackUID: A globally unique 64-bit identifier for persistent track referencing.
  • TrackType: Set to 1 to explicitly designate the track as a video stream.
  • Video Settings: Sub-elements specifying properties unique to that specific stream, such as PixelWidth, PixelHeight, DisplayWidth, DisplayHeight, and frame rate data.
  • CodecID: Identifies the video compression format for that specific track (typically V_VP8, V_VP9, or V_AV1).

Packet Multiplexing and Time Synchronization

Data storage in WebM occurs inside Cluster elements. Each Cluster contains a base timestamp (Timecode) and multiple data packets formatted as SimpleBlock or BlockGroup elements.

When multiplexing multiple video tracks:

  1. Header Identification: Every SimpleBlock begins with a variable-length integer indicating its corresponding TrackNumber.
  2. Payload Segregation: Video frames for different tracks are interleaved within the same Cluster. The demuxer reads the TrackNumber prefix to direct frames to the appropriate decoding pipeline.
  3. Timestamp Alignment: Each block carries a relative timecode offset. This ensures that frames across primary, secondary, or multi-angle video tracks remain synchronized to the same global playback timeline.

Stream Designation and Flagging

To guide player behavior when multiple video streams exist, WebM utilizes Matroska-derived track selection flags:

  • FlagDefault: Indicates whether a track should be played automatically if no user preference is defined. Only one video track should typically have this flag set to 1.
  • FlagEnabled: Specifies whether a track is active and usable by the player.
  • Name / Language: String tags that label the stream for the user interface (e.g., "Main Angle", "Director Cam", or "Sign Language Overlay").

Demuxing and Player Implementation

While the underlying EBML container natively supports multiple video streams, standard HTML5 <video> implementations typically decode only the default video track due to browser-level media engine limitations. However, dedicated media frameworks (such as FFmpeg and GStreamer) and advanced players (such as VLC) fully parse the Tracks header, allowing users or applications to switch between alternate video streams or render picture-in-picture streams from the same WebM file.
