WebM Cluster Timecode Timing Information

In the WebM container format, the Cluster Timecode element establishes the absolute baseline reference time for all media samples contained within a specific cluster. This article breaks down the exact timing data stored within the Cluster Timecode, how it interacts with the container's global time scaling, and how individual audio and video frames calculate their final presentation timestamps.

Absolute Base Timestamp

The Timecode element (also referred to as Timestamp in updated Matroska and WebM specifications, with EBML ID 0xE7) stores an absolute unsigned integer value. This value represents the cluster's start time relative to the beginning of the entire WebM segment (which starts at time zero). It does not represent an individual frame's display duration on its own, but rather serves as a shared synchronization anchor for every data block grouped inside that cluster.

TimecodeScale and Unit Resolution

The integer value stored in the Cluster Timecode is not in raw seconds or milliseconds by default. Instead, its real-world time unit depends on the global TimestampScale (or TimecodeScale) defined in the WebM Info header.

  • Default Scale: By default in WebM, TimestampScale is set to 1,000,000 nanoseconds (1 millisecond).
  • Time Calculation: To find the absolute time of a cluster in nanoseconds, the formula is: \[\text{Cluster Time (in nanoseconds)} = \text{Cluster Timecode} \times \text{TimestampScale}\]

For example, if the TimestampScale is 1,000,000 and the Cluster Timecode is 5000, the cluster begins precisely at 5,000,000,000 nanoseconds (5 seconds) into the media playback.

Frame Timing and Block Offsets

Inside each WebM cluster, actual media frames are stored within SimpleBlock or BlockGroup elements. To save file space, individual blocks do not store large absolute timestamps. Instead, each block contains a 16-bit signed integer representing a relative offset from the Cluster Timecode.

The final presentation time for any specific frame inside a cluster is calculated as:

\[\text{Frame Presentation Time} = (\text{Cluster Timecode} + \text{Block Timecode Offset}) \times \text{TimestampScale}\]

Because the block offset is a signed integer, frame timestamps can occur slightly before or after the base Cluster Timecode, though standard practice places the cluster timecode at or near the timestamp of the first keyframe in the cluster.

Primary Functions of the Cluster Timecode

  1. Efficient Compression: Using a cluster-level base timestamp allows individual frame timestamps to use compact 2-byte signed integers rather than full 64-bit values.
  2. Fast Seeking: Video players can quickly scan cluster headers to locate specific time intervals during seeking operations without parsing every individual frame.
  3. Track Synchronization: It provides a common time reference to ensure independent video, audio, and subtitle tracks remain synchronized throughout playback.
