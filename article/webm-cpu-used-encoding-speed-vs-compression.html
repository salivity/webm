WebM CPU-Used: Encoding Speed vs Compression

The -cpu-used parameter in WebM encoding controls the balance between processing speed, visual quality, and compression efficiency. In codecs like VP8 and VP9 (via libvpx), adjusting this setting tells the encoder how much computational effort to invest in analyzing video frames. Lower numerical values instruct the encoder to perform exhaustive compression algorithms, yielding smaller file sizes and better quality at the expense of longer render times. Higher values streamline or skip complex calculations, dramatically speeding up encoding while slightly reducing compression efficiency.

How the Parameter Works

In WebM encoding pipelines (such as FFmpeg using libvpx or libvpx-vp9), the -cpu-used setting acts as a speed-versus-efficiency dial. Depending on the encoding mode (quality/deadline set to good or realtime), the integer values alter internal algorithmic decisions:

  • VP9 (Quality/Good Mode): Accepts values typically from 0 to 5.
  • VP9 (Realtime Mode): Accepts values typically from 5 to 8 or -8 to 8 depending on the implementation.
  • VP8: Accepts values from 0 to 5 (or negative values down to -16 for real-time applications).

Impact on Encoding Speed

Increasing the -cpu-used value reduces the computational workload on the processor:

  • Higher Values (e.g., 4 to 8): The encoder skips deeper motion search iterations, uses larger partition blocks without evaluating smaller sub-blocks, and simplifies rate-distortion optimization. This leads to significantly faster encoding speeds, making high values essential for live streaming, real-time communication, and fast draft exports.
  • Lower Values (e.g., 0 to 2): The encoder evaluates every potential block split, intra-prediction mode, and motion vector. This drastically increases CPU time, often making exports multiple times slower compared to higher settings.

Impact on Compression Ratio and Quality

The compression ratio is directly tied to how thoroughly the encoder searches for spatial and temporal redundancies:

  • Higher Values: Because the encoder takes algorithmic shortcuts, it requires a higher bitrate to achieve the same visual fidelity, resulting in larger file sizes at a fixed quality level (or lower visual quality at a constrained bitrate).
  • Lower Values: Exhaustive searching allows the encoder to pack visual information into fewer bits, maximizing the compression ratio. A value of 0 or 1 achieves the highest possible quality-per-bit for VOD (Video on Demand) distribution.

Practical Guidelines

  • Archival and Final Distribution: Use -cpu-used 0 or -cpu-used 1 with VP9 in two-pass mode. While encoding will be slow, it delivers the smallest file size at the highest visual fidelity.
  • General Purpose / Web Delivery: Use -cpu-used 2 to -cpu-used 4. Setting the value to 4 offers the best sweet spot, providing a massive reduction in encoding time with only a marginal loss in compression efficiency compared to 0.
  • Live Streaming / Fast Previews: Use -cpu-used 5 to -cpu-used 8 combined with real-time deadline modes to ensure frames are processed quickly enough to prevent buffer underruns and dropped frames.
