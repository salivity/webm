WebM Video Cropping Binary Elements

WebM video containers rely on standard Matroska Extensible Binary Meta Language (EBML) elements to manage non-destructive video cropping during playback. Rather than permanently altering or re-encoding raw frame data, WebM utilizes four distinct binary metadata elements located within the video track headers to specify the precise clipping boundaries from each outer edge of the decoded video stream.

EBML Hierarchy and Placement

The clipping boundaries are stored as unsigned integers inside the main video settings tree of the WebM container. In the EBML hierarchy, these elements reside within Segment -> Tracks -> TrackEntry -> Video.

The Core Binary Elements

When a compliant WebM player renders a video, it reads the following four EBML elements to determine how many pixels to remove from the video frame margins:

  • PixelCropTop (0x54BB): Defines the number of video pixels to clip off the top edge of the encoded image.
  • PixelCropBottom (0x54AA): Defines the number of video pixels to clip off the bottom edge of the encoded image.
  • PixelCropLeft (0x54CC): Defines the number of video pixels to clip off the left edge of the encoded image.
  • PixelCropRight (0x54DD): Defines the number of video pixels to clip off the right edge of the encoded image.

Display Coordinate Calculation

By default, if any of these elements are omitted from the Video master element, their value defaults to 0.

When these elements are present, the player calculates the visible viewing area using the declared encoded dimensions (PixelWidth at 0xB0 and PixelHeight at 0xBA):

  • Rendered Width = PixelWidth - (PixelCropLeft + PixelCropRight)
  • Rendered Height = PixelHeight - (PixelCropTop + PixelCropBottom)

The resulting cropped area is then scaled according to the optional DisplayWidth (0x54B0), DisplayHeight (0x54BA), and DisplayUnit (0x54B2) tags to preserve the intended aspect ratio on the viewer's screen.
