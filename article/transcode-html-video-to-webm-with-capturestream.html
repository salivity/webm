Transcode HTML Video to WebM with CaptureStream

This article explains how web developers can transcode HTML video elements into WebM format directly within the browser. By combining the HTMLMediaElement.captureStream() method with the MediaRecorder API, developers can capture real-time audio and video tracks from a playing media element and re-encode them into a standalone WebM file without needing server-side processing.

The Transcoding Workflow

Transcoding on the client side relies on two primary browser APIs: captureStream() to pipe the media frames, and MediaRecorder to encode those frames into a specific container and codec.

  1. Stream Extraction: The videoElement.captureStream() method is called on an existing <video> element. This creates a MediaStream containing real-time video and audio tracks extracted directly from the element's current playback.
  2. Recorder Setup: A MediaRecorder instance is initialized using the captured MediaStream. The developer specifies the target MIME type, typically 'video/webm' or a more specific codec profile like 'video/webm; codecs=vp9,opus'.
  3. Data Collection: The recorder buffers encoded media slices as the video plays. An event listener on dataavailable stores these binary chunks in an array.
  4. Export: When the video ends or recording is stopped, the stop event listener compiles the collected chunks into a single Blob of type video/webm.

Implementation Example

The following JavaScript demonstrates the complete process of capturing an existing video and producing a downloadable WebM file:

async function transcodeVideoToWebM(videoElement) {
  // 1. Capture the stream from the video element
  const stream = videoElement.captureStream ? videoElement.captureStream() : videoElement.mozCaptureStream();

  // 2. Configure recorder options
  const options = { mimeType: 'video/webm; codecs=vp8,opus' };
  if (!MediaRecorder.isTypeSupported(options.mimeType)) {
    throw new Error(`${options.mimeType} is not supported on this browser.`);
  }

  const mediaRecorder = new MediaRecorder(stream, options);
  const recordedChunks = [];

  // 3. Collect data chunks as they become available
  mediaRecorder.ondataavailable = (event) => {
    if (event.data && event.data.size > 0) {
      recordedChunks.push(event.data);
    }
  };

  // 4. Return a promise that resolves when the recording stops
  return new Promise((resolve) => {
    mediaRecorder.onstop = () => {
      const webmBlob = new Blob(recordedChunks, { type: 'video/webm' });
      resolve(webmBlob);
    };

    // Automatically stop when the source video ends
    videoElement.onended = () => {
      mediaRecorder.stop();
    };

    // Start recording and initiate playback
    mediaRecorder.start();
    videoElement.play();
  });
}

Key Considerations

  • CORS Restrictions: The source video must comply with Cross-Origin Resource Sharing (CORS) rules. If the video is served from an external domain without the proper Access-Control-Allow-Origin headers, the media element becomes origin-clean tainted, and captureStream() will fail to capture the media tracks.
  • Real-Time Limitation: Because captureStream() records frames during playback, this method runs in real-time. A 60-second video will take 60 seconds to transcode, though developers can set videoElement.playbackRate to higher values (such as 2.0 or 3.0) in supporting browsers to accelerate the process.
  • Mime Type Availability: Browser support for specific codecs inside the WebM container varies. Always verify support using MediaRecorder.isTypeSupported() before initiating recording.
