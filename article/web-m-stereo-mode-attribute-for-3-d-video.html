WebM Stereo Mode Attribute for 3D Video

This article explains how the WebM container format identifies and organizes stereoscopic 3D video content using the StereoMode metadata element. By defining specific integer values within the video track headers, WebM enables media players and hardware decoders to correctly parse packed 3D layouts, such as side-by-side or top-bottom configurations, and present the appropriate view to each eye without requiring separate video streams.

EBML and Matroska Container Architecture

WebM is built upon the Extensible Binary Meta Language (EBML), a binary equivalent of XML derived from the Matroska specification. Because WebM inherits its container specifications from Matroska, stereoscopic signaling is implemented at the container track level rather than inside the raw VP8, VP9, or AV1 video bitstreams.

Within a WebM file, stereoscopic configuration is placed inside the TrackEntry element, specifically nested within the Video settings element:

  • Element Name: StereoMode
  • EBML ID: 0x53B8
  • Data Type: Unsigned Integer (uinteger)
  • Default Value: 0 (mono / 2D video)

When the StereoMode element is omitted, decoders assume the video is standard 2D content.

Supported StereoMode Layout Values

The StereoMode attribute uses an enumerated integer to define the spatial arrangement of the left and right eye views within each frame:

  • 0: Mono – Standard 2D video (no stereoscopic layout).
  • 1: Side-by-Side (Left Eye First) – The left eye view is placed on the left half of the frame; the right eye view is on the right half.
  • 2: Top-Bottom (Right Eye First) – The right eye view occupies the upper half; the left eye view occupies the lower half.
  • 3: Top-Bottom (Left Eye First) – The left eye view occupies the upper half; the right eye view occupies the lower half.
  • 4: Checkboard (Right Eye First) – Pixels alternate in a checkerboard pattern starting with the right eye.
  • 5: Checkboard (Left Eye First) – Pixels alternate in a checkerboard pattern starting with the left eye.
  • 6: Row Interleaved (Right Eye First) – Alternating horizontal lines, starting with the right eye.
  • 7: Row Interleaved (Left Eye First) – Alternating horizontal lines, starting with the left eye.
  • 8: Column Interleaved (Right Eye First) – Alternating vertical columns, starting with the right eye.
  • 9: Column Interleaved (Left Eye First) – Alternating vertical columns, starting with the left eye.
  • 10: Anaglyph (Cyan/Red) – Color-filtered stereoscopy suitable for red-cyan glasses.
  • 11: Side-by-Side (Right Eye First) – The right eye view is on the left half; the left eye view is on the right half.
  • 12: Anaglyph (Green/Magenta) – Color-filtered stereoscopy suitable for green-magenta glasses.
  • 13: Both Eyes Laced in One Block (Left Eye First) – Both frames are packed into a single block stream.
  • 14: Both Eyes Laced in One Block (Right Eye First) – Both frames are packed into a single block stream.

The most common implementations in web delivery and VR applications are Mode 1 (Side-by-Side, Left Eye First) and Mode 3 (Top-Bottom, Left Eye First).

Aspect Ratio and Resolution Handling

When packing two stereoscopic views into a single frame, the horizontal or vertical resolution of each individual eye is often halved (known as Half-SBS or Half-TAB).

WebM uses complementary EBML elements to ensure correct aspect ratio display:

  • PixelWidth and PixelHeight: Define the coded resolution of the full frame containing both views.
  • DisplayWidth and DisplayHeight: Define the intended rendering geometry for a single eye view after demuxing and scaling.
  • DisplayUnit: Configures the measurement unit for display dimensions (e.g., pixels, display aspect ratio).

Decoder and Player Implementation

When a WebM-compliant player encounters the StereoMode tag:

  1. Demuxing: The demuxer reads EBML ID 0x53B8 during header initialization.
  2. Decoding: The underlying video decoder (e.g., VP9) decodes the full combined frame as standard video.
  3. Rendering: The presentation engine splits or masks the decoded frame based on the StereoMode value, routing the corresponding frame halves to the display buffer, 3D screen, or VR headset displays.
