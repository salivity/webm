YUV to sRGB Conversion in Browser Compositors

Modern web browser compositors render YUV WebM video content to sRGB displays through an optimized, GPU-accelerated graphics pipeline. Rather than converting video frames to RGB immediately upon decoding, compositors receive planar or semi-planar YUV video buffers and defer color format transformation until the final rendering stage. Depending on hardware capabilities and page layout, the compositor executes this conversion either directly inside custom GPU fragment shaders or by delegating the planar buffers to specialized display controller hardware via multi-plane overlays.

Decoding and Buffer Management

WebM video containers typically encapsulate video streams encoded in VP8, VP9, or AV1 formats, which store pixel data in YUV color spaces—most frequently YUV 4:2:0 (such as I420 or NV12). In 4:2:0 subsampling, the chroma components (U and V) are stored at half the horizontal and vertical resolution of the luma component (Y) to save bandwidth.

Modern browsers avoid performing pixel format conversions on the CPU or immediately after decoding. When hardware-accelerated decoding (such as DXVA2/D3D11 on Windows, VideoToolbox on macOS, or VA-API on Linux) completes, the decoder outputs native GPU surface handles (like Direct3D textures, Metal textures, or DMA-BUFs). If a software decoder (like libvpx or dav1d) is used instead, the decoded planar system memory is uploaded directly to the GPU as separate single-channel and two-channel textures.

Hardware Overlay Scanout (The Fast Path)

Before processing the frame through standard composition shaders, browser compositing engines (such as Chromium’s Viz or Firefox’s WebRender) check if the video surface can utilize Direct Overlays or Multi-Plane Overlays (MPO).

If the video element is unoccluded, axis-aligned, and does not require complex CSS blending or filtering, the compositor passes the native YUV surface handle straight to the windowing system and display hardware. Modern display engines (found in Intel, AMD, and NVIDIA GPUs, as well as Apple Silicon) contain dedicated fixed-function scanout hardware capable of processing YUV inputs. The display processor handles chroma upsampling, color matrix multiplication, and sRGB gamma correction in real-time during scanout to the monitor. This path completely bypasses GPU fragment shading and memory read-back, significantly reducing power consumption and latency.

GPU Shader Pipeline Conversion

When an overlay cannot be promoted—such as when CSS effects, opacity, rotation, or overlaying DOM nodes are present—the compositor integrates the video frame into its standard rendering pass via a dedicated fragment shader.

  1. Chroma Upsampling: The fragment shader samples the Y plane and the subsampled U/V planes (either separate planes in I420 or interleaved UV in NV12). The GPU texture sampling units perform bilinear interpolation on the chroma coordinates to reconstruct full 4:4:4 resolution per pixel.
  2. Range Expansion: Video content can use either limited range (studio swing: Y spans 16–235, UV spans 16–240) or full range (0–255). The shader subtracts standard DC offsets and scales the values to normalize them into a uniform [0.0, 1.0] floating-point range based on container or bitstream metadata.
  3. Color Space Matrix Multiplication: The normalized YUV values are multiplied by a 3x3 transformation matrix to produce RGB. The exact matrix depends on the standard declared in the WebM bitstream:
    • BT.601: Primarily used for standard-definition content.
    • BT.709: Standard for high-definition content, which uses different luma weighting coefficients than BT.601.
    • BT.2020: Used for ultra-high-definition and wide-gamut workflows.
  4. Color Management and Transfer Functions: The matrix multiplication outputs linear RGB coordinates tied to the video's specified color primaries. If the target display expects standard sRGB, the compositor applies an Electro-Optical Transfer Function (EOTF) or an ICC color profile lookup to map the linear values into non-linear sRGB space.

Frame Buffer Presentation

Once the fragment shader calculates the final sRGB color values, it writes the result to the browser window’s draw buffer alongside other web elements. The final frame is submitted to the operating system's swapchain and presented to the screen, ensuring accurate color reproduction while maintaining high throughput and minimal memory bandwidth utilization.
