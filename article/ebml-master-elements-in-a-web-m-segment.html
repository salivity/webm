EBML Master Elements in a WebM Segment

This article provides a technical breakdown of the Extensible Binary Meta Language (EBML) Master elements that can be nested within the Segment element of a WebM file. In the WebM container format—a constrained subset of Matroska—the Segment element functions as the primary container for all playback data and metadata. Below is a direct, detailed reference to the specific Master elements permitted inside this top-level structure.

In EBML, a Master element is an element that contains other EBML sub-elements (acting similarly to an XML parent tag or directory). The Segment element (Element ID: 0x18538067) wraps the entire multimedia stream.

According to the WebM container specification, the following specific EBML Master elements can be nested directly beneath the Segment element:

1. SeekHead (0x114D9B74)

The SeekHead element contains index pointers to other top-level elements within the Segment. It enables players to seek directly to specific structures without parsing the entire file sequentially.

  • Key nested children: One or more Seek master elements (each containing SeekID and SeekPosition).

2. Info (0x1549A966)

The Info element houses fundamental metadata regarding the entire segment and playback synchronization. A WebM file must contain an Info element.

  • Key nested children: TimestampScale (formerly TimecodeScale), Duration, MuxingApp, and WritingApp.

3. Tracks (0x1654AE6B)

The Tracks element declares the technical parameters of the elementary media streams (video and audio). It is mandatory for file playback.

  • Key nested children: One or more TrackEntry master elements, which define parameters such as TrackNumber, TrackUID, TrackType, CodecID, Video, and Audio.

4. Cluster (0x1F43B675)

The Cluster element contains the actual media data packets. A WebM file typically contains multiple sequential Cluster elements, designed to facilitate network streaming and dynamic buffering.

  • Key nested children: Timestamp (the cluster baseline timestamp), SimpleBlock (standard compressed media frames), and BlockGroup (for complex media frames requiring additional metadata).

5. Cues (0x1C53BB6B)

The Cues element serves as the primary seek index for player navigation. It maps presentation timestamps to precise byte offsets of keyframe clusters.

  • Key nested children: Multiple CuePoint master elements, which further contain CueTime and CueTrackPositions.

6. Tags (0x1254C367)

The Tags element stores general descriptive metadata regarding the file, tracks, or individual segments (such as titles, artists, or copyright information).

  • Key nested children: One or more Tag master elements, each nesting Targets and SimpleTag structures.

7. Chapters (0x1043A770)

The Chapters element provides basic navigational markers throughout the timeline, allowing players to jump between predefined scene points.

  • Key nested children: EditionEntry and ChapterAtom master elements detailing chapter display names and start/stop timestamps.
