VP9 Transform Tree Depths in Recursive Intra-Coding

In WebM VP9 video coding, intra-prediction blocks can be recursively partitioned into transform blocks of varying sizes to maximize coding efficiency. During recursive intra-coding, VP9 supports transform tree depths ranging from depth 0 up to depth 3, depending on the coding block size. Because the codec defines four discrete square transform sizes—32x32, 16x16, 8x8, and 4x4—a block can undergo up to three successive levels of quadtree decomposition down to the 4x4 minimum transform size.

Supported Transform Sizes and Depths

VP9 restricts transform operations to four square dimensions: 32x32, 16x16, 8x8, and 4x4. The maximum transform dimension allowed is 32x32, while the minimum is 4x4. Transform tree depth measures how many times a coding block's transform domain is recursively split into four quadrants.

The supported transform depths correspond directly to the block size:

  • 32x32 Blocks (Depths 0 to 3):
    • Depth 0: Single 32x32 transform.
    • Depth 1: Four 16x16 transforms.
    • Depth 2: Sixteen 8x8 transforms.
    • Depth 3: Sixty-four 4x4 transforms.
  • 16x16 Blocks (Depths 0 to 2):
    • Depth 0: Single 16x16 transform.
    • Depth 1: Four 8x8 transforms.
    • Depth 2: Sixteen 4x4 transforms.
  • 8x8 Blocks (Depths 0 to 1):
    • Depth 0: Single 8x8 transform.
    • Depth 1: Four 4x4 transforms.
  • 4x4 Blocks (Depth 0):
    • Depth 0: Single 4x4 transform (no further decomposition is possible).
  • 64x64 Blocks:
    • Because the maximum transform size in VP9 is 32x32, a 64x64 coding block is mandatory-partitioned into four 32x32 transform units at the top level. Each 32x32 unit can then independently descend from depth 0 (32x32) down to depth 3 (4x4).

How Recursive Intra-Coding Works

When recursive intra-coding splits a block into smaller transform units (depth > 0), the intra-prediction and reconstruction loop executes sequentially in raster order across each sub-unit:

  1. Local Prediction: The encoder predicts the current sub-transform block using adjacent boundary pixels.
  2. Transform and Quantization: The residual for the sub-block is calculated, transformed, and quantized.
  3. Reconstruction: The quantized coefficients are inverse-transformed and reconstructed immediately.
  4. Boundary Update: The reconstructed edges of the current sub-block immediately serve as reference samples for adjacent subsequent sub-blocks within the same parent coding block.

This tight feedback loop is why deeper transform trees (depths 2 and 3) are particularly effective for intra-coding in high-detail areas, as reconstructed reference samples remain geographically closer to the pixels being predicted.

Transform Selection Signaling

The encoder controls transform depth signaling via the frame-level transform mode (tx_mode):

  • ONLY_4X4: Forces all blocks to the minimum 4x4 transform size.
  • ALLOW_8X8, ALLOW_16X16, ALLOW_32X32: Caps the maximum allowable transform size across the frame.
  • TX_MODE_SELECT: Allows the encoder to dynamically signal the optimal transform depth for each block, enabling full quadtree decomposition from depth 0 down to the block's maximum allowable depth.
