VP9 Intra-Only Non-Keyframe Bitstream Indicators

This article provides an overview of the specific syntax elements within the VP9 uncompressed frame header that designate a frame as an intra-only non-keyframe. In VP9 video streams, decoders determine whether a frame uses solely intra-prediction without acting as a full keyframe by parsing a sequence of header flags, specifically evaluating the show_existing_frame, frame_type, and intra_only syntax elements.

The VP9 Uncompressed Header Syntax

In VP9, frame-level properties are signaled at the beginning of each frame in the uncompressed header. To determine if a frame is an intra-only non-keyframe, the decoder reads the bitstream in the following sequential order:

  1. frame_marker (2 bits): Must be binary 10 (value 2) to validate the start of a VP9 frame.
  2. profile (1–3 bits): Determines the VP9 profile (profile_low_bit, and conditionally profile_high_bit / reserved_zero).
  3. show_existing_frame (1 bit): Must be 0. A value of 1 indicates that the frame is merely a display command for a previously decoded reference buffer, bypassing new frame decoding.
  4. frame_type (1 bit): Must be 1. In VP9:
    • 0 represents a KEY_FRAME.
    • 1 represents a NON_KEY_FRAME (typically an inter-coded frame).
  5. show_frame (1 bit): Dictates whether the frame is displayed immediately (1) or stored as a reference frame (0).
  6. error_resilient_mode (1 bit): Controls error resilience behavior.
  7. intra_only (1 bit): Must be 1. This flag is only present in the bitstream when frame_type is 1 (non-keyframe).

Key Signaling Condition

A frame is definitively identified as an intra-only non-keyframe when:

  • show_existing_frame == 0
  • frame_type == 1
  • intra_only == 1

Downstream Bitstream Implications

When intra_only evaluates to 1 on a non-keyframe:

  • reset_frame_context (2 bits): This field appears immediately after the intra_only flag. It specifies whether the frame context (probability tables) should be reset to default values (0b11 or 0b10) or maintained (0b00).
  • Absence of Reference Frame Selection: Unlike typical inter-frames (intra_only == 0), the bitstream skips parsing the ref_frame_idx and ref_frame_sign_bias fields because no temporal references (LAST, GOLDEN, or ALTREF) are utilized for reconstruction.
  • refresh_frame_flags (8 bits): The bitstream explicitly signals which reference frame buffers should be overwritten by this newly decoded intra frame without forcing a mandatory refresh of all buffers, which is standard behavior for traditional keyframes.

This signaling combination allows encoders to insert intra-coded recovery points or switch points (common in Scalable Video Coding / SVC) without disrupting the reference buffers required by subsequent dependent frames.
