Fix WebM Pixel Aspect Ratio Distortion

Non-standard Pixel Aspect Ratio (PAR) distortion occurs when a WebM video displays stretched or squished because the playback software assumes square pixels (1:1 PAR) instead of the intended non-square aspect ratio. This guide explains how to detect PAR discrepancies using tools like MediaInfo and FFmpeg, and provides step-by-step methods to fix the distortion by either altering metadata flags without quality loss or re-encoding the video to standard square pixels for universal web compatibility.

Understanding Pixel Aspect Ratio (PAR) in WebM

Video geometry relies on three core values:

  • Storage Aspect Ratio (SAR): The raw pixel dimensions (width x height) stored in the file.
  • Pixel Aspect Ratio (PAR): The shape of an individual pixel (width:height ratio). Standard digital video uses square pixels (1:1), whereas legacy formats (like DVD or anamorphic captures) often use rectangular pixels.
  • Display Aspect Ratio (DAR): The final intended viewing dimension, calculated as \(\text{DAR} = \text{SAR} \times \text{PAR}\).

Web browsers and HTML5 <video> players frequently ignore non-square PAR metadata inside WebM containers, forcing a 1:1 pixel rendering. This results in noticeable horizontal or vertical distortion.

How to Identify Non-Standard PAR

Method 1: Using FFmpeg (ffprobe)

Run the following command in your terminal to inspect the video stream metadata:

ffprobe -v error -select_streams v:0 -show_entries stream=width,height,sample_aspect_ratio,display_aspect_ratio input.webm

Output Analysis:

  • If sample_aspect_ratio=1:1 or N/A, the file uses standard square pixels.
  • If sample_aspect_ratio is anything other than 1:1 (e.g., 40:33, 32:27, or 8:9), the file contains non-standard PAR and will distort in players that do not support anamorphic playback.

Method 2: Using MediaInfo

Open the WebM file in MediaInfo and inspect the Video section:

  • Look at Original display aspect ratio versus Display aspect ratio.
  • Look at Pixel aspect ratio. A value other than 1.000 indicates non-square pixels.

How to Fix WebM PAR Distortion

Method 1: Re-encode to Standard Square Pixels (Universal Fix)

The most reliable solution for the web is re-encoding the video so the pixel data itself matches the intended display dimensions with a 1:1 PAR.

Use FFmpeg with the scale and setsar filters:

ffmpeg -i input.webm -vf "scale=iw*sar:ih,setsar=1" -c:v libvpx-vp9 -b:v 0 -crf 30 -c:a copy output.webm
  • scale=iw*sar:ih scales the image horizontally to match the display aspect ratio.
  • setsar=1 sets the pixel aspect ratio explicitly to 1:1 (square).
  • -c:v libvpx-vp9 -crf 30 -b:v 0 re-encodes the stream using VP9 with standard quality-based variable bitrate.
  • -c:a copy copies the audio stream without re-encoding.

If you need a specific target resolution (e.g., standard 1080p, 16:9):

ffmpeg -i input.webm -vf "scale=1920:1080:force_original_aspect_ratio=decrease,pad=1920:1080:(ow-iw)/2:(oh-ih)/2,setsar=1" -c:v libvpx-vp9 -crf 30 -b:v 0 -c:a copy output.webm

Method 2: Lossless Display Flag Correction (Remuxing)

If your target player respects Matroska/WebM container display dimension flags, you can modify the display width and height without re-encoding the video stream.

Using mkvmerge (from MKVToolNix):

  1. Determine the target display resolution (e.g., \(720 \times 480\) with a 16:9 DAR should display at \(854 \times 480\)).
  2. Run mkvpropedit or mkvmerge to set the display dimensions:
mkvmerge -o output.webm --display-dimensions 0:854x480 input.webm

Using FFmpeg (Lossless Remux):

ffmpeg -i input.webm -c copy -aspect 16:9 output.webm

Note: While remuxing is instantaneous and preserves 100% of original quality, some web browsers and mobile platforms may still ignore container-level aspect ratio flags. For guaranteed web compatibility, re-encoding to 1:1 PAR (Method 1) is recommended.
