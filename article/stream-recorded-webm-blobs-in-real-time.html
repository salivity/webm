Stream Recorded WebM Blobs in Real-Time

Streaming recorded WebM media blobs from a web browser to a remote server in real-time requires capturing media chunks as they are generated and transmitting them over a low-latency network protocol. This article outlines how to segment media data using the MediaRecorder API and details the primary JavaScript networking methods—WebSockets, WebTransport, the Fetch API with streaming request bodies, and WebRTC—used to transmit these WebM chunks to a backend server.

Capturing WebM Blobs in Real-Time

The browser cannot stream a live recording as a single monolithic file. Instead, the MediaRecorder API must be configured to slice the recording into time-based chunks.

const stream = await navigator.mediaDevices.getUserMedia({ video: true, audio: true });
const mediaRecorder = new MediaRecorder(stream, { mimeType: 'video/webm; codecs=vp8,opus' });

// Request data every 1000 milliseconds
mediaRecorder.start(1000);

mediaRecorder.ondataavailable = (event) => {
  if (event.data && event.data.size > 0) {
    sendChunkToServer(event.data); // event.data is a WebM Blob
  }
};

Passing a timeslice (in milliseconds) to mediaRecorder.start(timeslice) ensures that the ondataavailable event fires repeatedly at the specified interval, providing individual WebM Blob segments ready for transmission.

JavaScript Methods for Streaming to a Server

1. WebSocket API (WebSocket.send())

WebSockets provide a persistent, bidirectional TCP connection and represent the most common method for relaying WebM blobs to a backend.

  • Method: socket.send(blob) or socket.send(arrayBuffer)
  • Protocol: TCP (WS/WSS)
  • Best for: General-purpose real-time streaming where standard TCP reliability is acceptable.
const socket = new WebSocket('wss://example.com/media-stream');
socket.binaryType = 'arraybuffer';

mediaRecorder.ondataavailable = async (event) => {
  if (event.data.size > 0 && socket.readyState === WebSocket.OPEN) {
    // Send Blob directly or convert to ArrayBuffer
    const buffer = await event.data.arrayBuffer();
    socket.send(buffer);
  }
};

2. WebTransport API (WebTransport.createUnidirectionalStream())

WebTransport is a modern alternative to WebSockets that operates over HTTP/3 (QUIC). It provides bidirectional and unidirectional streams with lower latency and avoids head-of-line blocking.

  • Method: writableStream.getWriter().write(chunk)
  • Protocol: UDP (QUIC/HTTP/3)
  • Best for: Ultra-low latency streaming and environments requiring multiplexed, independent streams.
const transport = new WebTransport('https://example.com:4433/stream');
await transport.ready;

const stream = await transport.createUnidirectionalStream();
const writer = stream.getWriter();

mediaRecorder.ondataavailable = async (event) => {
  if (event.data.size > 0) {
    const buffer = new Uint8Array(await event.data.arrayBuffer());
    await writer.write(buffer);
  }
};

3. Fetch API with Streaming Request Bodies

Modern browsers support streaming request bodies with the fetch() API via ReadableStream. This allows sending an ongoing stream over a standard HTTP/2 or HTTP/3 POST request without managing long-lived WebSocket connections.

  • Method: fetch(url, { method: 'POST', body: readableStream, duplex: 'half' })
  • Protocol: HTTP/2 or HTTP/3
  • Best for: REST-oriented architectures and standard HTTP server endpoints.
let streamController;
const customStream = new ReadableStream({
  start(controller) {
    streamController = controller;
  }
});

// Initiate the chunked HTTP POST request
fetch('/api/upload-stream', {
  method: 'POST',
  body: customStream,
  headers: { 'Content-Type': 'video/webm' },
  duplex: 'half' // Required for streaming request bodies in Chromium
});

mediaRecorder.ondataavailable = async (event) => {
  if (event.data.size > 0 && streamController) {
    const buffer = new Uint8Array(await event.data.arrayBuffer());
    streamController.enqueue(buffer);
  }
};

mediaRecorder.onstop = () => {
  streamController.close();
};

4. WebRTC Data Channels (RTCDataChannel.send())

While WebRTC natively streams media using RTP tracks, recorded WebM blobs can also be sent directly over an established RTCDataChannel using SCTP/UDP.

  • Method: dataChannel.send(blob) or dataChannel.send(arrayBuffer)
  • Protocol: UDP (SCTP via DTLS)
  • Best for: Low-latency peer-to-peer transmissions or integration with Selective Forwarding Units (SFUs).
const peerConnection = new RTCPeerConnection(servers);
const dataChannel = peerConnection.createDataChannel('media-recording');
dataChannel.binaryType = 'arraybuffer';

mediaRecorder.ondataavailable = async (event) => {
  if (event.data.size > 0 && dataChannel.readyState === 'open') {
    const buffer = await event.data.arrayBuffer();
    dataChannel.send(buffer);
  }
};

Key Technical Considerations

  1. Initialization Metadata: The first WebM blob emitted by MediaRecorder contains the initialization segment (EBML header, Segment, and Track metadata). Subsequent chunks contain media Clusters. If a client connects mid-stream or chunks are processed out of order, the server or player requires the initial header chunk to decode subsequent frames.
  2. Backpressure: Network latency can cause data to accumulate faster than it can be transmitted. Monitor properties like WebSocket.bufferedAmount or RTCDataChannel.bufferedAmount to prevent memory bloat during connectivity drops.
