How WebM Coordinates with Matroska on Updates

The WebM format is an open-source, royalty-free multimedia container designed for the web that exists as a restricted subset of the broader Matroska (MKV) specification. To maintain compatibility and prevent fragmentation between the two formats, the WebM Project and the Matroska organization coordinate container updates through shared foundational architectures, cross-project developer collaboration, standardization within the Internet Engineering Task Force (IETF), and strict upstream synchronization rules.

Shared Architectural Foundation

WebM is built directly on Extensible Binary Meta Language (EBML), the binary equivalent of XML developed by the Matroska team. Because WebM uses the identical DocType syntax, structural rules, and base element identifiers as Matroska, the two container formats share the same core parsing logic.

When the WebM community identifies a need to expand or modify container capabilities, it does not invent an isolated container architecture. Instead, it works within the parameters of the underlying Matroska specification, restricting elements primarily to what is necessary for web-based streaming and playback.

Formal Standardization via the IETF

The primary formal venue for technical alignment between WebM and Matroska is the IETF CELLAR (Codec Encoding for Losslessly Archived Audio and Video) working group. The CELLAR working group is tasked with formally standardizing:

  • EBML (RFC 8794)
  • The Matroska container specifications
  • Related audio/video codec mappings

Engineers working on WebM—primarily from Google and partner organizations—participate directly in these IETF mailing lists, virtual meetings, and document drafts alongside independent Matroska maintainers. This ensures that any new element identifiers (Element IDs), data types, or structural modifications made to Matroska are reviewed by WebM stakeholders, and vice versa.

Upstream Alignment and Codec Integration

Whenever WebM expands to support modern codecs—such as the transition from VP8 and Vorbis to VP9, Opus, and AV1—coordination occurs upstream. The WebM Project does not define proprietary element IDs for standard container operations. Instead, it follows a strict sequence:

  1. Drafting Specifications: WebM engineers draft the codec mappings and required container headers.
  2. Matroska Review: The proposed mappings are submitted to the Matroska specification maintainers to ensure they align with Matroska's broader element definitions (such as CodecID values and CodecPrivate metadata).
  3. ID Allocation: Unique EBML IDs are officially reserved in the central Matroska registry to prevent collision with other MKV-specific features.
  4. Subset Definition: The WebM team publishes the implementation guidelines specifying which Matroska features remain valid inside a .webm file.

Tooling and Reference Implementations

Coordination also takes place through reference software libraries. Projects such as libwebm, libmatroska, and the Matroska reference tools (MKVToolNix) serve as testing grounds for shared compatibility. Maintainers from both communities regularly submit bug reports, patches, and conformance test suites across these repositories.

When new container behaviors, such as block addition mappings or HDR color metadata elements, are implemented, developers ensure that open-source demuxers like FFmpeg and browser engines (Chromium, Gecko) can parse the elements predictably regardless of whether the file carries an .mkv or .webm extension.

Subset Integrity and Compatibility Rules

A defining rule in the coordination between both groups is that all valid WebM files must remain valid Matroska files, but not all Matroska files are valid WebM files. The Matroska core team supports WebM’s need to disallow complex features—such as DVD-style menu systems, esoteric subtitles, and proprietary codecs—to optimize for lightweight web browsers.

By maintaining open communication through standard bodies and shared source repositories, both groups preserve this subset relationship: Matroska advances high-end archival and multimedia versatility, while WebM adopts only the streamlined features necessary for modern web delivery.
