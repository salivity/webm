VP9 Motion Vector Prediction Explained

This article explores the mathematical and algorithmic principles governing motion vector (MV) prediction across adjacent blocks in the WebM VP9 video codec. It examines spatial and temporal candidate derivation, vector coordinate clamping, sub-pixel representation, and the differential vector calculations used to optimize coding efficiency.

Spatial Neighborhood Modeling and Coordinate Geometry

VP9 determines motion vector predictors using a causal spatial neighborhood around the current coding block. When a block is located at coordinate \((x, y)\) with width \(W\) and height \(H\), its available neighbors are structurally defined as:

  • Left (\(A\)): Located at \((x - 1, y)\)
  • Above (\(B\)): Located at \((x, y - 1)\)
  • Above-Right (\(C\)): Located at \((x + W, y - 1)\)
  • Above-Left (\(D\)): Located at \((x - 1, y - 1)\)

Unlike older video formats that rely primarily on computing a spatial component-wise median \(\text{median}(MV_A, MV_B, MV_C)\), VP9 establishes an ordered search across these neighboring coordinates to build a primary candidate set. The algorithm categorizes predictors into two ordered reference candidates: NEARESTMV and NEARMV.

Candidate Selection and Reference Frame Matching

The selection of a predictor depends on matching reference frames. Each neighbor \(N \in \{A, B, C, D\}\) possesses a reference frame assignment \(R_N\) and a motion vector \(\vec{v}_N = (v_{x,N}, v_{y,N})\).

The mathematical condition for selecting a candidate vector \(\vec{v}\) to predict a target block using reference frame \(R_{target}\) is modeled as a conditional filter:

\[\text{Candidate}(\vec{v}_N) = \begin{cases} \vec{v}_N & \text{if } R_N = R_{target} \\ \emptyset & \text{otherwise} \end{cases}\]

If identical matches are found, duplicate elimination occurs:

\[\vec{v}_{candidate} \neq \vec{v}_{selected}\]

If fewer than two candidates match \(R_{target}\), the engine scans adjacent blocks that reference different reference frames and projects their vectors mathematically based on whether the frames are past or future references. If no valid candidates emerge, the default null vector is assigned:

\[\vec{v}_{zero} = (0, 0)\]

Temporal Motion Vector Projection

VP9 utilizes temporal motion vector prediction derived from the co-located block of a previously decoded frame. Let \((x, y)\) represent the current block coordinates in frame \(t\). The co-located motion vector in the reference frame \(t-1\) is \(\vec{v}_{col} = (v_{x,col}, v_{y,col})\).

When temporal prediction is active, the projected vector is evaluated against reference distances. The temporal candidate is incorporated into the prediction list if spatial candidates are exhausted or fail to match the target reference frame.

Differential Motion Vector Calculation

To minimize the bitstream overhead, VP9 does not signal the absolute motion vector \(\vec{v} = (v_x, v_y)\). Instead, it codes a motion vector difference (MVD), denoted as \(\Delta\vec{v}\):

\[\Delta\vec{v} = \vec{v} - \vec{v}_{pred}\]

\[\Delta v_x = v_x - v_{pred,x}, \quad \Delta v_y = v_y - v_{pred,y}\]

Here, \(\vec{v}_{pred}\) represents either NEARESTMV, NEARMV, or \(\vec{v}_{zero}\). The probability distribution of \(\Delta\vec{v}\) resembles a zero-mean Laplacian distribution:

\[P(\Delta v) = \frac{1}{2b} \exp\left(-\frac{|\Delta v|}{b}\right)\]

VP9 leverages context-adaptive Boolean entropy coding trees mapped directly to this distribution, minimizing coding cost when \(\|\Delta\vec{v}\|_1 \to 0\).

Vector Clamping and Boundary Arithmetic

Motion vectors must not reference pixels that extend excessively beyond the padded boundary of the reference frame. Let the frame boundaries be defined by \([0, W_{frame} - 1]\) and \([0, H_{frame} - 1]\). For a block positioned at \((x, y)\) with dimensions \(W \times H\), the permissible motion vector range is constrained by an interval clamping function:

\[\text{clamp}(a, \min, \max) = \max(\min, \min(a, \max))\]

The valid displacement components \(v_x\) and \(v_y\) are strictly bounded by:

\[v_{x,\min} = -(x + \text{BORDER\_OFFSET})\] \[v_{x,\max} = (W_{frame} - x - W) + \text{BORDER\_OFFSET}\] \[v_{y,\min} = -(y + \text{BORDER\_OFFSET})\] \[v_{y,\max} = (H_{frame} - y - H) + \text{BORDER\_OFFSET}\]

The final clamped prediction vector components are:

\[v_x' = \text{clamp}(v_x, v_{x,\min}, v_{x,\max})\] \[v_y' = \text{clamp}(v_y, v_{y,\min}, v_{y,\max})\]

Sub-Pixel Representation and Interpolation

VP9 motion vectors are represented mathematically with 1/8-pel precision. The stored coordinate is an integer scalar \(k \in \mathbb{Z}\) scaled such that:

\[\text{Displacement} = \frac{k}{8} \text{ pixels}\]

Any motion vector \(\vec{v}\) decomposes into an integer component and a fractional component:

\[\vec{v}_{int} = \left( \lfloor v_x / 8 \rfloor, \lfloor v_y / 8 \rfloor \right)\] \[\vec{v}_{frac} = (v_x \bmod 8, v_y \bmod 8)\]

The fractional phase index \(\phi = \vec{v}_{frac}\) selects one of eight sub-pixel 8-tap filter kernels \(H_\phi = [h_{-3}, h_{-2}, h_{-1}, h_0, h_1, h_2, h_3, h_4]\) to perform convolution:

\[S(x, y) = \sum_{i=-3}^{4} H_\phi(i) \cdot P(x + i, y)\]

where \(P\) is the reference pel and \(S\) is the interpolated prediction value. This fractional structure guarantees high spatial correlation between adjacent motion fields while constraining high-frequency interpolation artifacts.
