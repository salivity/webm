Handling Mixed Frame Dimensions in WebM Video

The WebM container specification handles video streams with mixed frame dimensions by pairing Matroska-based container headers with codecs that natively support in-band dynamic resolution changes, such as VP8, VP9, and AV1. While the container defines baseline or maximum dimensions at the track level, the actual resolution of each video frame is driven directly by the codec bitstream, allowing seamless dimension switching without restarting the stream.

Container-Level Configuration

At the container level, WebM is a subset of the Matroska (EBML) format. Within a WebM file, the TrackEntry element contains initial video configuration parameters:

  • PixelWidth and PixelHeight: These elements define the coded pixel dimensions of the initial frame or the maximum resolution expected across the stream. Decoders often use these initial values to allocate default memory buffers.
  • DisplayWidth and DisplayHeight: These optional elements specify the target aspect ratio for presentation, allowing players to scale frames correctly even when pixel aspect ratios vary.

The WebM container does not require a new track or file segment when frame dimensions change; it leaves mid-stream resolution changes to the coded video packets.

Codec-Level Resolution Signaling

Because WebM restricts video streams to codecs that natively support resolution switching, the heavy lifting of dynamic sizing happens inside the video payload:

  • VP8: Frame dimensions can be modified on any keyframe (intra-frame). The VP8 uncompressed frame header contains horizontal and vertical scale parameters along with the new pixel width and height.
  • VP9: VP9 expands resolution switching capabilities by allowing dimension updates not just on keyframes, but also on inter-frames through reference frame scaling. The VP9 bitstream signals new dimensions in the frame header, allowing the decoder to adapt on the fly.
  • AV1: AV1 includes explicit support for frame size overrides and reference frame scaling directly within its frame headers, allowing dynamic resolution transitions per frame without needing a sequence header reset.

Playback and Rendering Behavior

When a compliant WebM media player encounters a stream with mixed dimensions, the decoding pipeline dynamically resizes its frame buffers according to the bitstream header of the incoming packet. The rendering layer handles the resulting dimensional shifts in one of two ways:

  1. Canvas Resizing: The video player element resizes itself to match the new dimensions reported by the decoder.
  2. Viewport Scaling: The presentation window maintains a fixed size, and the renderer scales or letterboxes the dynamically sized frames to fit the active display area while preserving the specified aspect ratio.
