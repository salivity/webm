Transcode WebM to MP4 in Browser via WebAssembly

The native MediaRecorder API in modern browsers predominantly captures audio and video into WebM containers using VP8, VP9, or Opus codecs. Because many legacy media players, platforms, and Apple ecosystems prefer or require the MP4 (H.264/AAC) format, converting these recordings is often necessary. By leveraging WebAssembly (Wasm) ports of media processing engines such as FFmpeg, developers can transcode WebM output directly to MP4 entirely client-side, eliminating backend processing latency, bandwidth costs, and server overhead.

The Client-Side Transcoding Workflow

Transcoding MediaRecorder data to MP4 directly in the browser follows a clear five-step pipeline:

  1. Record media streams into WebM chunks.
  2. Combine chunks into a single WebM Blob.
  3. Load the WebAssembly FFmpeg instance into the browser.
  4. Pass the WebM data into the Wasm virtual file system.
  5. Execute the transcoding process and extract the generated MP4 file.

Step-by-Step Implementation

1. Capturing the Media Stream

Set up the MediaRecorder to record the audio or video stream from a source (such as getUserMedia or getDisplayMedia).

let recordedChunks = [];
const stream = await navigator.mediaDevices.getUserMedia({ video: true, audio: true });
const mediaRecorder = new MediaRecorder(stream, { mimeType: 'video/webm' });

mediaRecorder.ondataavailable = (event) => {
  if (event.data.size > 0) {
    recordedChunks.push(event.data);
  }
};

mediaRecorder.start();
// Later: mediaRecorder.stop();

2. Integrating FFmpeg.wasm

To transcode without a backend, integrate a WebAssembly build of FFmpeg, such as @ffmpeg/ffmpeg. Load the core script and initialize the engine:

import { FFmpeg } from '@ffmpeg/ffmpeg';
import { fetchFile } from '@ffmpeg/util';

const ffmpeg = new FFmpeg();

async function loadFFmpeg() {
  // Load the Wasm core files from a CDN or local assets
  await ffmpeg.load({
    coreURL: 'https://unpkg.com/@ffmpeg/core@0.12.6/dist/esm/ffmpeg-core.js',
    wasmURL: 'https://unpkg.com/@ffmpeg/core@0.12.6/dist/esm/ffmpeg-core.wasm'
  });
}

3. Executing the Transcode Command

Once recording finishes, convert the collected WebM chunks into a Blob, write them to the FFmpeg virtual file system, execute the command, and read the resulting output.

async function convertWebmToMp4() {
  const webmBlob = new Blob(recordedChunks, { type: 'video/webm' });
  const inputFileName = 'input.webm';
  const outputFileName = 'output.mp4';

  // Write the WebM blob to FFmpeg's memory file system
  await ffmpeg.writeFile(inputFileName, await fetchFile(webmBlob));

  // Run FFmpeg conversion command
  // Re-encodes VP8/VP9 video to H.264 and Opus to AAC
  await ffmpeg.exec([
    '-i', inputFileName,
    '-c:v', 'libx264',
    '-preset', 'ultrafast',
    '-c:a', 'aac',
    outputFileName
  ]);

  // Read the MP4 data from memory
  const data = await ffmpeg.readFile(outputFileName);

  // Clean up virtual files to free memory
  await ffmpeg.deleteFile(inputFileName);
  await ffmpeg.deleteFile(outputFileName);

  // Return the converted MP4 Blob
  return new Blob([data.buffer], { type: 'video/mp4' });
}

4. Handling the Resulting MP4

The generated MP4 Blob can now be downloaded or bound to an HTML <video> element:

const mp4Blob = await convertWebmToMp4();
const mp4Url = URL.createObjectURL(mp4Blob);

const downloadLink = document.createElement('a');
downloadLink.href = mp4Url;
downloadLink.download = 'recording.mp4';
downloadLink.click();

Performance Considerations

  • Encoder Preset: Re-encoding video in WebAssembly is CPU-intensive. Use -preset ultrafast or -preset veryfast to balance processing time and CPU load.
  • SharedArrayBuffer Support: Multi-threaded FFmpeg.wasm operations require cross-origin isolation. Ensure your server delivers the appropriate headers (Cross-Origin-Opener-Policy: same-origin and Cross-Origin-Embedder-Policy: require-corp).
  • Memory Limits: WebAssembly has maximum memory limits (typically 2GB to 4GB depending on the browser engine). Large recordings should be kept within memory constraints, or transcoded in segmented sequences.
