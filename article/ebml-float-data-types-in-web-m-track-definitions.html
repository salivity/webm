EBML Float Data Types in WebM Track Definitions

This article examines how the Extensible Binary Meta Language (EBML) represents floating-point numbers within WebM track definitions. It details the specific EBML Float data type, its underlying binary format standards, and the key track-level elements in WebM containers that rely on these data structures for accurate media playback.

The EBML Float Data Type

The Extensible Binary Meta Language (EBML) defines a native data type called Float (technically specified as EBML Float) to store real numbers. In the WebM container specification—which is a constrained subset of the Matroska format—all floating-point values are encoded using the standard IEEE 754 format in big-endian byte order.

EBML allows two specific byte lengths for the Float data type:

  • 4-Byte (32-Bit) Float: Represents a standard single-precision IEEE 754-1985 floating-point number.
  • 8-Byte (64-Bit) Float: Represents a standard double-precision IEEE 754-1985 floating-point number.

A WebM parser determines whether a float is single-precision or double-precision based on the length descriptor encoded in the element's EBML data size header.

Floating-Point Elements in WebM Track Definitions

Inside the TrackEntry master element (0xAE), most spatial dimensions and track identifiers are stored as unsigned integers (UInteger). However, specific elements governing audio timing and playback rates require fractional precision and strictly use the EBML Float type.

Audio Track Definitions

The primary use of the EBML Float type within WebM track definitions occurs inside the Audio master element (0xE1):

  • SamplingFrequency (Element ID 0xB5): Defines the sampling frequency of the audio stream in Hertz (Hz). It is stored as an EBML Float (defaulting to 8000.0 if not present) to accommodate standard fractional sample rates such as 44100.0 Hz or 48000.0 Hz, as well as non-integer rates.
  • OutputSamplingFrequency (Element ID 0x78B5): Defines the output sampling frequency in Hertz for audio that needs to be resampled during playback. Like SamplingFrequency, it is encoded as an EBML Float.

Video and Projection Settings

While standard video width and height use unsigned integers (PixelWidth and PixelHeight), advanced video metadata—such as spherical video projection coordinates or color mastering luminance parameters—can also use the EBML Float type when fractional precision is necessary to describe continuous physical properties.
