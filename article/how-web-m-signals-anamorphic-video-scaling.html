How WebM Signals Anamorphic Video Scaling

WebM signals anamorphic video scaling by defining display and pixel dimension metadata within its container-level video track headers. Because WebM is a restricted subset of the Matroska (MKV) format based on Extensible Binary Meta Language (EBML), it uses standardized Matroska elements to explicitly declare both the coded storage resolution and the target display aspect ratio. When a media player or browser rendering engine parses these container elements, it calculates the proper pixel aspect ratio (PAR) and rescales the decoded video frame to its intended geometry before presenting it on the screen.

The Core EBML Video Elements

Inside a WebM file, video streams are organized within the TrackEntry master element. Under the child Video element, WebM provides distinct parameters to separate the encoded storage dimensions from the display dimensions:

  • PixelWidth (EBML ID 0xB0): Defines the actual encoded horizontal resolution in raw video samples (e.g., 1440 pixels).
  • PixelHeight (EBML ID 0xBA): Defines the actual encoded vertical resolution in raw video samples (e.g., 1080 pixels).
  • DisplayWidth (EBML ID 0x54B0): Indicates the intended target width for rendering (e.g., 1920 pixels).
  • DisplayHeight (EBML ID 0x54BA): Indicates the intended target height for rendering (e.g., 1080 pixels).
  • DisplayUnit (EBML ID 0x54B2): Optional parameter that dictates how the display dimensions are measured. By default, a value of 0 denotes pixels, but it can also be configured to signal fixed display aspect ratios.

In standard non-anamorphic video using square pixels, PixelWidth equals DisplayWidth, and PixelHeight equals DisplayHeight. For anamorphic video, these values diverge. For example, a 16:9 widescreen video captured on a sensor using non-square pixels might be encoded at an anamorphic 1440x1080 storage resolution. The WebM container specifies PixelWidth as 1440 and PixelHeight as 1080, while setting DisplayWidth to 1920 and DisplayHeight to 1080.

Calculation and Rendering Pipeline

When a media pipeline (such as Chromium's media stack, FFmpeg, or GStreamer) plays a WebM file, the anamorphic scaling occurs through a sequential process:

  1. Demuxing and Metadata Extraction: The container parser reads the EBML track headers before decoding begins, capturing the pixel resolution and the display dimensions.
  2. Pixel Aspect Ratio Calculation: The rendering engine determines the scaling factor by comparing the ratios: \[\text{Display Aspect Ratio (DAR)} = \frac{\text{DisplayWidth}}{\text{DisplayHeight}}\] \[\text{Pixel Aspect Ratio (PAR)} = \text{DAR} \times \frac{\text{PixelHeight}}{\text{PixelWidth}}\]
  3. Decoding: The video decoder (VP8, VP9, or AV1) decodes the frames at their native PixelWidth by PixelHeight buffer size without performing any spatial distortion correction.
  4. Presentation Scaling: The rendering engine or video sink applies a hardware-accelerated scaling transformation (such as a bilinear or bicubic stretch) to scale the native frame buffers to the dimensions dictated by DisplayWidth and DisplayHeight, effectively restoring the true geometry of the content.

Container Metadata vs. Codec Bitstream

While underlying codecs like VP9 and AV1 can embed sample aspect ratio information directly inside their sequence headers, WebM prioritizes the container-level Matroska elements. Rendering engines typically evaluate the WebM container’s DisplayWidth and DisplayHeight tags as the authoritative source for final viewport layout, ensuring consistent playback even if bitstream-level signaling is missing or inconsistent.
