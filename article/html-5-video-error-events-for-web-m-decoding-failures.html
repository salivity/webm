HTML5 Video Error Events for WebM Decoding Failures

When an HTML5 <video> element fails to decode a WebM file, it triggers a standardized DOM error event and populates the media element's error property with a MediaError object. This guide covers the specific event emitted during a WebM decoding breakdown, the exact error codes assigned, how source tags alter event routing, and how to capture these failures programmatically.

The Primary Decode Error Event

When a WebM file is corrupted, truncated, or contains bitstream errors that the browser's media pipeline cannot process, the <video> element fires a single error event.

Simultaneously, the element assigns a MediaError object to the video.error property. For decoding failures, the code attribute of this object will always be:

  • MediaError.MEDIA_ERR_DECODE (Numeric value: 3)

This indicates that the browser recognized the WebM container format (Matroska-based) and initially validated the media resource, but encountered an unrecoverable error while decoding the underlying audio (Opus/Vorbis) or video (VP8, VP9, AV1) streams.

Secondary and Preceding Events

Before or alongside the error event, the browser pipeline may dispatch other state-change events depending on where the decode failure occurs during playback:

  • waiting / stalled: Fired if decoding halts mid-stream because the decoder is unable to parse subsequent frames.
  • abort: Fired if the media playback engine terminates decoding abruptly.
  • emptied: Fired when the media buffer is cleared following the fatal error state.

Direct Video Source vs. Child <source> Elements

The target of the error event depends on how the WebM resource is declared in HTML:

  1. Direct src attribute (<video src="video.webm">): The error event fires directly on the <video> element. The video.error.code is accessible and will return 3 (MEDIA_ERR_DECODE).
  2. Child <source> elements (<source src="video.webm" type="video/webm">): If decoding or loading fails at the source level, the error event fires on the individual <source> tag instead of the parent <video>. If all fallback sources fail, the <video> element then fires an error event with MediaError.MEDIA_ERR_SRC_NOT_SUPPORTED (code 4).

Handling WebM Decode Errors in JavaScript

To detect and handle a WebM decoding failure, attach an event listener to the video element and evaluate video.error:

const video = document.querySelector('video');

video.addEventListener('error', (event) => {
  const mediaError = video.error;

  if (mediaError) {
    switch (mediaError.code) {
      case MediaError.MEDIA_ERR_DECODE:
        console.error('WebM decode failed: Corrupted bitstream or unsupported codec profile.', mediaError.message);
        break;
      case MediaError.MEDIA_ERR_SRC_NOT_SUPPORTED:
        console.error('WebM format or codec is not supported by this browser.', mediaError.message);
        break;
      case MediaError.MEDIA_ERR_NETWORK:
        console.error('Network error interrupted WebM download.', mediaError.message);
        break;
      case MediaError.MEDIA_ERR_ABORTED:
        console.error('Playback aborted by user or script.', mediaError.message);
        break;
      default:
        console.error('An unknown media error occurred.', mediaError.message);
    }
  }
});

The mediaError.message property provides detailed, browser-specific diagnostic strings explaining the exact reason the WebM decoder crashed, such as an invalid cluster header, missing keyframe index, or malformed VP9 packet.
