Measure WebM Decode Latency Using JavaScript APIs

Measuring real-time latency when decoding WebM live streams in the browser requires capturing high-precision timing at various stages of the media pipeline. Developers primarily rely on the WebCodecs API for direct access to the decoding stage, the HTMLVideoElement.requestVideoFrameCallback() method for render-phase metrics, and the Performance API for high-resolution timestamps. Combining these interfaces allows applications to measure packet-to-frame duration, decode queuing delay, and end-to-end rendering latency accurately.

The WebCodecs API (VideoDecoder)

For granular, frame-by-frame measurement of the actual decoding stage, the WebCodecs API provides low-level control. When receiving a WebM container over WebSockets or Fetch/Streams, a demuxer extracts raw VP8, VP9, or AV1 chunks and passes them to a VideoDecoder instance.

  • Tracking Decode Duration: You can attach a high-resolution timestamp (performance.now()) to incoming EncodedVideoChunk objects. When the VideoDecoder emits the output VideoFrame, you compare the completion timestamp against the dispatch timestamp to compute raw decode time.
  • Queue Monitoring: The VideoDecoder.decodeQueueSize attribute indicates the number of pending decode requests, helping to identify processing bottlenecks before frames drop.

HTMLVideoElement.requestVideoFrameCallback()

When playing a WebM live stream using standard playback mechanisms—such as Media Source Extensions (MSE) with an HTML <video> element—requestVideoFrameCallback() (rVFC) provides accurate rendering and decode statistics directly from the browser's compositor.

The callback provides a VideoFrameCallbackMetadata dictionary containing critical latency properties:

  • processingDuration: The time (in seconds) taken from the submission of the encoded packet to the decoder until the frame was ready for display.
  • presentationTime: The timestamp indicating when the browser rendered or expects to render the frame.
  • expectedDisplayTime: The exact system time when the frame is targeted to be shown on screen.
  • captureTime: If populated by the source encoder, provides the exact capture timestamp, enabling full glass-to-glass latency calculations.

Media Source Extensions (MSE) Buffer Monitoring

When using SourceBuffer to append incoming WebM initialization and media segments, measuring the distance from the playback head to the live edge indicates buffer-induced latency:

  • Query the most recent buffered range using sourceBuffer.buffered.end(index).
  • Subtract HTMLMediaElement.currentTime from that end timestamp to determine the buffered latency currently queued ahead of the decoder.

The Performance API (performance.now())

Both WebCodecs and MSE rely on performance.now() from the High Resolution Time API. Because performance.now() provides monotonic, sub-millisecond precision unaffected by system clock adjustments, it acts as the reference clock to correlate network packet arrival, demuxing operations, WebCodecs output callbacks, and monitor refresh intervals.
