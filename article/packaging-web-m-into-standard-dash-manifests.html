Packaging WebM into Standard DASH Manifests

WebM containers can be fully packaged and streamed using standard Dynamic Adaptive Streaming over HTTP (DASH) manifests. Although DASH is most commonly associated with fragmented MP4 (fMP4) containers, the official DASH specification supports the WebM container format. This article explains how WebM integrates into DASH Media Presentation Description (MPD) manifests, how segmentation works with Matroska-based containers, and how to implement this workflow.

WebM Support in the DASH Specification

The MPEG-DASH standard (ISO/IEC 23009-1) is container-agnostic. While ISO Base Media File Format (ISOBMFF/fMP4) is the default deployment target in many commercial ecosystems, the standard formally defines the integration of other container profiles, including WebM.

The WebM Project created a dedicated specification mapping Matroska and WebM structures into standard DASH MPD manifests. This allows WebM video streams (encoded with VP8, VP9, or AV1) and WebM audio streams (encoded with Opus or Vorbis) to be partitioned into adaptive representations.

Manifest Representation

In a DASH manifest (.mpd), WebM streams are defined within standard AdaptationSet and Representation XML elements. The primary difference from an MP4-based DASH stream lies in the container-specific attributes:

  • MIME Type: Set to video/webm or audio/webm.
  • Codecs: Defined using standard codec identifiers (e.g., codecs="vp9" or codecs="opus").

A typical WebM Representation in an MPD uses the following structure:

<AdaptationSet mimeType="video/webm" codecs="vp9" subsegmentAlignment="true">
  <Representation id="vp9-720p" bandwidth="2000000" width="1280" height="720">
    <BaseURL>video_720p.webm</BaseURL>
    <SegmentBase indexRange="0-1024">
      <Initialization range="0-512"/>
    </SegmentBase>
  </Representation>
</AdaptationSet>

How WebM Segmentation Works

Unlike MP4, which segments data using movie fragment boxes (moof and mdat), WebM DASH uses Matroska EBML elements:

  1. Initialization Segment: Contains the EBML Header, Segment Info, and Tracks elements. It provides the decoder with layout, resolution, and codec information without containing any media frames.
  2. Media Segments / Subsegments: Composed of Matroska Cluster elements containing sequential SimpleBlock structures. Every segment or subsegment must start with a keyframe (I-frame) to ensure seamless track switching.

WebM DASH can be deployed in two segmentation models:

  • Single-file (Byte-Range): The entire representation resides in a single WebM file. The MPD manifest defines byte ranges (using SegmentBase and indexRange) for each segment.
  • Multi-file (Segment List/Template): The WebM file is physically cut into discrete chunks (e.g., segment_1.webm, segment_2.webm) fetched using SegmentTemplate declarations.

Packaging and Playback

Packaging Tools

Several production packagers support DASH-compliant WebM creation:

  • Shaka Packager: Natively parses WebM/VP9/AV1 inputs and outputs compliant WebM DASH manifests and segments.
  • FFmpeg: Supports native WebM DASH generation using the -f dash muxer alongside the WebM file format.

Playback

Client-side playback works through the HTML5 Media Source Extensions (MSE) API. Open-source players like Shaka Player and Dash.js support WebM-based DASH playback natively in modern web browsers (including Chrome, Firefox, and Edge) without requiring third-party plugins.
