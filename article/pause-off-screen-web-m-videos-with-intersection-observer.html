Pause Off-Screen WebM Videos with Intersection Observer

Modern web developers use the Intersection Observer API to monitor the visibility of media elements on a webpage asynchronously. By observing when a WebM video enters or exits the viewport, developers can automatically trigger play and pause actions. This article explains how the API works, why it is critical for performance optimization, and how to implement a clean JavaScript solution to pause off-screen WebM videos.

Why Pause Off-Screen Videos?

Autoplaying multiple WebM background videos or media feeds simultaneously can degrade browser performance, spike CPU and GPU usage, and drain mobile battery life. Decoding video frames consumes significant processing power. Pausing media when it is not visible frees up hardware resources and preserves bandwidth without disrupting the user experience.

The Mechanism Behind Intersection Observer

The Intersection Observer API replaces inefficient scroll event listeners and manual bounding-box calculations (Element.getBoundingClientRect()). It allows code to register a callback function that executes whenever an observed target element intersects with an ancestor element or the top-level document's viewport.

The observer operates asynchronously on the browser's main thread idle time, eliminating the jank and performance bottlenecks associated with continuous scroll-event polling.

Implementation Steps

Implementing automatic pause and play functionality requires three main steps: targeting the WebM video elements, configuring the observer, and handling media playback promises.

1. Define the HTML Video Element

Ensure your video element is configured with the standard attributes required for smooth autoplay handling across modern browsers:

<video class="observe-video" muted playsinline loop>
  <source src="animation.webm" type="video/webm">
  Your browser does not support the video tag.
</video>

2. Create the Observer in JavaScript

Initialize an IntersectionObserver instance that checks the isIntersecting property of each observed entry:

// Define the observer options
const observerOptions = {
  root: null, // Uses the browser viewport as the container
  rootMargin: '0px',
  threshold: 0.25 // Triggers when 25% of the video is visible
};

// Create the observer callback
const handleIntersection = (entries, observer) => {
  entries.forEach(entry => {
    const video = entry.target;

    if (entry.isIntersecting) {
      // Play video when entering the viewport
      const playPromise = video.play();
      if (playPromise !== undefined) {
        playPromise.catch(error => {
          // Autoplay policy prevented playback
          console.warn('Playback prevented:', error);
        });
      }
    } else {
      // Pause video immediately when leaving the viewport
      video.pause();
    }
  });
};

// Instantiate the observer
const videoObserver = new IntersectionObserver(handleIntersection, observerOptions);

// Target all relevant WebM videos and observe them
document.querySelectorAll('.observe-video').forEach(video => {
  videoObserver.observe(video);
});

Key Considerations for Production

  • Promise Handling: HTMLMediaElement.play() returns a Promise. Always catch potential rejection errors to handle browser autoplay policies or rapid viewport scrolling where a pause command interrupts a play request.
  • Muted Playback: Browsers typically restrict unmuted autoplay. Ensure off-screen WebM videos set the muted attribute so they resume seamlessly when scrolled back into view.
  • Threshold Selection: A threshold of 0 triggers immediately when a single pixel enters or exits, while higher values (e.g., 0.5) require half the video to be visible before playback starts.
