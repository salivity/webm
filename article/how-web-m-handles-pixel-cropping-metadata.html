How WebM Handles Pixel Cropping Metadata

WebM utilizes Matroska-based container-level metadata to define pixel cropping, allowing decoders and media players to display a custom viewport without modifying or re-encoding the raw video bitstream. By storing distinct pixel offset values within the video track header, WebM informs the rendering pipeline which edge pixels to discard before scaling the frame to its final display aspect ratio.

Container Hierarchy and Metadata Location

Because WebM is a subset of the Matroska (MKV) multimedia container format, it inherits the Matroska EBML (Extensible Binary Meta Language) structure. Video track configuration is housed within the Tracks master element.

Specifically, pixel cropping metadata is nested inside the Video settings element of a given TrackEntry:

Segment ➔ Tracks ➔ TrackEntry ➔ Video

The Pixel Cropping Elements

WebM defines four unsigned integer elements to control the display window boundaries:

  • PixelCropTop (0x54BB): The number of video pixels to remove from the top of the decoded frame.
  • PixelCropBottom (0x54AA): The number of video pixels to remove from the bottom of the decoded frame.
  • PixelCropLeft (0x54CC): The number of video pixels to remove from the left side of the decoded frame.
  • PixelCropRight (0x54DD): The number of video pixels to remove from the right side of the decoded frame.

If any of these elements are omitted from the WebM header, their values default to 0, indicating that no cropping should occur on that particular edge.

Rendering Pipeline and Display Calculations

When a WebM player renders a video file with pixel cropping metadata, it executes the following pipeline:

  1. Decoding: The video frame is decoded at its native coded resolution, defined by PixelWidth and PixelHeight.
  2. Cropping: The player calculates the visible viewing area: \[\text{Visible Width} = \text{PixelWidth} - (\text{PixelCropLeft} + \text{PixelCropRight})\] \[\text{Visible Height} = \text{PixelHeight} - (\text{PixelCropTop} + \text{PixelCropBottom})\]
  3. Scaling: The resulting cropped region is mapped and scaled to match the intended presentation dimensions specified by the DisplayWidth, DisplayHeight, and DisplayUnit elements.

Primary Use Cases

  • Encoder Padding Removal: Video codecs often require frame dimensions to be multiples of 8 or 16 (macroblock boundaries). Pixel cropping allows encoders to pad an odd-sized video during compression and instruct the player to crop out the padding during playback.
  • Aspect Ratio Adjustments: Non-destructive cropping of letterbox bars (black bars) or pillarbox areas.
  • Clean Aperture Definition: Eliminating edge artifacts or analog blanking lines without altering the underlying compressed VP8, VP9, or AV1 video streams.
