WebM Video Frame Default Duration Parameters

WebM relies on specific Matroska-derived container-level elements to specify the timing and default duration of video frames. At the core of this system are the DefaultDuration parameter located within the track header and the TimestampScale parameter defined in the segment information header. Together, these values establish the base timing grid and nominal frame rate for playback engines and decoders.

The DefaultDuration Element

The primary container-level parameter defining the default duration of a video frame in WebM is the DefaultDuration element (EBML ID: 0x23E383).

  • Location: Segment > Tracks > TrackEntry
  • Units: Nanoseconds (ns)
  • Function: It specifies the expected duration of a single frame (or block) in nanoseconds.

For fixed frame rate (CFR) video, players use this value to calculate the nominal frame rate: \[\text{Frame Rate (FPS)} = \frac{1,000,000,000}{\text{DefaultDuration}}\]

For example, a video intended to play at 24 frames per second (fps) will set DefaultDuration to approximately 41666666 nanoseconds (1,000,000,000 / 24). For 60 fps, it will be set to 16666666 nanoseconds.

The TimestampScale Element

While DefaultDuration dictates the length of an individual frame, container timestamps themselves are scaled by the TimestampScale element (EBML ID: 0x2AD7B1, historically named TimecodeScale).

  • Location: Segment > Info
  • Units: Nanoseconds (ns)
  • Default Value: 1,000,000 (which equals 1 millisecond)
  • Function: Acts as the multiplier to convert relative block timestamps (stored in integers) into real-time nanoseconds.

The playback timestamp of a frame is calculated as: \[\text{Absolute Timestamp} = \text{Block Timestamp} \times \text{TimestampScale}\]

Frame Timing Priority and Overrides

WebM supports both Constant Frame Rate (CFR) and Variable Frame Rate (VFR) media through a tiered timing system:

  1. DefaultDuration as a Baseline: If blocks do not explicitly carry individual duration metadata, the player defaults to the value set in DefaultDuration.
  2. Explicit Block Timing: WebM uses SimpleBlock and BlockGroup structures to hold encoded video data. Each block contains an explicit relative timestamp. If successive block timestamps differ from DefaultDuration, the explicit delta between timestamps dictates the actual display timing (supporting VFR).
  3. BlockDuration Element: When using BlockGroup rather than SimpleBlock, an optional BlockDuration element (EBML ID: 0x8B) can be present to explicitly declare the exact duration of a specific frame, overriding the track's DefaultDuration for that instance.
