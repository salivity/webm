How the WebM Video Specification Is Maintained

The WebM specification is maintained and updated through a collaborative open-source model led by Google in conjunction with independent developers, browser vendors, and multimedia working groups. By relying on a restricted subset of the Matroska (MKV) container format alongside standardized open-source codecs—such as VP8, VP9, AV1, Vorbis, and Opus—the community updates the format via public code repositories, standards body alignment, and structured peer-review processes.

Stewardship and Governance

Google launched the WebM Project in 2010 under a permissive BSD-style license, providing the initial foundation for the container and codec implementations. While Google provides engineering resources and infrastructure, governance functions as an open-source collaboration. Technical steering occurs through open developer mailing lists, public issue trackers, and direct contributions from browser vendors like Mozilla and multimedia software teams like FFmpeg and VLC.

Matroska and IETF CELLAR Working Group Alignment

Because the WebM container is fundamentally a profile of the Matroska format, changes to the WebM container architecture are closely tied to the Matroska specification. The underlying EBML (Extensible Binary Meta Language) and Matroska specifications are standardized through the Internet Engineering Task Force (IETF) CELLAR (Codec Encoding for LossLess Archiving and Real-time transmission) Working Group. When new structural elements or metadata fields are proposed for WebM, they must comply with or expand upon the Matroska standard to prevent ecosystem fragmentation.

Codec Integration and Evolution

WebM’s capability expands primarily through the integration of newer, more efficient audio and video codecs. Updates to support next-generation codecs follow established industry standards:

  • Video Codecs: Updates to video capabilities—such as transitioning from VP8 to VP9, and later adopting AV1—are coordinated with the Alliance for Open Media (AOMedia) to ensure bitstream specifications and container mappings are standardized.
  • Audio Codecs: Integration and updates for audio formats, notably Vorbis and Opus, are coordinated through specifications defined by the Xiph.Org Foundation and standardized via the IETF.

Code Repositories and Patch Reviews

The reference implementations—primarily libwebm for container muxing/demuxing and libvpx or libaom for video encoding—are hosted on public Git repositories. Maintenance follows a standard patch-review lifecycle:

  1. Proposal and Implementation: Developers submit feature requests, bug fixes, or spec amendments via the project's issue tracker or code review tools (such as Gerrit).
  2. Automated Testing: Continuous Integration (CI) pipelines test code against regression suites to ensure backward compatibility with existing decoders.
  3. Peer Review: Core maintainers evaluate the patch for compliance with the WebM container guidelines, memory safety, and performance.
  4. Integration: Approved changes are merged into the main tree and tagged in official library releases.

Documentation and Public Releases

Once changes are validated in reference libraries, the official documentation hosted on the WebM Project website is updated. These updates specify byte-level requirements, container constraints (such as restricted DocType and element exclusions compared to full Matroska), and guidelines for hardware and software implementers to maintain universal interoperability across the web.
