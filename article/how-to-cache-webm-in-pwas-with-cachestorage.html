How to Cache WebM in PWAs with CacheStorage

Progressive Web Apps (PWAs) leverage Service Workers and the CacheStorage API to enable offline media playback and reduce network latency. This guide explains how to effectively store, manage, and serve WebM audio and video assets using the CacheStorage API, while addressing key technical requirements such as runtime caching and handling HTTP partial range requests for smooth media streaming.

Understanding CacheStorage for Media Files

The CacheStorage API stores paired Request and Response objects in the browser's persistent storage. While commonly used for HTML, CSS, and JavaScript, it can store binary large objects (BLOBs), including WebM media containers (video/webm or audio/webm).

When caching WebM files, you generally use one of two caching strategies:

  • Precaching: Storing critical, short WebM assets (such as UI sound effects or short looping background videos) during the Service Worker install event.
  • Runtime Caching: Capturing and storing WebM assets dynamically on-demand as users stream or download them during app execution.

Step 1: Precaching Static WebM Assets

For essential media assets required immediately upon application load, cache them during the service worker installation phase:

const CACHE_NAME = 'media-cache-v1';
const STATIC_WEBM_ASSETS = [
  '/media/intro.webm',
  '/media/notification.webm'
];

self.addEventListener('install', (event) => {
  event.waitUntil(
    caches.open(CACHE_NAME).then((cache) => {
      return cache.addAll(STATIC_WEBM_ASSETS);
    })
  );
});

Step 2: Implementing Runtime Caching for WebM Files

Large WebM files are better cached dynamically during fetch requests to prevent slow installation times and unnecessary storage consumption:

self.addEventListener('fetch', (event) => {
  const url = new URL(event.request.url);

  if (url.pathname.endsWith('.webm')) {
    event.respondWith(
      caches.open(CACHE_NAME).then(async (cache) => {
        const cachedResponse = await cache.match(event.request);
        if (cachedResponse) {
          return cachedResponse;
        }

        const networkResponse = await fetch(event.request);
        if (networkResponse.status === 200) {
          cache.put(event.request, networkResponse.clone());
        }
        return networkResponse;
      })
    );
  }
});

Step 3: Handling Range Requests (HTTP 206)

Browsers request media assets like WebM using HTTP Range headers to support seeking and progressive buffering. By default, the CacheStorage API stores complete 200 OK responses and does not natively slice partial content out of the box for 206 Partial Content requests.

To serve a cached WebM file when a browser sends a Range request:

  1. Retrieve the complete 200 OK Response object from the cache.
  2. Read the binary data as an ArrayBuffer.
  3. Parse the Range header from the request (e.g., bytes=0-1048575).
  4. Slice the ArrayBuffer according to the requested byte offsets.
  5. Return a new Response with status 206 Partial Content, containing the sliced buffer, the matching Content-Range header, and the correct Content-Length.
async function handleRangeRequest(request, cache) {
  const fullResponse = await cache.match(request.url);
  if (!fullResponse) {
    return fetch(request);
  }

  const rangeHeader = request.headers.get('range');
  if (!rangeHeader) {
    return fullResponse;
  }

  const arrayBuffer = await fullResponse.arrayBuffer();
  const bytes = rangeHeader.replace(/bytes=/, '').split('-');
  const start = parseInt(bytes[0], 10);
  const end = bytes[1] ? parseInt(bytes[1], 10) : arrayBuffer.byteLength - 1;

  const slicedBuffer = arrayBuffer.slice(start, end + 1);

  return new Response(slicedBuffer, {
    status: 206,
    statusText: 'Partial Content',
    headers: {
      'Content-Type': fullResponse.headers.get('Content-Type') || 'video/webm',
      'Content-Range': `bytes ${start}-${end}/${arrayBuffer.byteLength}`,
      'Content-Length': slicedBuffer.byteLength,
      'Accept-Ranges': 'bytes'
    }
  });
}

Best Practices for WebM Storage

  • Storage Quotas: WebM files can rapidly consume disk space. Use navigator.storage.estimate() to inspect available quota before attempting to cache large video files.
  • Cache Invalidation: Regularly clean up outdated WebM files by listening to the activate event and deleting obsolete cache versions with caches.delete().
  • CORS Handling: When fetching WebM files from external CDNs, ensure the server returns appropriate Access-Control-Allow-Origin headers. Caching opaque responses (mode: 'no-cors') significantly bloats storage quota calculations and prevents reading response headers.
