Record WebGL Scenes to WebM with MediaRecorder API

Capturing smooth, high-framerate WebGL animations directly in the browser allows developers to export interactive 3D canvas content into efficient WebM video files without server-side rendering. By pairing the HTMLCanvasElement.captureStream() method with the MediaRecorder API, you can record hardware-accelerated scenes at a locked frame rate such as 60 FPS. This article covers how to extract the canvas stream, configure the recorder for WebM output, handle frame rendering to prevent stutter, and export the final video blob.

1. Capture the WebGL Canvas Stream

The foundation of recording a WebGL scene is captureStream(). This method creates a continuous MediaStream from the rendered <canvas> element.

const canvas = document.querySelector('canvas');
const targetFPS = 60;
const stream = canvas.captureStream(targetFPS);

Passing a specific frame rate (e.g., 60) requests that the browser capture frames at that fixed interval. Note that in WebGL contexts, ensure your WebGL context attributes do not clear the drawing buffer prematurely if you sample frames asynchronously:

const gl = canvas.getContext('webgl2', { preserveDrawingBuffer: true });

2. Configure the MediaRecorder for WebM

Initialize the MediaRecorder instance using the captured stream. To ensure maximum quality and cross-platform playback within modern browsers, specify a WebM MIME type with VP9 or VP8 codecs and set an adequate bitrate.

const mimeTypes = [
  'video/webm;codecs=vp9',
  'video/webm;codecs=vp8',
  'video/webm'
];

const selectedMimeType = mimeTypes.find(type => MediaRecorder.isTypeSupported(type));

const options = {
  mimeType: selectedMimeType,
  videoBitsPerSecond: 8000000 // 8 Mbps for high fidelity
};

const recorder = new MediaRecorder(stream, options);

3. Handle Data Buffering and Export

The MediaRecorder outputs recorded data in chunks via the ondataavailable event. Collect these chunks in an array, then aggregate them into a single Blob when recording stops.

const recordedChunks = [];

recorder.ondataavailable = (event) => {
  if (event.data && event.data.size > 0) {
    recordedChunks.push(event.data);
  }
};

recorder.onstop = () => {
  const blob = new Blob(recordedChunks, { type: selectedMimeType });
  const videoUrl = URL.createObjectURL(blob);

  // Trigger automatic download
  const a = document.createElement('a');
  a.href = videoUrl;
  a.download = `webgl-recording-${Date.now()}.webm`;
  a.click();

  URL.revokeObjectURL(videoUrl);
};

4. Maintain Consistent Framerates During Recording

Real-time recording using requestAnimationFrame can drop frames if the GPU or CPU throttles under load. To guarantee a high-framerate output:

  1. Avoid Zero-Argument Streams: When using canvas.captureStream(0), the stream only captures a new frame when you explicitly call stream.getVideoTracks()[0].requestFrame(). This allows for deterministic, frame-by-frame offline rendering.
  2. Fixed Time Steps: Update your WebGL physics and animations using a fixed delta time (e.g., 1 / 60) rather than wall-clock time (performance.now()). This ensures that even if a frame takes longer than 16.6ms to compute, the resulting video remains at a stable 60 FPS.

Complete Implementation

function startRecording(canvas, durationInSeconds) {
  const stream = canvas.captureStream(60);
  const options = {
    mimeType: 'video/webm;codecs=vp9',
    videoBitsPerSecond: 8000000
  };

  const recorder = new MediaRecorder(stream, options);
  const chunks = [];

  recorder.ondataavailable = (e) => {
    if (e.data.size > 0) chunks.push(e.data);
  };

  recorder.onstop = () => {
    const completeBlob = new Blob(chunks, { type: options.mimeType });
    const downloadLink = document.createElement('a');
    downloadLink.href = URL.createObjectURL(completeBlob);
    downloadLink.download = 'render.webm';
    downloadLink.click();
  };

  recorder.start();

  setTimeout(() => {
    recorder.stop();
  }, durationInSeconds * 1000);
}
