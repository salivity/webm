Mapping Opus Audio to WebM SimpleBlock Elements

This article explains how Opus-encoded audio frames are encapsulated within WebM SimpleBlock structures. It outlines the container architecture, the binary layout of the SimpleBlock header, and the exact process of packing raw Opus packets—including timestamp assignment, keyframe signaling, and lacing constraints—into WebM containers.

WebM and Opus Container Context

WebM is a restricted subset of the Matroska (EBML) container format. When storing Opus audio in WebM, the track's CodecID EBML element is set to A_OPUS. The track initialization header contains a CodecPrivate element that holds the standard 19-byte OpusHead structure (defining channel counts, pre-skip values, and original sample rates). Once the track is initialized, the actual compressed audio stream is divided into individual Opus packets and wrapped directly inside WebM SimpleBlock elements.

The Structure of a WebM SimpleBlock

A WebM SimpleBlock consists of a short binary header followed immediately by the audio payload. Its binary structure is organized as follows:

  1. Element ID & Size: The EBML ID 0xA3 identifies the SimpleBlock, followed by a variable-length integer (VINT) specifying the total size of the block data.
  2. Track Number: An EBML VINT identifying the audio track to which this block belongs.
  3. Relative Timecode: A 16-bit signed big-endian integer representing the block's timestamp relative to the parent Cluster timecode, calculated using the track's TimestampScale.
  4. Flags Byte: An 8-bit field defining block characteristics:
    • Bit 0 (MSB): Keyframe flag (1 for keyframe, 0 otherwise).
    • Bits 1–3: Reserved (must be 0).
    • Bit 4: Invisible / non-displayable flag.
    • Bits 5–6: Lacing flags (00 = No lacing, 01 = Xiph lacing, 10 = Fixed-size lacing, 11 = EBML lacing).
    • Bit 7 (LSB): Discardable flag.
  5. Payload: The raw audio data.

Packet Mapping and Encapsulation Rules

Mapping an Opus packet into this structure involves specific rules defined by the WebM Opus specification:

  • Direct Payload Insertion: Unlike Ogg encapsulation, WebM does not wrap Opus packets with Ogg page headers. The raw Opus packet—starting with its Table of Contents (TOC) byte followed by the compressed frame data—is placed directly into the payload section of the SimpleBlock.
  • One Packet Per Block (No Lacing): Although Matroska supports lacing multiple audio frames into one block, WebM guidelines mandate that each SimpleBlock should contain exactly one Opus packet with the lacing flag bits set to 00.
  • Keyframe Designation: Because Opus frames depend on internal prediction states, they do not function as independent visual keyframes. However, within WebM, the keyframe bit (Bit 0 of the Flags byte) on an Opus SimpleBlock is set to 1 (marking the block as 0x80 if no other flags are set).
  • Duration and Timestamps: The SimpleBlock format does not have an explicit duration field. The duration of the audio inside the block is determined directly by decoding the frame configuration inside the Opus TOC byte (ranging from 2.5 ms to 120 ms). The block's presentation timestamp indicates the playback time of the first sample in that packet.
  • Pre-Skip and Padding: Audio encoders insert priming samples (pre-skip) at the beginning of an Opus stream. While the initial pre-skip is defined globally in the CodecPrivate element, sample-exact end trimmings or seek-point adjustments use Matroska's DiscardPadding element (typically found inside a BlockGroup rather than a standalone SimpleBlock).
