How to Set WebM Bitrate, Minrate, and Maxrate in FFmpeg

This article provides a straightforward guide on configuring constrained bitrate encoding for WebM files using FFmpeg. You will learn the exact flags required to define target bitrate, minimum bitrate, and maximum bitrate using the libvpx-vp9 and libvpx codecs. The guide also covers two-pass encoding workflows and constrained quality (CQ) mode to ensure predictable bandwidth consumption without sacrificing visual fidelity.

Core FFmpeg Flags for Bitrate Control

When encoding WebM video (primarily using VP9 or VP8), bitrate boundaries are controlled via three primary video flags:

  • -b:v: Sets the target average video bitrate.
  • -minrate: Sets the minimum allowed bitrate.
  • -maxrate: Sets the maximum peak bitrate.
  • -crf: Sets a constant quality ceiling (optional, used in Constrained Quality mode).

Method 1: Two-Pass Constrained Bitrate Encoding (VP9)

For the libvpx-vp9 codec, two-pass encoding is strongly recommended. It enables the encoder to analyze the entire video first to optimize bit allocation within your defined constraints.

Pass 1:

ffmpeg -i input.mp4 -c:v libvpx-vp9 -b:v 2M -minrate 1M -maxrate 3M -pass 1 -an -f null /dev/null

(On Windows, replace /dev/null with NUL)

Pass 2:

ffmpeg -i input.mp4 -c:v libvpx-vp9 -b:v 2M -minrate 1M -maxrate 3M -pass 2 -c:a libopus -b:a 128k output.webm

Flag breakdown:

  • -b:v 2M: The average bitrate will aim for 2000 kbps.
  • -minrate 1M: Bitrate will not drop below 1000 kbps during simple scenes.
  • -maxrate 3M: Bitrate will not exceed 3000 kbps during complex or fast-moving scenes.
  • -c:a libopus: Standard high-efficiency audio codec for WebM containers.

Method 2: Constrained Quality (CQ) Mode

Constrained Quality mode uses a CRF (Constant Rate Factor) target while enforcing an upper and lower bitrate limit. This prevents high-motion scenes from exceeding bandwidth caps while allowing low-motion scenes to use fewer bits efficiently.

Pass 1:

ffmpeg -i input.mp4 -c:v libvpx-vp9 -crf 30 -b:v 2M -minrate 500k -maxrate 2.5M -pass 1 -an -f null /dev/null

Pass 2:

ffmpeg -i input.mp4 -c:v libvpx-vp9 -crf 30 -b:v 2M -minrate 500k -maxrate 2.5M -pass 2 -c:a libopus -b:a 128k output.webm

Note: For VP9, -crf values range from 0 to 63 (recommended values: 15–35). In CQ mode, -b:v acts as an upper limit if not paired with -maxrate, but explicitly defining -maxrate guarantees strict bandwidth adherence.

Method 3: Legacy VP8 WebM Encoding

If you are targeting older browsers that do not support VP9, use the libvpx encoder. The syntax remains identical:

ffmpeg -i input.mp4 -c:v libvpx -b:v 1500k -minrate 750k -maxrate 2000k -c:a libvorbis -b:a 128k output.webm

Key Recommendations

  • Always use two passes for standard VBR/CBR: VP9 requires two passes to accurately respect -minrate and -maxrate limits.
  • Buffer control: If streaming over variable networks, the standard practice is to keep -maxrate within 1.5x to 2x of -b:v to prevent buffering issues.
