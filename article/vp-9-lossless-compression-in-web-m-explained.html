VP9 Lossless Compression in WebM Explained

WebM achieves lossless video compression by pairing the Matroska-based container format with the VP9 video codec configured in its dedicated lossless mode. By bypassing standard frequency transforms and quantization stages, VP9 allows exact mathematical reconstruction of source frames while utilizing intra-prediction, inter-prediction, and arithmetic entropy coding to reduce file sizes. This article details the internal mechanics of VP9 lossless encoding, color space requirements, and how the WebM container encapsulates the resulting data stream.

Transform Bypass and Zero-Quantization

In conventional lossy VP9 encoding, video frames are divided into blocks, transformed using the Discrete Cosine Transform (DCT) or Asymmetric Discrete Sine Transform (ADST), and then quantized to discard imperceptible visual data.

To achieve lossless compression, the encoder sets the quantization parameter to zero (qp = 0 or --lossless=1). When lossless mode is activated, VP9 completely bypasses the transform and quantization pipelines:

  1. Prediction: The encoder generates spatial (intra) or temporal (inter) predictions for each block to identify redundancy.
  2. Residual Generation: The predicted values are subtracted from the actual pixel values, generating a residual error matrix.
  3. Direct Coding: Instead of converting these residuals into frequency coefficients via DCT/ADST, the raw residual values are fed directly into the entropy encoder.

Entropy Coding with the VP9 Boolean Engine

Because the transform step is omitted, all compression gains in lossless mode rely entirely on VP9's prediction accuracy and its native entropy coder. VP9 uses an 8-bit precision non-adaptive boolean arithmetic coder.

The arithmetic engine encodes the exact prediction residuals using probability models optimized for raw spatial domain differences rather than transform-domain coefficient tokens. This ensures that every bit of pixel data is preserved without precision loss or rounding artifacts.

Color Formats and VP9 Profiles

True mathematical losslessness requires preserving the original color representation. VP9 implements lossless encoding across different profiles depending on the chroma format:

  • Profile 0: Supports 8-bit color with 4:2:0 chroma subsampling. While the compression of the 4:2:0 stream is mathematically lossless, converting an RGB or 4:4:4 source to 4:2:0 prior to encoding results in visual information loss.
  • Profile 1: Supports 8-bit color with 4:4:4 chroma subsampling and native RGB color spaces, enabling fully lossless compression for screen captures, graphic content, and master archives without color degradation.
  • Profiles 2 and 3: Extend these capabilities to 10-bit and 12-bit high bit-depth content for 4:2:0 (Profile 2) and 4:4:4/RGB (Profile 3).

WebM Container Encapsulation

The WebM container manages lossless VP9 streams seamlessly because the lossless state is defined entirely within the VP9 bitstream rather than through specialized container-level metadata.

Inside the WebM file, the video track is assigned the standard codec identifier V_VP9. In the bitstream, the VP9 uncompressed frame header contains a lossless_flag that signals the decoder to bypass the inverse transform and dequantization steps for that frame or segment. As a result, standard WebM parsers and decoders process lossless VP9 tracks without requiring custom container extensions or separate stream definitions.
