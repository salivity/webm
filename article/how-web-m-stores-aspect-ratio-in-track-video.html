How WebM Stores Aspect Ratio in TrackVideo

The WebM container format stores aspect ratio and geometry metadata inside the TrackVideo element using a combination of pixel resolution and display dimension tags. Instead of writing a single static aspect ratio value, WebM relies on separate fields for coded storage dimensions (PixelWidth and PixelHeight) and rendered output dimensions (DisplayWidth and DisplayHeight). This structure allows media decoders and players to correctly handle both standard square-pixel video and anamorphic content requiring non-square Pixel Aspect Ratios (PAR).

The TrackVideo EBML Structure

WebM is based on the Extensible Binary Meta Language (EBML), a binary equivalent of XML derived from the Matroska specification. Track configurations are organized in the following hierarchy:

  • Segment
    • Tracks
      • TrackEntry
        • Video (also referred to as TrackVideo)

All video scaling, resolution, and aspect ratio metadata is contained within this Video sub-element.

Key Elements Defining Aspect Ratio

Inside the TrackVideo element, three pairs of parameters determine the final rendered aspect ratio:

1. Storage Dimensions (Pixel Geometry)

  • PixelWidth (ID 0xB0): Defines the coded width of the video in physical pixels (e.g., 1920).
  • PixelHeight (ID 0xBA): Defines the coded height of the video in physical pixels (e.g., 1080).

These fields represent the raw buffer size output by the video decoder before scaling.

2. Display Dimensions (Target Output)

  • DisplayWidth (ID 0x54B0): The intended width of the video image upon playback.
  • DisplayHeight (ID 0x54BA): The intended height of the video image upon playback.

If DisplayWidth or DisplayHeight are omitted, their values automatically default to the corresponding PixelWidth and PixelHeight values.

3. Display Unit Definition

  • DisplayUnit (ID 0x54B2): Specifies the measurement unit used for DisplayWidth and DisplayHeight. The standard values include:
    • 0: Pixels (Default)
    • 1: Centimeters
    • 2: Inches
    • 3: Display Aspect Ratio (DAR)

When DisplayUnit is set to 0 (pixels), the values are treated as a target resolution for playback scaling. When set to 3, DisplayWidth and DisplayHeight act purely as a ratio (e.g., 16 and 9).

How Players Compute the Aspect Ratio

A WebM-compliant player evaluates these elements to calculate the Display Aspect Ratio (DAR) and Pixel Aspect Ratio (PAR):

  1. Display Aspect Ratio (DAR): Calculated directly as: \[\text{DAR} = \frac{\text{DisplayWidth}}{\text{DisplayHeight}}\]
  2. Pixel Aspect Ratio (PAR): Calculated by comparing the display ratio to the storage pixel ratio: \[\text{PAR} = \frac{\text{DisplayWidth} \times \text{PixelHeight}}{\text{DisplayHeight} \times \text{PixelWidth}}\]

Example: Anamorphic Video

For an anamorphic DVD stream encoded into WebM:

  • PixelWidth: 720
  • PixelHeight: 480
  • DisplayWidth: 16 (or 854 if using pixel units)
  • DisplayHeight: 9 (or 480 if using pixel units)
  • DisplayUnit: 3 (Aspect Ratio)

The player decodes the 720x480 frame buffer but stretches the rendering canvas to match the 16:9 ratio indicated by the DisplayWidth and DisplayHeight values.
