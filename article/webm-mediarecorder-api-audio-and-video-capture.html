WebM MediaRecorder API Audio and Video Capture

The WebM MediaRecorder API allows web applications to capture, encode, and record live multimedia streams directly inside a browser without external plugins. This article explains the underlying mechanism of this process, from accessing the user's camera and microphone using standard Web APIs, to encoding raw media frames into the WebM format (typically using VP8/VP9 for video and Opus for audio), and finally extracting the recorded binary data chunks for storage or streaming.

1. Acquiring the Media Stream

The recording process begins with obtaining access to the physical input devices. The browser utilizes the navigator.mediaDevices.getUserMedia() method, which prompts the user for permission to use their camera and microphone.

When permission is granted, the browser returns a MediaStream object. This stream is a synchronization container composed of individual MediaStreamTrack instances—one track for the video input (camera) and one track for the audio input (microphone).

2. Initializing the MediaRecorder

Once the MediaStream is active, it is passed into a new instance of the MediaRecorder interface. During initialization, the target format is defined via the mimeType configuration property, such as video/webm;codecs=vp8,opus or video/webm;codecs=vp9,opus.

const stream = await navigator.mediaDevices.getUserMedia({ video: true, audio: true });
const options = { mimeType: 'video/webm; codecs=vp9,opus' };
const mediaRecorder = new MediaRecorder(stream, options);

3. Encoding and Muxing Pipeline

After mediaRecorder.start() is called, the browser begins processing the live data through an internal pipeline:

  • Frame Capture: The browser grabs raw video frames (typically YUV format) from the camera sensor at the stream's specified frame rate and resolution.
  • Audio Sampling: The microphone input is converted into raw PCM audio samples.
  • Encoding: The browser passes the raw video data to a video encoder (such as VP8, VP9, or AV1) and the raw audio data to an audio encoder (typically Opus). Hardware acceleration is utilized if supported by the client device.
  • Muxing: The encoded video and audio bitstreams are packaged together inside the WebM container format (a subset of the Matroska/EBML container structure).

4. Handling Recorded Data Chunks

The MediaRecorder interface does not store the entire recording in memory as a single object. Instead, it emits ondataavailable events containing encoded binary segments as Blob objects.

If a timeslice argument is passed to mediaRecorder.start(timeslice) (e.g., 1000 milliseconds), the ondataavailable event fires periodically at that interval. This is useful for streaming the WebM chunks over a WebSocket or uploading them incrementally. If no timeslice is specified, the event fires once when recording stops.

const recordedChunks = [];

mediaRecorder.ondataavailable = (event) => {
  if (event.data.size > 0) {
    recordedChunks.push(event.data);
  }
};

5. Finalizing the WebM File

When mediaRecorder.stop() is invoked, the recorder flushes the remaining data from the encoders, writes the final container metadata, and triggers the stop event. The collected Blob segments can then be combined into a complete WebM file:

mediaRecorder.onstop = () => {
  const completeBlob = new Blob(recordedChunks, { type: 'video/webm' });
  const videoURL = URL.createObjectURL(completeBlob);
  // The videoURL can now be used for playback or downloading
};
