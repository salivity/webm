Residual Quantization and Entropy Coding in WebM

This article explains how video frames in the WebM container—primarily utilizing codecs such as VP8 and VP9—process prediction error residuals. It details the complete pipeline from transforming spatial residual differences into frequency coefficients, scaling and rounding those values through quantization, and finally packing them into the bitstream using context-adaptive arithmetic entropy coding.

1. Residual Generation and Forward Transformation

When a WebM video frame is compressed, the encoder first predicts pixel blocks using spatial prediction (intra-frame) or temporal motion vectors (inter-frame). Subtracting this prediction from the actual source block produces the prediction error residual.

To prepare the residual for efficient compression, the encoder applies a forward discrete transform to convert the spatial residual values into frequency domain coefficients:

  • VP8: Uses a 4x4 Discrete Cosine Transform (DCT) for standard residual blocks and an additional Walsh-Hadamard Transform (WHT) on DC coefficients for intra-16x16 luminance and chrominance blocks.
  • VP9: Expands transform sizes up to 32x32 and introduces the Asymmetric Discrete Sine Transform (ADST) alongside the standard DCT to better represent boundary-adjacent intra prediction errors.

This transformation concentrates the majority of the residual energy into a few low-frequency coefficients (top-left of the block), leaving high-frequency components near zero.

2. Quantization of Transform Coefficients

Quantization is the lossy stage of the process, reducing the precision of the transform coefficients to discard imperceptible visual data and maximize compression.

  • Quantization Index (base_qindex): The frame header specifies a base quantization index ranging from 0 to 255.
  • De-quantization Factors: The codec converts this index into separate scaling factors for DC and AC coefficients across luminance and chrominance planes using lookup tables and delta offsets.
  • Division and Rounding: The forward transform coefficients are divided by these quantization step sizes and rounded to the nearest integer. Smaller coefficients (typically high-frequency noise and fine details) are rounded to zero, creating long runs of zero values that can be efficiently compressed.

3. Coefficient Scanning and Tokenization

After quantization, the 2D matrix of integer coefficients is converted into a 1D array using a predefined scan order:

  • Scan Patterns: VP8 uses a traditional zig-zag scan pattern, while VP9 selects between zig-zag, horizontal, and vertical scans depending on the intra-prediction mode. This ensures non-zero coefficients appear early in the array, followed by contiguous trailing zeros.
  • Tokenization: Coefficients are grouped into tokens representing categories such as zero values, small integer values (1 to 4), value ranges, sign bits, and End-of-Block (EOB) markers that signal all subsequent coefficients in the block are zero.

4. Entropy Coding

The tokenized coefficients are compressed losslessly using arithmetic entropy coding before being multiplexed into WebM SimpleBlock or Block structures.

  • VP8 (Boolean Arithmetic Coder): Uses a binary arithmetic coder. Each token is encoded using specific tree structures, where branch probabilities are determined by the block type, coefficient position (band), and whether the preceding neighbor blocks contained non-zero coefficients.
  • VP9 (Context-Adaptive Binary/Multi-Symbol Arithmetic Coder): Utilizes multi-dimensional probability contexts based on transform size, color plane, coefficient position, and neighbor block activity. VP9 dynamically tracks symbol counts and updates frame context probabilities, allowing the arithmetic coder to assign shorter bit representations to the most statistically probable residual values.

The resulting binary output represents the compressed residual signal, packaged directly into the frame payload inside the WebM container.
