Configure Web Servers for WebM MIME Types

Serving WebM video and audio files correctly requires your web server to send the proper Multipurpose Internet Mail Extensions (MIME) types in HTTP response headers. If these headers are missing or misconfigured, web browsers may fail to play media inline, encounter seeking errors, or force the user to download the file instead. This guide covers the correct MIME definitions for the WebM format and provides straightforward configuration steps for Apache, Nginx, Microsoft IIS, and Caddy to ensure automated, accurate delivery.

Standard WebM MIME Types

When serving WebM content, use the following standardized MIME types:

  • Video (.webm with video stream): video/webm
  • Audio (.weba or audio-only .webm): audio/webm

Apache HTTP Server

Apache maps extensions to MIME types using either the main server configuration files (httpd.conf / apache2.conf) or directory-level .htaccess files.

Using .htaccess or httpd.conf

Add the AddType directives inside your .htaccess file or within the <VirtualHost> / <Directory> block of your main configuration:

AddType video/webm .webm
AddType audio/webm .weba

Using mime.types

If Apache loads an external mime.types file (typically via mod_mime), you can append the mappings directly:

video/webm    webm
audio/webm    weba

Reload Apache to apply changes:

sudo systemctl reload apache2   # Debian/Ubuntu
sudo systemctl reload httpd     # RHEL/CentOS

Nginx

Nginx determines MIME types through the mime.types file included within the http block of nginx.conf.

Updating mime.types

Open /etc/nginx/mime.types and ensure the following lines exist inside the types { ... } block:

types {
    video/webm                            webm;
    audio/webm                            weba;
}

Adding Directly to Server Blocks

If you cannot edit the global mime.types file, add the mapping inside your specific server or location block in nginx.conf:

location ~* \.webm$ {
    add_header Content-Type video/webm;
}

location ~* \.weba$ {
    add_header Content-Type audio/webm;
}

Test the configuration and reload Nginx:

sudo nginx -t
sudo systemctl reload nginx

Microsoft IIS

In Microsoft Internet Information Services (IIS), you can configure MIME types using the graphical IIS Manager or by modifying the web.config file in your application's root directory.

Using web.config

Add the static content mappings inside the <system.webServer> section:

<configuration>
   <system.webServer>
      <staticContent>
         <remove fileExtension=".webm" />
         <mimeMap fileExtension=".webm" mimeType="video/webm" />
         <remove fileExtension=".weba" />
         <mimeMap fileExtension=".weba" mimeType="audio/webm" />
      </staticContent>
   </system.webServer>
</configuration>

(Note: The <remove> tags prevent duplicate mapping errors if the MIME type is already defined at the global server level.)

Caddy

Modern versions of Caddy detect standard WebM MIME types automatically. To explicitly override or guarantee the header, use the header directive in your Caddyfile:

example.com {
    root * /var/www/html
    file_server

    @webm path *.webm
    header @webm Content-Type video/webm

    @weba path *.weba
    header @weba Content-Type audio/webm
}

Reload Caddy to apply changes:

caddy reload

Verifying the Configuration

To verify that your server outputs the correct Content-Type header, run a curl request against a hosted WebM file:

curl -I https://example.com/media/sample.webm

Inspect the output to confirm the header is present:

HTTP/2 200
content-type: video/webm
