How to Mux VP9 Video and Opus Audio to WebM

Muxing standalone VP9 video streams and Vorbis or Opus audio streams into a single WebM container allows you to create high-efficiency, royalty-free media files compatible with modern web browsers and media players. This process involves packaging the distinct video and audio streams together without re-encoding, preserving original quality while taking only seconds to complete. The most reliable tools for this task are FFmpeg and MKVToolNix.

Muxing with FFmpeg

FFmpeg is the industry standard for command-line media manipulation. To combine your VP9 video file with an Opus or Vorbis audio track without re-encoding, use the stream copy (-c copy) command.

For Opus Audio:

ffmpeg -i video_input.vp9 -i audio_input.opus -c copy output.webm

For Vorbis Audio:

ffmpeg -i video_input.vp9 -i audio_input.ogg -c copy output.webm

Command Breakdown:

  • -i video_input.vp9: Specifies the source video file (can also be an .ivf, .mkv, or raw stream).
  • -i audio_input.opus: Specifies the source audio file.
  • -c copy: Tells FFmpeg to copy both audio and video streams directly without decoding or re-encoding.
  • output.webm: The target WebM file.

If your input files have multiple tracks or metadata conflicts, explicitly map the desired streams:

ffmpeg -i video_input.vp9 -i audio_input.opus -map 0:v:0 -map 1:a:0 -c copy output.webm

Muxing with MKVToolNix (mkvmerge)

Since WebM is a subset of the Matroska (MKV) container format, mkvmerge can natively assemble WebM files when given the appropriate output extension.

mkvmerge -o output.webm video_input.vp9 audio_input.opus

For Vorbis streams:

mkvmerge -o output.webm video_input.vp9 audio_input.ogg

Important Considerations

  1. Strict Codec Compliance: The WebM specification only officially supports VP8, VP9, and AV1 for video, and Vorbis and Opus for audio. Attempting to mux other codecs (like H.264 or AAC) into a .webm file will result in an invalid or non-standard container.
  2. Audio-Video Synchronization: Ensure that your standalone streams share identical start timestamps. If the audio is delayed relative to the video, you can apply an offset in FFmpeg using the -itsoffset flag before the second input: 
    ffmpeg -i video_input.vp9 -itsoffset 0.5 -i audio_input.opus -c copy output.webm
