Required EBML Header Elements in WebM Files

WebM is an open-media container format based on Matroska, which relies on the Extensible Binary Meta Language (EBML) to structure binary data. Every valid WebM document must begin with an EBML Header that declares the specifications, versions, and document types needed for parsers to decode the file correctly. Below is the breakdown of all mandatory EBML header elements required in every valid WebM file.

1. EBML (Master Element)

  • Element ID: 0x1A45DFA3
  • Requirement: Mandatory
  • Description: The top-level master element that wraps the entire header. Every valid WebM file begins with this byte sequence.

2. EBMLVersion

  • Element ID: 0x4286
  • Requirement: Mandatory
  • Default/Expected Value: 1
  • Description: Specifies the version of the EBML parser used to create the document. For WebM, this is always set to 1.

3. EBMLReadVersion

  • Element ID: 0x42F7
  • Requirement: Mandatory
  • Default/Expected Value: 1
  • Description: Defines the minimum EBML parser version an application must support to read the file. For WebM, this is set to 1.

4. EBMLMaxIDLength

  • Element ID: 0x42F2
  • Requirement: Mandatory
  • Default/Expected Value: 4
  • Description: Indicates the maximum length in bytes of the Element IDs used within the file. For WebM and Matroska specifications, this is fixed to 4.

5. EBMLMaxSizeLength

  • Element ID: 0x42F3
  • Requirement: Mandatory
  • Default/Expected Value: 8
  • Description: Indicates the maximum length in bytes of the Element Data Size indicators within the file. For WebM, this is fixed to 8.

6. DocType

  • Element ID: 0x4282
  • Requirement: Mandatory
  • Expected Value: "webm" (ASCII string)
  • Description: Identifies the specific data format wrapped inside the EBML container. To be recognized as a valid WebM file rather than a standard Matroska (MKV) file, the string value must be exactly "webm".

7. DocTypeVersion

  • Element ID: 0x4287
  • Requirement: Mandatory
  • Expected Value: 2 or 4
  • Description: Specifies the version of the DocType specification used to author the file. Most standard WebM files use version 2 or version 4.

8. DocTypeReadVersion

  • Element ID: 0x4285
  • Requirement: Mandatory
  • Expected Value: 2
  • Description: Defines the minimum DocType parser version required to interpret the file. WebM players supporting WebM version 2 or higher can successfully parse documents that require this read version.
