WebM EBML Master Element Binary Sequence

This article examines the structural identification of Extensible Binary Meta Language (EBML) master elements within WebM files. It provides the exact binary and hexadecimal signatures used to recognize the root EBML header, details how EBML Variable-Length Integers (VINTs) define element boundaries, and lists the primary 4-byte identifiers for core WebM master elements.

The EBML Root Master Element Identifier

The primary EBML master element that begins every compliant WebM file is the EBML Header. It is identified by a unique 4-byte (32-bit) sequence:

  • Hexadecimal: 0x1A 0x45 0xDF 0xA3
  • Binary: 00011010 01000101 11011111 10100011

When parsed at the byte level:

  1. 0x1A = 00011010
  2. 0x45 = 01000101
  3. 0xDF = 11011111
  4. 0xA3 = 10100011

This 32-bit sequence acts as the file signature (or "magic bytes") for EBML-based media, indicating the start of the container's metadata declaration.

How EBML Identifies Element Lengths (VINT Structure)

EBML elements—including master elements—do not use fixed-length tags. Instead, they begin with a Variable-Length Integer (VINT) representing the Element ID, immediately followed by another VINT indicating the size of the element's payload.

The length of an Element ID is encoded in its initial bits:

  • 1-octet ID: Starts with 1 (1xxxxxxx)
  • 2-octet ID: Starts with 01 (01xxxxxx xxxxxxxx)
  • 3-octet ID: Starts with 001 (001xxxxx xxxxxxxx xxxxxxxx)
  • 4-octet ID: Starts with 0001 (0001xxxx xxxxxxxx xxxxxxxx xxxxxxxx)

Because the EBML Header starts with 00011010, the leading 0001 signals to a parser that the identifier is 4 octets long.

Other Common WebM Master Element Signatures

A master element in EBML contains other nested elements rather than raw data. In addition to the root EBML header, WebM files contain other major 4-byte master elements that structure the media:

  • Segment: 0x18 0x53 0x80 0x67 (00011000 01010011 10000000 01100111) — Encompasses all other data in the file.
  • Info (Segment Information): 0x15 0x49 0xA9 0x66 (00010101 01001001 10101001 01100110) — Stores timestamps and container metadata.
  • Tracks: 0x16 0x54 0xAE 0x6B (00010110 01010100 10101110 01101011) — Declares video, audio, and subtitle streams.
  • Cluster: 0x1F 0x43 0xB6 0x75 (00011111 01000011 10110110 01110101) — Holds the basic audio/video block groups.

Each of these identifiers begins with the 0001 binary pattern, defining them as 4-byte master element IDs under the EBML specification.
