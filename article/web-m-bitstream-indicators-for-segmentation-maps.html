WebM Bitstream Indicators for Segmentation Maps

WebM video containers rely primarily on the VP8 and VP9 video codecs, both of which define explicit bitstream flags in their uncompressed frame headers to control spatial segmentation. Spatial segmentation divides a frame into distinct regions to apply customized quantization, loop filtering, or reference frame settings. This article outlines the specific bitstream syntax elements across VP8 and VP9 that signal whether an encoded WebM frame activates segmentation and contains updated spatial segmentation maps.

VP8 Segmentation Indicators

In VP8 bitstreams, segmentation controls are located in the uncompressed frame header. A decoder evaluates two primary hierarchical flags to determine the presence and structure of spatial segmentation:

  • segmentation_enabled (1 bit): Located within the frame header, this flag serves as the master switch. A value of 0 indicates that spatial segmentation is entirely disabled for the frame, and standard global parameters apply. A value of 1 indicates that the frame uses segmentation.
  • update_mb_segmentation_map (1 bit): When segmentation_enabled is set to 1, the decoder immediately parses this bit.
    • If set to 1, the bitstream carries a newly updated macroblock-to-segment map. The decoder then parses the segment_prob tree probability array, and subsequent macroblock headers will contain segment identification tokens.
    • If set to 0, the frame maintains the macroblock segmentation map inherited from the previous reference frame, and no new spatial map tokens are transmitted within the block payload.

VP9 Segmentation Indicators

VP9 expands segmentation functionality up to eight distinct segments per frame and introduces temporal prediction for segmentation maps. The uncompressed frame header reads the following indicators:

  • segmentation_enabled (1 bit): The primary indicator that segmentation mode is active for the current frame.
  • segmentation_update_map (1 bit): If segmentation is active, this syntax element indicates whether the frame defines a new spatial segmentation map.
    • A value of 0 signals that the decoder must retain the existing segmentation map from the designated reference frame without decoding new block-level segment IDs.
    • A value of 1 signals that the current frame contains updated block-level segment data.
  • segmentation_temporal_update (1 bit): When segmentation_update_map is true and the current frame is an inter-frame, this flag determines how the map is transmitted.
    • A value of 1 indicates that the block-level segment IDs are coded relative to the previous frame’s map using temporal prediction flags (segment_id_predicted).
    • A value of 0 indicates that segment IDs are coded unconditionally using tree probabilities (segmentation_tree_probs).

Block-Level Parsing Behavior

When header indicators signal an active map update (update_mb_segmentation_map in VP8 or segmentation_update_map in VP9), the decoder expects explicit segment ID syntax tokens within each macroblock (VP8) or block/super-block (VP9) partition. If the update indicators are cleared, these block-level syntax elements are entirely absent from the compressed stream, and the decoder copies segment affiliations directly from the frame's reference context.
